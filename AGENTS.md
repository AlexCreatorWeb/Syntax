# Syntax — контекст для AI-разработчика

Фронтенд обучающей платформы «Syntax» (учим программирование в браузере).
Работа ведётся в этом репо; бэкенд пока не существует — все данные статические (в конфигах/i18n).

## Запуск
- `npm run dev` → http://localhost:5173 (лог: `/tmp/vite-dev.log`). Vite обязан работать с `server.watch.usePolling: true` — НЕ убирать (AI меняет иноды файлов, watcher виснет без поллинга).
- `npm run build`, `npm run lint` — обязаны быть зелёными после каждого изменения.
- Версии: Vite 7.3.6, React 19.2.8, @vitejs/plugin-react 5.2.0, @monaco-editor/react 4.7.0, emmet-monaco-es, flag-icons.

## Архитектура

- `src/components/MainContent.jsx` — свитч вкладок: `home → MainView`, `roadmap → RoadmapView`, `tasks → TasksView`, `rankings → RankingsView`, `documentation → DocsView`, `community → CommunityView`, `editor → CodeEditor`, остальное → заглушка lesson-карты.

Вьюха НЕ содержит свой правый rail — она одноколоночная, aside монтируется во внешний rail. Две колонки справа — баг.
- **Хедер универсальный** (`Header.jsx`): логотип (→ home), флаг-язык, тема, уведомления, **гостевой блок auth** (Log in ghost + Sign up free primary, класс `.auth`; на ≤1100px только пилюля, ≤480 скрыт колокольчик `.tb-menu-wrap--notif`), аватар. Таб-специфичный контент (заголовки, поиска, сегмент-контролы) живёт ВНУТРИ вьюх. `.topbar` — `sticky; z-index: 50`; НИКАКИХ поздних правил, перебивающих его position/z-index (был баг: `.topbar, .shell { position: relative; z-index: 1 }` — топбар ехал под липкие карточки сайдбара).
- **SignupModal** (`src/components/SignupModal.jsx`, state в App: `openSignup`/`closeSignup`): одна модалка на ВСЕ гостевые действия (Start for free, Continue Learning, Start Challenge, финальный CTA, кнопки хедера). - `CodeEditor.jsx` — Monaco (загружается с CDN **0.55.1** через @monaco-editor/loader — не путать с node_modules). Emmet НЕ в ядре Monaco 0.5x: подключается плагином `emmet-monaco-es` в `beforeMount` (`emmetHTML(emmetCSS(emmetJSX))`, гвард `monaco.__syntaxEmmet`). Рабочее пространство файлов: старт-файл с кодом, новые файлы пустые, дубликаты имени → `(2)`, `(3)`, табы перетаскиваются и закрываются. Run: JS-only файлы — скрытый раннер-iframe, HTML — перезапуск превью; не-JS (py/sql/css) — честная подсказка «runner coming soon» в консоли (Run не молчит). `console.log/warn/error` и ошибки перехватываются скриптом `CONSOLE_CAPTURE` в iframe; **номера строк ошибок — в координатах файла**: перед каждым JS-блоком отдельный тег `window.__syntaxOffset = N` (обязателен отдельным `<script>`: при SyntaxError сам блок не исполняется); клик по ошибке → revealLineInCenter. Консоль всегда в кадре (подсказка до первого Run, авто-скролл + вспышка после). Submit = run + вердикт.

- **Supabase (первые данные из БД)**: `src/lib/supabase.js` — клиент + `fetchDbLessons()` (таблица `lessons`: id/title/content/**code**/tech; таймаут 4с, кэш на сессию; сбой/пусто → null/[] → fallback на i18n). TechnologyView: секция «Lessons» (`techPage.dbLessons/dbLessonOpen`, 5 языков) — уроки трека из БД, нумерация с 1, клик по строке (`.techmod--db`) → вкладка **`#/lesson` → LessonView**: шапка (chip тех · Lesson, From database, Back→свой трек) + 2 колонки: **материал** (markdown-lite) | **редактор** (тот же CodeEditor, свой job-заголовок скрыт CSS `.lesson-view .editor-job{display:none}`); мобилка — в столбец. **Контракт контента урока (для агента-наполнителя)**: `lessons { title, tech, content, code }`, где `content` = markdown-lite: `##`/`###`, `**жирный**`, `*курсив*`, `` `код` ``, ```lang-блоки (Copy-кнопка), `TIP:`/`NOTE:`/`WARN:` → callout'ы; `code` = стартовый код задания в Monaco. Парсер: `src/lib/markdown.js` (чистый, без JSX: parseMdBlocks/inlineMdTokens) + рендер `src/lib/markdown-view.jsx` (MdContent; разделение — react-refresh правило «только компоненты»). i18n: `lessonView.{material,task,noMaterial}` ×5. Статичные i18n-уроки (без строк в БД) — как раньше, в редакторе. Ключи: `.env` в репо (`VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`; publishable — безопасно коммитить, Vercel-сборка работает без env-панели). База `xaslezkoktydranikqnx.supabase.co`, таблицы profiles/lessons/courses/modules (кроме lessons — пусты). **RLS-лента**: anon нужны политики SELECT/INSERT/DELETE `USING/WITH CHECK (true)` + GRANT; **UPDATE-политики НЕТ** (403) — правка строки = DELETE + INSERT (или создать политику). Ловушки: строка в БД + SELECT-политика не `USING (true)` → API молча `[]` (лечится новой политикой — пермиссивные суммируются по OR); DELETE через API без DELETE-политики → молча 204, строка не удаляется.

- **Курс HTML в БД (16 уроков)**: исходники — `course/html/` (`00-roadmap.md` с контрактом + `01..16-*.md` + `code/01..16.html`). Порядок: структура → кодировки → текст → ссылки → навигация/вкладки → изображения → списки → таблицы → формы×2 → семантика → медиа → a11y → мета/SEO → современные элементы (dialog/details/time) → финальный проект. **Контракт урока** (фиксирован, QC в сидере): 5 разделов (Цель/Теория/Пример/Частые ошибки/Практическое задание), минимум 1 `TIP:` и 1 `WARN:` (ошибки = WARN-пункты), без таблиц/`[ссылок](url)`, объём content 4000–7000 зн. **`code` = скелет ЗАДАНИЯ с `<!-- TODO -->` (не решение!)** — лежит в `code/NN.html`. Сидер `seed-html-course.mjs` (корень репо): `node seed-html-course.mjs` — IDEMPOTENT (удаляет ВСЕ tech='html' и вставляет 16, id `10000000-…00NN`), встроенный QC (5 разделов, callout'ы, ссылки, объём, html-блок) — падает до БД при нарушении; `DRY=1 node …` — только проверка без записи. Ловушка: в markdown-lite нет списков/таблиц (буллеты → «• » строки через пустые строки), callout-строка — plain text (без ** и ` внутри).
## Конвенции
- Дизайн-система «Protocol Neo»: токены тем в `src/css/style.css` (`:root` тёмная, `[data-theme="light"]`). Скроллбары: тонкие, тёмная тема — акцентный зелёный, светлая — нейтральный (токены `--scroll-thumb*`).
- i18n: **5 языков** EN/RU/UK/ES/DE. `src/i18n/index.js` (EN + RU), `locales-extra.js` (UK/ES/DE). `useT()` — dot-lookup, `{param}`-интерполяция, fallback на EN. Список-данные (посты, модули, задачи, гиды, уведомления) — переводятся как массивы в словарях; state в компонентах держит **индексы**, не строки. Новый ключ обязан попасть во ВСЕ 5 словарей.
- Выбор языка: `localStorage["syntax-ui-lang"]`, тема: `localStorage["syntax-theme"]`, синхронизируется `<html lang>`.
- Аватары: монограммы-кружки с HSL-градиентом (`src/components/Avatar.jsx`), фото придут с бэкендом.
- i18n-аудит ключей (обязателен после добавления t("...")): `npx esbuild src/i18n/index.js --bundle --format=cjs --outfile=/tmp/locales.cjs` + node-скрипт: собрать все `t("key")` из jsx, сверить с LOCALES по всем 5 языкам (шаблон скрипта — в хронике/прошлых сессиях; node ESM напрямую не импортирует i18n — там extension-less import, только через esbuild).

**React-Compiler лент** (learned the hard way, не повторять): 1) компоненты НЕ объявлять внутри компонента (Node/ModuleIcon/ReplyItem/ThreadModal/ComposerModal — в топ-уровень; `const X = () => {}` в теле = «Cannot create components during render»); 2) `getTech()` в рендере + `.Logo` — «component created during render» → static-мапы на уровне модуля (`TRACK_LOGOS = Object.fromEntries(TECHS.map(...))`); 3) мутация `let`-флагов в map во время рендера — «Cannot reassign» → предвычислять индексы; 4) setState в useEffect для синка с пропом — «cascading renders» → remount через `key={prop}` в родителе (TasksView key=activeTech); 5) присваивание ref.current в рендере — в useEffect.
Осторожно с i18n: скрипты batch-вставки с вложенными циклами ломали файлы (дубли ключей; однажды ES/DE-блоки склеились в UK-объект) — после любых python-правок: `npm run lint` + esbuild-аудит полноты (`node /tmp/audit.js` — шаблон, собирает t("...") из src и сверяет с LOCALES; roadmap.module — известный false positive на комментарий в useT.js).
