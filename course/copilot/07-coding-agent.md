# Coding Agent: задачи, issues, PR

## Цель

После урока студент сможет: объяснить, что такое GitHub Coding Agent (облачный агент, работающий на стороне GitHub), запустить его на issue своего репозитория, прочитать отчёт агента и pull request, который он прислал, и отличить задачу, подходящую агенту, от задачи, которую лучше делать руками.

## Теория

Coding Agent — фича, ради которой Copilot перестал быть «подсказкой в редакторе»: ты пишешь issue на GitHub (или назначаешь @copilot в комментарии к issue), и GitHub запускает агента в облачной песочнице (копия твоего репозитория в Codespaces). Агент читает issue, сам планирует, правит файлы, запускает тесты (если есть CI или команды из инструкций), и присылает pull request. Ты не при компьютере — работа идёт в облаке, и результат (PR с диффом и отчётом) появляется, когда агент закончит: минуты для простой задачи, десятки минут для сложной.

Почему это работает именно в связке с GitHub: агенту нужен (1) репозиторий — у тебя есть, (2) среда исполнения — GitHub даёт Codespaces, (3) место, куда положить результат — pull request. Никакой локальный инструмент не закроет все три пункта так же бесшовно.

Ключевое условие успеха — самоодерживающаяся задача. Агент видит только то, что в репозитории: issue, код, инструкции, CI. Если в issue написано «сделай как обсуждали в мессенджере» — агент угадывать не будет (и правильно). Хорошие issue для агента:

- есть чёткий ожидаемый результат («команда done 99 должна печатать ошибку и не падать»);
- есть способ проверить (тест, команда, ожидаемый вывод);
- не требует решений по архитектуре (это уже agent mode или ты сам).

Механика запуска: в issue ставишь label «copilot» (в новых версиях — или просто упоминаешь @copilot в комментарии); GitHub снимает issue «в работу», ты видишь тред: план агента, коммиты, запуск тестов. По окончании — PR. Дальше обычный цикл: читаешь диф (урок 13 научит это делать с Copilot-ревью), mergest или пишешь коммент с правкой — агент поправит по комменту.

TIP: перед первым запуском агента проверь два файла: copilot-instructions.md (он его прочитает — в нём должны быть команды тестов) и workflow CI (урок 14). Агент без тестов «сдаёт» то, что не падает, а не то, что работает.

NOTE: облачный агент считает premium-запросы и «agent minutes» — лимиты бесплатного тарифа на агента меньше, чем на чат. Первые два запуска сделай на простых задачах, чтобы привыкнуть к циклу, а не «сжечь» месячную квоту на эксперименте.

## Пример

```bash
# 1. Создай issue в GitHub (через gh CLI):
gh issue create --title "done: неизвестный id падает с traceback" \
  --body "Команда: python taskit.py done 99
Ожидаемо: сообщение «Нет задачи с id 99», код возврата 1.
Сейчас: traceback ValueError.
Проверка: python taskit.py done 99; echo \$?"

# 2. Назначь агенту (в веб-интерфейсе issue):
#    @copilot — или label «copilot».
#    Тред покажет: plan → work → tests → PR.

# 3. Когда PR появится — проверь его:
gh pr list
gh pr diff <номер>
gh pr merge <номер> --squash   # только после чтения диффа и тестов
```

Цикл «issue → @copilot → PR → diff → merge» — это и есть ежедневная работа с облачным агентом. Обрати внимание на тред: агент сам пишет, что понял из issue, какие файлы тронет, какие тесты прогонит. Этот «отчёт» — твоя точка контроля: если план кривой, останови до того, как он допишет код.

## Частые ошибки

WARN: кидать агенту «размытое» issue («улучши обработку ошибок»): без ожидаемого результата агент сделает что-то правдоподобное и закроет issue. Правило: в issue должны быть вход, выход и команда проверки — тогда и у агента, и у тебя (при ревью) есть критерий.

WARN: мержить PR агента без чтения диффа: агент правит файлы, и добавляет imports, и «улучшает» соседние функции. Diff агента — как чужой PR: читаем, прогоняем тесты, и только потом merge. (В уроке 13 — как читать такие PR с помощью Copilot-ревью.)

WARN: ожидать, что агент знает контекст из чата: облачный агент видит только репозиторий (issue, код, инструкции, CI). Всё, что «мы обсудили в чате», нужно перелить в issue или в copilot-instructions.md.

WARN: гнать агента по архитектуре: «переделай хранение на SQLite» — это 20 файлов и решений. Для таких задач — agent mode в редакторе (урок 8) или ты сам; облачный агент — для самоодерживающихся issue.

## Практическое задание

Проведи полный цикл: создай issue в taskit (например, «list: отметка выполненных задач [x]»), назначь @copilot, дождись PR, прочитай дифф и отчёт, прогони тесты локально, смержь. Затем заполни в copilot-instructions.md раздел «Issues и PR»: формат issue (вход/ожидание/проверка), правило «PR от агента — только после чтения диффа», шаблон описания PR. Эти правила агент будет читать при каждой задаче.
