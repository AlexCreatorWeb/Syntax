# GitHub Copilot CLI: GitHub в терминале

## Цель

После урока студент сможет: установить и войти в Copilot CLI, объяснить, чем он отличается от чата в редакторе (автонормный, скриптуемый, работает в CI), выполнить три базовых сценария (агент в терминале, конвертация markdown, запуск в скрипте) и собрать свой первый «агентский» скрипт для taskit.

## Теория

Copilot CLI — программа в терминале, которая даёт те же возможности Copilot (чат, агент, skills) без редактора. Зачем, если чат есть в VS Code? Три причины.

Первая — автонормность: CLI можно вызывать из bash/скриптов и CI. «Сгенерируй changelog из commit'ов», «проверь PR и оставь коммент» — это строки в скрипте, а не тапки по клавишам чата. Вторая — скорость: в терминале нет панелей и вкладок, и для коротких задач (переписать текст, объяснить diff, сгенерировать commit message) CLI быстрее чата. Третья — CI: в Actions (урок 14) CLI — тот же инструмент, что и в твоем терминале, только на машине GitHub.

Базовая механика (команды уточняй по своей версии — CLI молодой, набор растёт):

- copilot — интерактивный чат в терминале (то же ядро, что в редакторе, с skills и инструкциями).
- copilot agent «задача» — запустить агента в терминале: читает репозиторий, правит файлы, показывает диф (аналог Agent mode, но без редактора).
- copilot markdown file.md — конвертация markdown в текст (пример фичи «одной командой»).
- gh copilot — часть gh CLI: управление агентами и issue-задачами (запуск coding agent из терминала).

Ключевое отличие от чата в редакторе: в CLI нет @workspace-индекса «из коробки» в том же виде — агент сам читает файлы (grep/cat), и для больших репозиториев это медленнее, зато предсказуемо: ты видишь, какие команды агент выполняет, и можешь ограничить их списком (allowlist).

Skills в CLI — то же, что и в редакторе (урок 14): папки с инструкциями, которые агент подхватывает по триггеру. В терминале они особенно удобны: «skill: changelog» — и агент знает, в каком формате писать changelog у тебя в проекте, без повторения в каждой задаче.

TIP: в терминале агент особенно хорош для «мелочи репозитория»: сгенерировать commit message, обновить README по диффу, написать issue-шаблон. Такие задачи в редакторном чате «некогда» открывать, а в CLI это одна строка.

NOTE: CLI и «агенты» в нём развиваются быстрее всего: имена команд (copilot agent, copilot skill) и флаги меняются от версии к версии. Перед сценарием проверяй copilot --help — он честнее любых гайдов, включая этот.

## Пример

```bash
# 1. Установка и вход (Windows: winget/scoop; macOS: brew):
#    curl -fsSL https://raw.githubusercontent.com/github/copilot-cli/main/install.sh | sh
copilot --version
gh auth login   # вход тем же GitHub-аккаунтом, что и редактор

# 2. Чат одной строкой:
copilot "объясни diff последнего коммита в 3 предложениях"

# 3. Агент в терминале (в папке taskit):
copilot agent "добавь в README секцию «Команды» с примерами add/list/done"
# агент прочитает README и taskit.py, предложит диф — прими (y).

# 4. Скрипт (свой первый «агентский» скрипт):
copilot markdown CHANGELOG.md > changelog.txt
```

Сценарий 3 — тот же Agent mode, что в уроке 8, только в терминале. Сценарий 4 — то, ради чего CLI и существует: markdown-конвертация одной строкой, без открытия редактора.

## Частые ошибки

WARN: давать CLI-агенту задачу «на весь репозиторий» и не читать, какие команды он выполняет: в терминале у агента есть bash, и он может запустить что угодно. Смотри команды в реальном времени (агент их печатает) и держи allowlist в настройках.

WARN: использовать CLI для задач, где нужен визуальный диф (большие правки): терминальный диф — хуже редакторного. Крупное — в редакторе (Agent mode) или в облаке (coding agent → PR).

WARN: путать gh copilot и copilot CLI: это разные инструменты — gh copilot управляет облачными агентами и issue, copilot — локальный терминальный чат/агент. У них общие аккаунт и лимиты, но разные сценарии.

WARN: скриптовать CLI без идиотентности: copilot markdown file — ок, а copilot agent «переделай всё» в cron-скрипте — лотерея. Скрипты — для детерминированных задач с чётким входом и выходом.

## Практическое задание

Установи CLI, пройди три сценария из «Примера» и сделай для taskit «агентский скрипт» scripts/ai-changelog.sh: из последних 5 коммитов (git log) через copilot сгенерирует блок changelog и допишет его в CHANGELOG.md. Затем заполни в copilot-instructions.md раздел «Терминал»: как в проекте запускают CLI-агента, какие команды разрешены (allowlist: python, pytest, ruff, git), какие — запрещены (rm -rf, force push).
