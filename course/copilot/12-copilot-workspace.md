# Copilot Workspace: от issue до кода

## Цель

После урока студент сможет: объяснить, что такое Copilot Workspace (режим «issue → план → код → дифф» в редакторе), запустить его на issue taskit, разобрать его план на шаги и отредактировать до того, как агент начнёт, и отличить Workspace от Agent mode и от Coding Agent (когда что).

## Теория

Copilot Workspace — режим в VS Code, который превращает issue в «рабочее пространство»: ты открываешь issue (из GitHub, или вводишь текст), Workspace показывает план работы (шаги, файлы, шаги проверки), ты правь план, жмёшь «go», и агент исполняет — шаг за шагом, с дифами, как в Agent mode, только вход — структурированная задача, а не чат-сообщение.

Позиция в триаде (уроки 7–8):

- Agent mode (урок 8): синхронный чат-агент, задача — текстом, в редакторе.
- Coding Agent (урок 7): асинхронный облачный агент, задача — issue, результат — PR.
- Workspace: «середина»: задача — issue (или текст), работа — локально в редакторе, с планом, который ты видишь и редактируешь ДО старта.

Почему «план до старта» — главная фича: в Agent mode ты видишь план, но он «в потоке» (чат). В Workspace план — отдельный артефакт: список шагов, для каждого — файлы и проверка. Ты можешь «выкинуть» шаг, добавить свой, поменять порядок — до того, как агент тронет код. Это самый «управляемый» из трёх режимов, и для задач «среднего размера» (не одна функция, не весь проект) — лучший выбор.

Механика (в актуальных сборках VS Code): иконка Workspace в панели GitHub/Copilot → выбрать issue (или «new workspace» с текстом) → план → правка плана → «Start» → исполнение по шагам, дифы, проверка (тесты, если в плане).

Когда Workspace, а когда не он: одна функция / пара файлов — Agent mode или чат с Apply (Workspace «раздунит» для этого); issue на «отойти и вернуться» — Coding Agent (облако); «issue → код, и я хочу видеть каждый шаг» — Workspace.

TIP: пиши issue так, чтобы из него получился план: «что сделать» (2–3 предложения), «как проверить» (команда), «что не трогать» (границы). Такой issue Workspace превращает в план почти без правок.

NOTE: Workspace — развивающаяся фича: в разных сборках она называется по-разному (Copilot Workspace, «workspace from issue»), и часть поведения (авто-прогон тестов, параллельные шаги) меняется. Если у тебя «не та» версия — сверяй с актуальным списком фич GitHub (страница Copilot в доках).

## Пример

```bash
# 1. Создай issue (через gh):
gh issue create --title "list: сортировка по дате создания (новые выше)" \
  --body "Что: команда list печатает задачи в порядке добавления
   (новые снизу).
   Нужно: новые сверху (последние добавленные — первыми).
   Проверка: python -m pytest; python taskit.py list
   Не трогать: формат tasks.json, другие команды."

# 2. В VS Code: панель Workspace → выбери этот issue.
#    План (пример): 1) изменить sort в list(), 2) добавить тест
#    test_list_sorts_newest_first, 3) прогнать pytest.
#    Правка плана: добавь шаг «проверить, что done() не пострадал».

# 3. Start. Агент исполняет по шагам; на каждом — диф.
#    Финал: тесты зелёные, issue можно закрыть.
```

Цикл «issue → план → правка плана → исполнение» — это и есть Workspace. Обрати внимание: правка плана (шаг 2) — дешевле, чем правка кода после. Один цикл «добавь шаг в план» = пять циклов «стоп, переделай» в Agent mode.

## Частые ошибки

WARN: запускать Workspace на «одной функции»: для правки в одном месте режим «раздунит» (план, шаги, дифы) — и ты потеряешь время. Маленькое — чат/inline, среднее — Workspace, «отойти» — Coding Agent.

WARN: не править план и жать «Start»: план агента — черновик. Добавь «что не трогать» и «проверку» в план, и исполнение будет точнее (агент читает план как задачу).

WARN: путать Workspace с «новым репозиторием/веткой»: Workspace — режим работы, а не копия проекта. Он правит текущие файлы (с дифами), и если что-то пойдёт не так — откат через git (обычный, как всегда).

WARN: ждать, что Workspace «запомнит» issue: план — артефакт сессии. Если закрыл Workspace и открыл заново — план будет пересобран из issue (и из copilot-instructions.md). Всё важное — в issue и в инструкциях.

## Практическое задание

Проведи полный цикл Workspace на issue taskit (например, «list: фильтр --done / --all»): создай issue через gh, открой Workspace, поправь план (добавь шаг проверки и «не трогать»), исполни, проверь дифы и тесты. Затем заполни в copilot-instructions.md раздел «План задач»: формат issue (что/проверка/не трогать), правило «план править до старта», правило «маленькое — не в Workspace». Эти правила обеими руками (Workspace и Coding Agent) будут читать при каждой задаче.
