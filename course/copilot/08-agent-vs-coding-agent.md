# Agent mode vs coding agent: когда что использовать

## Цель

После урока студент сможет: объяснить разницу между Agent mode (агент в редакторе, локально) и Coding Agent (агент в облаке, асинхронно), принять решение «что использую» для конкретной задачи по чётким критериям, запустить Agent mode в VS Code на реальную правку в taskit и прочитать его план до начала работы.

## Теория

Два «агента» в Copilot — это разные инструменты с разным местом работы, и путаница между ними — самая частая ошибка на этом этапе курса. Разложим по слоям.

Где работает: Agent mode — в твоём редакторе, на твоём проекте, на твоих файлах (модель получает доступ править файлы и запускать команды в твоём терминале). Coding Agent — в облаке GitHub, на копии репозитория (Codespaces), ты при нём не нужен и результат приходит pull request'ом.

Как ты участвуешь: Agent mode — синхронный диалог: ты смотришь, как агент работает, можешь в любой момент сказать «стоп, иначе», посмотреть промежуточный диф. Coding Agent — асинхронный пуск: ты задал issue, занялся своим, через 10–40 минут проверяешь PR.

Что видит: Agent mode видит твой редактор целиком — открытые файлы, выделения, историю чата, @workspace. Coding Agent видит только репозиторий: issue, код, copilot-instructions.md, CI.

Исходя из этого — правила выбора (запомни как таблицу):

- Правка в текущем файле/нескольких файлах, ты рядом, нужно подсмотреть и поправить → Agent mode (или просто inline-правка/чат с Apply, если правка маленькая).
- Самоодерживающийся issue с понятным критерием проверки, можно отойти → Coding Agent.
- Архитектурное решение, много контекста «из головы», несколько итераций дизайна → ты сам (агент — помощник, не архитектор).
- Нужно, чтобы задача «записалась» в историю проекта (issue → PR → merge) → Coding Agent: артефакты остаются в GitHub, а не в чате.

Agent mode в VS Code (2025+): в чате переключатель «Agent» (или Ctrl+Shift+L в новых сборках — сверяй свою). Ты пишешь задачу: «добавь команду remove: python taskit.py remove 1; неизвестный id — ошибка». Агент показывает план (какие файлы, какие шаги), ты жмёшь approve, он работает: читает, правит, запускает pytest, показывает итоговый диф. На каждом дифе — кнопки Accept / Edit / Reject: принимаешь по частям, как в уроке 4.

TIP: перед запуском Agent mode проверь, что в copilot-instructions.md есть разделы «Команды» и «Стиль кода»: агент читает их как регламент. Без них он будет гадать, как запускать тесты, и гадать о стиле — и гадать будет хуже, чем ты.

NOTE: Agent mode в 2025–2026 активно развивается: появляются «авто-запуск команд», песочница для команд, работа с несколькими репозиториями. Нумерация клавиш и переключателей меняется от сборки к сборке — если кнопки нет на своём месте, ищи её в меню чата («...»), а не пересобирай настройки из старых гайдов.

## Пример

```bash
# 1. В чате VS Code: переключи режим на Agent (переключатель у чата).
#    Задача:
#    «Добавь команду remove: python taskit.py remove <id> —
#     удаляет задачу, печатает «Удалено: <текст>».
#     Неизвестный id: «Нет задачи с id N», exit code 1.
#     Напиши тесты, прогони pytest.»

# 2. Агент покажет план: файлы (taskit.py, test_taskit.py), шаги.
#    Посмотри план: если шаги кривые — поправь СЕЙЧАС («не трогай list»,
#    «используй ValueError, как в done»).

# 3. Approve. Агент работает: правит, запускает pytest,
#    показывает диффы. Accept по частям.

# 4. Сравни с облачным вариантом (мысленно): эту задачу
#    МОЖНО было оформить issue и отдать Coding Agent —
#    но она была «рядом», и мы хотели посмотреть план.
```

Обрати внимание на момент 2: чтение плана агента до старта — главная экономия. Один цикл «стоп, иначе» на этапе плана дешевле, чем пять итераций на этапе кода.

## Частые ошибки

WARN: давать Agent mode задачу «на весь проект» («сделай нам CLI как todo-list»): локальный агент на таком объёме потеряет нить и начнёт править файлы, которые не надо. Крупное — расчлени на 3–5 задач, сделай по одной (или отдай Coding Agent по issue).

WARN: отдавать Coding Agent задачу, где нужен твой глаз «в процессе» (дизайн API, переименования): облачный агент не принимает «ну почти, но чуть иначе» в реальном времени. Всё уточнение — через комменты к PR, итерациями.

WARN: забывать про контекст: Agent mode видит чат-историю, облачный — нет. Если в чате было «о, давай ещё и так» — перенеси это в задачу (для локального) или в issue (для облачного) явно.

WARN: считать, что агент «сам всё проверит»: и локальный, и облачный агент запускают тесты, если знают команду (из инструкций). Нет тестов — нет проверки. Урок 11 (TDD) — прямое продолжение этого.

## Практическое задание

Сделай команду search (python taskit.py search «кофе» — поиск по тексту задач) через Agent mode: посмотри план поправи его (если нужно), примешь диффы, прогони тесты. Затем заполни в copilot-instructions.md раздел «Границы решений»: что агенту можно делать без спроса (правка логики, тесты, docstring), что — только с подтверждением (новые зависимости, смена структуры файлов, смена формата tasks.json). Эти правила обеими руками (локальный и облачный агент) будут читать при каждой задаче.
