# Практика: Copilot в ежедневном рабочем процессе

## Цель

После урока студент сможет: собрать «день разработчика с Copilot» из конкретных сценариев (утро/день/вечер), объяснить, что реально ускоряет (и что нет), отличить «работает с ИИ» от «работает над ИИ» (когда инструмент управляет тобой), и записать свои личные правила в copilot-instructions.md.

## Теория

После 14 уроков у тебя есть весь набор: комплит, чат, inline, Agent mode, Coding Agent, CLI, MCP, Workspace, ревью, Actions, skills. Урок — собрать их в «день», который ты реально проведёшь, и понять, где ИИ ускоряет, а где — шум.

Утро (15 минут, «собраться»): открыть GitHub, посмотреть: есть ли PR от Coding Agent (задача из вчера), есть ли комментарии (ревью, issue). Запустить pytest локально (базовая линия: «всё зелёное»). В чате: @workspace «что изменилось за вчера?» (по git log). 15 минут — и ты «в контексте» проекта, без «а что я там делал?».

День (основная работа): задача дня (новая команда, баг, рефакторинг). Цикл (из уроков 4, 8, 11): (1) сформулировать (issue или чат), (2) выбрать инструмент (маленькое — чат/inline, среднее — Workspace/Agent mode, «отойти» — Coding Agent), (3) план (посмотреть, поправить), (4) исполнение (агент, дифы), (5) тесты (TDD-цикл), (6) PR (ревью, merge). Повторять для каждой задачи. Ключевое: не «спрашивать ИИ» (реактивно), а «задавать ИИ» (активно, с планом).

Вечер (10 минут, «закрыть день»): commit + push (сообщение — через CLI, урок 9), если есть «недосделанное» — issue на завтра (чтобы агент мог начать), «напиши changelog» (skill, урок 14). 10 минут — и «день закрыт»: код в git, задача на завтра в issue, changelog обновлён.

Что реально ускоряет (честный список): бойлерплейт (функции, тесты, docstring) — 2–5 раз быстрее; навигация по чужому коду (@workspace) — 2–3 раза; «мелочь репозитория» (commit message, changelog, issue-шаблон) — 5–10 раз (CLI); ревью (второе мнение) — не быстрее, но ловит баги. Что НЕ ускоряет (и не должно): архитектурные решения (ИИ «подсказывает», но решение твоё); отладку «почему не работает» (ИИ гадает, debug-инструменты — нет); «сделать всё» (агент на «всё» = 5 итераций, лучше 5 задач по одной).

«Работает с ИИ» vs «работает над ИИ»: первый — ты задаёшь задачи, ИИ исполняет, ты контролируешь (план, дифы, тесты). Второй — ты «слушаешь» ИИ (каждую подсказку, каждый коммент ревью), и «инструмент» начинает управлять твоей логикой. Граница: если ты «согласился» с ИИ без проверки — ты «работаешь над ИИ». Правило курса: план, диф, тесты — три точки контроля, и на каждой — ты.

TIP: держи «личное» в copilot-instructions.md (раздел «Мой workflow»): что ты делаешь утром/вечером, какие инструменты для каких задач, где «не трогать». Тогда и ты (в новом чате), и агент (в PR) будут знать, «как ты работаешь».

NOTE: «День с Copilot» — не догма, а «каркас». Через 2 недели ты начнёшь менять его (уберёшь «вечерний changelog», добавишь «утренний @terminal»). Это нормально: каркас — чтобы начать, а не чтобы «следовать».

## Пример

```bash
# Утро (15 мин):
git pull && python -m pytest   # базовая линия
gh pr list                      # есть ли PR от агента
gh issue list                   # что «недосделано»
# В чате: @workspace «что изменилось за вчера?» (по git log)

# День (задача дня):
# 1. Формулировка: issue «list: фильтр --done»
# 2. Инструмент: Workspace (средняя задача)
# 3. План: посмотреть, поправить (добавить «не трогать»)
# 4. Исполнение: агент, дифы
# 5. Тесты: TDD (кейсы → красное → зелёное)
# 6. PR: @copilot review, merge

# Вечер (10 мин):
git add -A && git commit -m "$(copilot 'commit message из git diff')"
git push
# В чате: «создай issue на завтра: search: поддержка --all»
# Skill: «напиши changelog»
```

Обрати внимание: «день» — это не «спрашивать ИИ 50 раз», а «задавать ИИ 3–5 задач». Разница: первый — реактивный (шум), второй — активный (система).

## Частые ошибки

WARN: «спрашивать» вместо «задавать»: 50 микровопросов в чате — не «работа с ИИ», а «шум». Задача (issue) + план + исполнение — это «работа». Микровопросы — только когда «застрял» (и тогда — один, конкретный).

WARN: «соглашаться» с ИИ без проверки: план, диф, тесты — три точки контроля. Если «согласился» без чтения — ты «работаешь над ИИ». Правило: на каждой из трёх — ты (чтение, не «кнопка approve»).

WARN: «делать всё» одной задачей: агент на «сделай нам CLI» = 5 итераций. 5 задач по одной (каждая с планом, дифами, тестами) — быстрее и предсказуемее.

WARN: не «закрывать день»: без commit/push/issue на завтра «утро» начнётся с «а что я делал?». 10 минут вечером — и «утро» будет «в контексте».

## Практическое задание

Проведи «день» (хотя бы сокращённый: утро 5 мин, одна задача, вечер 5 мин) на taskit и запиши в copilot-instructions.md раздел «Мой workflow»: что делаешь утром/вечером, какие инструменты для каких задач (маленькое/среднее/«отойти»), где «не трогать» (например, «формат tasks.json — не трогать без миграции»). Этот раздел — «личная настройка» твоего Copilot, и он будет читать и ты (в новом чате), и агент (в PR).
