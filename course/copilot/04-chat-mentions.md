# Чат: как спрашивать, @workspace, @terminal

## Цель

После урока студент сможет: уверенно работать с чатом Copilot в VS Code (Ctrl+L), использовать упоминания #файл, @workspace, @terminal, @selection, @problems, составить запрос, на который чат даст точный ответ по целому репозиторию, и отличить «чат знает проект» от «чат знает то, что ты ему показал».

## Теория

Чат (Ctrl+L) — главный инструмент после комплита: это диалог с кодовой базой, где ты контролируешь контекст через упоминания. Механика одна и та же: символ открывает меню, ты выбираешь сущность — и она попадает в контекст модели. Разберём по символам.

# (хеш) — файлы: #taskit.py, #test_taskit.py. Откройшь меню и увидишь открытые и недавние файлы. Это самый дешёвый способ «приложить» конкретный файл: модель прочитает его целиком (до ограничения контекста)

@ (ат) — сущности проекта и среды:

- @workspace — семантический поиск по всему репозиторию: GitHub индексирует твои файлы (локально, без отправки всего кода), и на вопрос «где мы обрабатываем ошибки?» модель сама найдёт нужные места и приложит их.
- @terminal — чат видит последний вывод команд терминала и может их запускать: «почему тесты падают?» после провала pytest — и ответ будет про твой конкретный трэйсбэк, а не про pytest вообще.
- @selection — выделенный в редакторе фрагмент.
- @problems — текущие ошибки линтера/типов.
- @git — история: можно спросить «почему мы так написали?» и получить ответ с опорами на diff.

Главная привычка курса: перед тем как задать вопрос, подумай «что модели нужно увидеть?» — и приложи ровно это (#файл или @workspace), ничего лишнего. Чат с контекстом — это «инженер, которому показали код», без контекста — «инженер, который гуглит».

Разница между «чатом» и «inline-правкой» (Ctrl+I): чат отвечает в панели и предлагает применить патч (Apply), inline-правка меняет код сразу в редакторе. Чат — для «что тут происходит?», «спроектируй», «напиши тесты»; inline — для «переделай этот блок на async», «переименуй по нашему стилю». Ещё одна тонкость: чат в VS Code умеет режимы — обычный диалог, «ask» (только ответить, ничего не менять) и агентный (может сам править файлы и запускать команды). Для вопросов про структуру проекта используй ask, чтобы модель не «показала инициативу» и не начала переставлять файлы без спроса.

Формулировки тоже решают. Плохой запрос — «сделай как надо»; хороший — «исправь обработку пустого tasks.json: сейчас KeyError, ожидается пустой список». Чем конкретнее входные и выходные состояния, тем меньше итераций «ещё не то» — а каждая итерация съедает premium-квоту.

TIP: держи под рукой три готовых запроса: (1) @workspace «объясни структуру проекта и где что лежит» — первая строка в новом репозитории; (2) @terminal «что сломалось и как починить?» — после провала тестов; (3) #файл «какие edge-cases здесь не покрыты тестами?» — перед коммитом.

NOTE: индексация @workspace обновляется фоном: сразу после создания нового файла он может не попасть в ответ — подожди минуту или приложи файл через #явно. Это не баг, а отложенный индекс.

## Пример

```bash
# 1. Сделай в терминал что-то, что упадёт (намеренно):
python taskit.py done 99
# (ValueError: нет задачи с id 99 — у нас её ещё нет)

# 2. В чате (Ctrl+L), приложив терминал:
#    @terminal — что сломалось и как правильно обработать этот кейс?
#    Чат предложит патч (try/except + вывод «нет задачи с id N»);
#    жми Apply на предложенном диффе.

# 3. Проверь, что чат видит весь проект:
#    @workspace — где в проекте мы пишем tasks.json?
#    Ожидаемо: путь и имя функции, которая сохраняет данные.

# 4. Запусти тесты после правки:
python -m pytest
```

Сценарий «намеренный сбой → @terminal → патч → тесты» — это базовый рабочий цикл с чатом: сломал (или баг сломал), показал чату вывод, применил предложенное, проверил тестами. К уроку 15 этот цикл станет 80% ежедневной работы.

## Частые ошибки

WARN: спрашивать @workspace в пустом/только что созданном проекте: индекс пустой, и чат отвечает общими словами. Сначала доводи код до состояния «есть что искать», потом спрашивай.

WARN: лить весь контекст наугад (#файл1 #файл2 #файл3 @workspace): лишние файлы съедают лимит premium-запроса и размазывают внимание модели. Прикладывай минимум, который покрывает вопрос.

WARN: принимать Apply-патч без чтения диффа: чат правит код, которого ты не видел, — и «почему тут лишний import» из уроков 11–17 начинается именно с непрочеитанных патчей. Патч = чужой pull request: читаем, применяем, проверяем тестами.

WARN: путать чат с поиском: @workspace — семантика, а не grep. Вопрос «напечатай все места, где есть tasks.json» лучше задать через обычный поиск VS Code (Ctrl+Shift+F) — это бесплатно и точечно; чат — для вопросов по смыслу.

## Практическое задание

Проведи в репозитории taskit три сценария из «Примера» и добавь в copilot-instructions.md раздел «Структура»: какие файлы в проекте, что делает каждый (taskit.py — логика, tasks.json — данные, test_taskit.py — тесты), и где лежит README. Заполни по шаблону — это сохранит @workspace-контекст «на всякий случай»: даже если индекс будет пуст, чат прочитает этот раздел и знает, где что.
