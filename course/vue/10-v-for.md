# Урок 10. v-for: списки и ключи

## Цель

После урока студент сможет: рендерить списки через `v-for`, понимать, почему нужен `:key`, отличать «хороший» key (стабильный id) от «плохого» (index), использовать `v-for` с `v-if` корректно, и рендерить диапазоны и объекты.

## Теория

### v-for: рендер списка

`v-for="item in list"` повторяет элемент для каждого элемента `list`. Доступны:

- `item` — текущий элемент;
- `item, index` — элемент и индекс;
- `(value, key) in object` — для объектов (пары ключ-значение);
- `item in 10` — диапазон (1..10).

```html
<li v-for="(item, i) in items" :key="item.id">{{ i }}: {{ item.name }}</li>
```

### :key — почему он обязателен

`key` — **уникальный идентификатор** элемента списка. Он помогает Vue понимать, **какой именно** элемент изменился, появился или исчез, при изменении данных — и **перезаиспользовать** DOM-ноды, а не пересоздавать весь список.

Почему это важно:

- **Производительность** — без `key` Vue пересоздаёт DOM при любом изменении списка (медленно, «мигает»).
- **Корректность** — состояние внутри элемента (например, введённый текст, сфокусированный input, анимация) привязано к DOM-ноде. Без правильного `key` оно может «прыгать» между элементами.

**Хороший key:** стабильный, уникальный **id** элемента (`item.id`).
**Плохой key:** `index` (`i`) — он меняется при вставке/удалении в начале списка, и Vue «потеряет» соответствие.

```html
<!-- Хорошо: стабильный id -->
<li v-for="item in items" :key="item.id">…</li>
<!-- Плохо: index (ломается при вставке/удалении) -->
<li v-for="(item, i) in items" :key="i">…</li>
```

Исключение: если список **не меняется** (статичный) и нет `id` — `index` допустим, но лучше дать `id`.

### v-for + v-if

`v-for` имеет **приоритет** над `v-if` на одном элементе, но совмещать их на **одном** теге — антипаттерн (сложно читать, и `v-if` не видит `item`). Лучше:

- отфильтруй **в `computed`** и отрендерь отфильтрованный список;
- или оберни: `<template v-for="item in list"><div v-if="condition(item)"/></template>`.

### Диапазоны и объекты

- `v-for="n in 5"` — `n` = 1..5;
- `v-for="(value, key, index) in obj"` — пары объекта.

TIP: если список большой (сотни/тысячи) и часто меняется — убедись, что `key` стабильный и `computed` отфильтровывает до рендера. Для виртуализации (рендер только видимых) — сторонние библиотеки.

NOTE: в раннере Syntax `v-for` + `:key` работают так же, как в Vite. Попробуй удалить первый элемент — и увидишь, как «прыгает» состояние без правильного `key`.

## Пример

```vue
<script setup>
import { ref } from "vue";

const users = ref([
  { id: 1, name: "Анна" },
  { id: 2, name: "Борис" },
  { id: 3, name: "Вера" },
]);
const activeId = ref(1);

function add() {
  users.value.push({ id: Date.now(), name: "Новый" });
}
function removeFirst() {
  users.value.shift(); // удаление в начале — проверка корректности key
}
function setActive(id) { activeId.value = id; }
</script>

<template>
  <div class="demo">
    <ul>
      <li
        v-for="(u, i) in users"
        :key="u.id"
        :class="{ active: u.id === activeId }"
        @click="setActive(u.id)"
      >
        {{ i + 1 }}. {{ u.name }}
      </li>
    </ul>
    <button @click="add">Добавить</button>
    <button @click="removeFirst">Удалить первый</button>
    <p>Активен: {{ users.find(u => u.id === activeId)?.name || "—" }}</p>

    <!-- Диапазон -->
    <div>Множитель 3:
      <span v-for="n in 5" :key="n" class="badge">{{ n * 3 }}</span>
    </div>
  </div>
</template>
```

Что проверить:

- `:key="u.id"` — при удалении первого состояния (активный) «не прыгает»;
- клик по элементу — `activeId` меняется, класс `active` перерисовывается;
- «Добавить» — новый элемент получает уникальный `id`;
- диапазон — 5 бейджей с `n*3`.

## Частые ошибки

WARN: `:key="index"` на **меняющемся** списке. При вставке/удалении в начале — Vue «перепутает» элементы, и состояние внутри (input, фокус) прыгнет. Используй стабильный `id`.

WARN: **забываешь** `:key` вообще. Vue предупредит в консоли («Each child in a list should have a unique key»), но рендер будет медленным и «мерцающим».

WARN: `v-if` и `v-for` на **одном** элементе. `v-for` побеждает, но `v-if` не видит `item` — читай и баги. Отфильтруй в `computed` или оберни в `<template v-for>`.

WARN: `key` не уникален (два элемента с одинаковым `id`). Vue «спутает» их, и рендер будет некорректным. `id` должен быть уникальным.

## Практическое задание

В `App.vue` сделай «Список задач»:

1. `const tasks = ref([{ id: 1, text: "Выучить v-for", done: false }, …])` (3-4 задачи).
2. Рендер через `v-for="task in tasks"` с `:key="task.id"`.
3. Чекбокс `:checked="task.done"` и `@change` — переключает `task.done`.
4. Кнопка «Удалить» (удаляет конкретную задачу по `id` — используй `tasks.value = tasks.value.filter(t => t.id !== id)`).
5. Кнопка «Добавить» — пушит `{ id: Date.now(), text: "…", done: false }`.
6. Сверху — `computed` `remaining` — количество невыполненных.
7. Запусти **Run**: добавь/удали, отметь — убедись, что `key` стабильный и состояния не «прыгают».
