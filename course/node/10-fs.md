# Урок 10. fs: sync vs async, readFile/writeFile, коды ошибок

## Цель

После урока студент сможет: читать и писать файлы (синхронно и через `fs.promises`), создавать каталоги (`mkdir` с `recursive`), проверять существование (`access`), обрабатывать файловые ошибки по **кодам** (`ENOENT`, `EISDIR`), и объяснять, когда `sync`-версии допустимы, а когда — нет.

## Теория

### `fs` — модуль файловой системы

`fs` (file system) — главный встроенный модуль для файлов. Две формы API:

1. **Колбэк**: `fs.readFile(file, "utf8", (err, data) => …)` — историческая.
2. **Promise**: `const data = await fs.promises.readFile(file, "utf8")` — современная (используем её).
3. **Sync**: `fs.readFileSync(file, "utf8")` — блокирует Event Loop.

Промис-форма доступна как `fs.promises` или отдельным импортом: `import { promises as fsp } from "fs"`.

### Базовые операции

```js
import { promises as fsp } from "fs";

await fsp.writeFile("/app/a.json", JSON.stringify({ ok: true }));   // записать (перезаписать)
await fsp.appendFile("/app/log.txt", "строка\n");                    // дописать
const raw = await fsp.readFile("/app/a.json", "utf8");              // прочитать (encoding → строка)
await fsp.mkdir("/app/deep/dir", { recursive: true });              // создать каталог (с родителями)
await fsp.access("/app/a.json");                                     // существует? (иначе бросит)
await fsp.rename("/app/a.json", "/app/b.json");                      // переименовать
await fsp.unlink("/app/b.json");                                     // удалить файл
const list = await fsp.readdir("/app");                              // содержимое каталога
const stat = await fsp.stat("/app/a.json");                          // { size, isFile(), isDirectory(), … }
```

### Sync vs async: когда что

- **async (promises)** — практически всегда в серверном коде: не блокирует Event Loop.
- **sync** — только в скриптах/CLI (файл конфигурации при старте), в тестах и в кодах, где «дождать» проще, чем обёртывать. В HTTP-обработчике `readFileSync` на большом файле = замирает **весь** сервер.

### Ошибки: коды, а не текст

Файловые ошибки — объекты с **`code`** (стабильная машина-строка): `ENOENT` (нет файла), `EISDIR` (это каталог), `EEXIST` (уже есть), `EPERM` (нет прав). Сравнивайте **код**, а не текст сообщения (текст меняется между версиями/ОС):

```js
try {
  await fsp.readFile("/app/nope.txt", "utf8");
} catch (e) {
  if (e.code === "ENOENT") { /* файла нет — создадим */ }
  else throw e; // неожиданная — пробрасываем
}
```

TIP: `fs.access` перед операцией — **анти-паттерн** (гонка: файл могли удалить между проверкой и чтением). Лучше «попробовать и поймать `ENOENT`» (try/catch по коду).

NOTE: в песочнице платформы `fs` — **in-memory** файловая система: файлы живут до перезагрузки страницы (в терминале — на диске). API и коды ошибок — идентичные.

## Пример

`server.js`:

```js
import { promises as fsp } from "fs";

async function main() {
  // 1) Каталог + файл
  await fsp.mkdir("/app/data", { recursive: true });
  await fsp.writeFile("/app/data/config.json", JSON.stringify({ port: 3000 }, null, 2));
  console.log("Записали config.json");

  // 2) Чтение + обработка ENOENT по коду
  async function readJsonSafe(file) {
    try {
      return JSON.parse(await fsp.readFile(file, "utf8"));
    } catch (e) {
      if (e.code === "ENOENT") return null; // файла нет — «нормально»
      throw e;
    }
  }
  console.log("config:", await readJsonSafe("/app/data/config.json"));
  console.log("missing:", await readJsonSafe("/app/data/missing.json"));

  // 3) append + stat
  await fsp.appendFile("/app/data/log.txt", "line 1\n");
  await fsp.appendFile("/app/data/log.txt", "line 2\n");
  const st = await fsp.stat("/app/data/log.txt");
  console.log("log.txt:", st.size, "байт, isFile:", st.isFile());

  // 4) readdir: список файлов
  const entries = await fsp.readdir("/app/data");
  console.log("В каталоге:", entries);

  // 5) rename + unlink
  await fsp.rename("/app/data/log.txt", "/app/data/old.log");
  console.log("После rename:", await fsp.readdir("/app/data"));
  await fsp.unlink("/app/data/old.log");
  console.log("После unlink:", await fsp.readdir("/app/data"));
}

main().catch((e) => console.error("Ошибка:", e.code, e.message));
```

## Частые ошибки

WARN: `readFileSync`/`writeFileSync` в HTTP-обработчике — блокирует Event Loop (сервер «замирает» на время операции). Только `fs.promises`.

WARN: сравниваете `e.message` по строке (`"no such file"`). Текст зависит от версии/ОС. Сравнивайте **`e.code`** (`ENOENT`).

WARN: `fs.access` перед `readFile` — гонка (файл удалят между проверкой и чтением). Паттерн: try/catch по `ENOENT`.

WARN: `mkdir` без `recursive: true` на вложенный каталог — `ENOENT` (нет родителя). Для «создай каталог вместе с родителями» — `{ recursive: true }`.

4. Реализуйте `appendLog(file, msg)`: добавить строку `timestamp + " " + msg`; если файла нет — создать.
5. Проверьте: `listItems` на пустом каталоге (должен вернуть `[]`, не упасть); `appendLog` дважды; `stat` результата.
