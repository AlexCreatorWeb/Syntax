# Урок 1. Node.js и V8: как работает рантайм

## Цель

После урока студент сможет: объяснить, что такое Node.js и чем он отличается от браузера, назвать, на чём он построен (V8, libuv, Event Loop), запускать скрипты командой `node`, использовать глобальный объект `process` (env, argv, version, exit) и понимать, где «живёт» код Node (файловая система, сеть, child process — а не вкладка браузера).

## Теория

### Что такое Node.js

Node.js — **рантайм** (среда выполнения) для JavaScript: он позволяет запускать JS **вне браузера**. В браузере JS управляет страницей (DOM), в Node — «системными» ресурсами: файлами, сетью, процессами. Подвижки один и тот же язык (JavaScript + ES-модули), но окружение другое:

- нет `document`, `window`, `fetch` как DOM-API — зато есть **встроенные модули**: `fs` (файлы), `http` (сервер), `path` (пути), `events`, `buffer` и десятки других;
- есть глобальный объект **`process`** — «окно» в процесс: окружение (`process.env`), аргументы запуска (`process.argv`), версия (`process.version`), выход (`process.exit(code)`).

### Из чего состоит Node

Три слоя:

1. **V8** — движок JavaScript (тот же, что в Chrome): компилирует JS в машинный код, умеет и промисы, и GC (сборку мусора).
2. **libuv** — библиотека, которая умеет **неблокирующий ввод-вывод**: сеть, файлы, таймеры. Она работает в **отдельных потоках** и стучится в основной, когда «готово».
3. **Event Loop** — цикл, который в **основном** (единственном) потоке разбирает задачи: «выполни функцию, обработай готовный I/O, выполни микротаски».

Ключевая идея: **один поток для вашего кода**. Ваш JS никогда не блокируется на I/O: запросили файл/сеть → control уходит в libuv → когда готово — колбэк попадает в очередь. Поэтому один процесс Node держит десятки тысяч соединений (в отличие от «потока на запрос» у классических серверов).

### Первый скрипт

Создаёте файл `server.js` и запускаете в терминале: `node server.js`. Всё, что пишет `console.log`, видно в терминале (в платформе Syntax — в панели консоли под редактором).

NOTE: в платформе Syntax Node-задания выполняются в **браузерном песочнице**: `process.env` предзаполнен демо-значениями (`PORT`, `JWT_SECRET`, `DATABASE_URL`), файлы — в памяти, HTTP-сервер — имитация (проверяете его хелпером `__request`, см. NOTE в уроках про http/Express). Логика при этом та же самая, что в реальном Node.

## Пример

`server.js`:

```js
// Мой первый Node-скрипт
console.log("Привет из Node!");
console.log("Версия:", process.version);
console.log("Среда:", process.env.NODE_ENV || "(не задана)");
console.log("Порт из env:", process.env.PORT);
console.log("Аргументы:", process.argv); // [path-to-node, path-to-server.js, ...аргументы]

// process.nextTick — «выполни как можно скорее» (раньше микротасок)
process.nextTick(() => console.log("nextTick: я выполнился до setTimeout"));

setTimeout(() => console.log("setTimeout: я позже"), 10);

// exit-код: 0 — успех, != 0 — ошибка (важно для CI/скриптов)
// process.exit(0);
```

Запуск: `node server.js`. Обратите внимание: порядок вывода — `nextTick` **до** `setTimeout` (микротаски обгоняют макротаски — подробно в уроке 2).

## Частые ошибки

WARN: пишете браузерный код: `document`, `window`, `alert` — в Node их нет (ReferenceError). Окружение другое: вместо `window` — `globalThis`, вместо DOM — модули (`fs`, `http`).

WARN: запускаете `server.js` двойным кликом (как HTML-файл). Node-скрипты запускают **из терминала**: `node server.js`. В IDE — через терминал или «Run task».

WARN: читаете `process.env.PORT` и ждёте число, а получаете **строку** `"3000"`. Все env-переменные — строки: приводите сами (`Number(process.env.PORT)`).

## Практическое задание

1. Создайте `server.js` и выведите: версию Node (`process.version`), платформу (`process.platform`), текущий рабочий каталог (`process.cwd()`).
2. Выведите все переменные окружения песочницы: `console.log(process.env)`.
3. Запустите скрипт с аргументами (`node server.js foo 42`) и выведите `process.argv` — объясните, что означают первые два элемента.
4. Добавьте `process.nextTick` и `setTimeout` (0 мс) с разными сообщениями — убедитесь, что nextTick раньше.
5. В платформе: нажмите **Run** и сравните вывод в панели консоли с выводом в терминале.
