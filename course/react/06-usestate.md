# Урок 6. Состояние: useState

## Цель
После урока студент сможет: создавать состояние с `useState`; понимать, чем состояние отличается от обычной переменной; обновлять состояние правильно (без мутаций) и использовать функциональную форму `setState`.

## Теория
### Состояние — данные, которые «живут» в компоненте
**Состояние** (state) — данные компонента, при изменении которых React **перерисовывает** UI. Обычная переменная (`let count = 0`) меняется молча — UI не обновится. Чтобы React «увидел» изменение, данные должны быть **состоянием**.
```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <p>Нажатий: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
```
`useState(0)` возвращает **пару**: текущее значение `count` и **функцию обновления** `setCount`. Начальное значение `0` задаётся **один раз**, при первом рендере.

### Как обновлять состояние: `setCount(новоеЗначение)`
Вызвать `setCount(5)` — React запомнит новое значение и **перерендерит** компонент, и UI обновится. Главное правило: **не мутируйте** состояние, а **заменяйте** его.
```jsx
// ❌ мутация — React может не заметить
items.push("новое");

// ✅ замена — новый массив
setItems([...items, "новое"]);
```
Для примитивов (числа, строки, булевы) мутации не существует — вы просто задаёте новое значение. Для **объектов и массивов** — всегда **копирование** (спрэд `[...arr]`, `{ ...obj }`), потому что React сравнивает **ссылки**: та же ссылка — тот же объект.

### Функциональная форма: `setCount(prev => prev + 1)`
Когда новое значение зависит от **текущего**, используйте **функциональную** форму:
```jsx
setCount((prev) => prev + 1);   // безопасно
setCount(count + 1);            // тоже работает, но…
```
Разница проявляется, когда вы делаете **несколько** обновлений подряд или обновление приходит **из события с задержкой**. Функциональная форма всегда берёт **самое свежее** `prev`, поэтому **надёжнее**. По умолчанию пишите `setX((prev) => …)` для счётчиков и списков.

### Когда состояние «живёт»
Состояние хранится **внутри компонента** и **принадлежит** ему. Компонент перерисовывается — состояние **сохраняется** (React привязывает его к позиции в дереве). Компонент **размонтируется** (исчез из дерева) — состояние **теряется**. Поэтому «общее» состояние поднимают в **общего родителя** (state lifting, уроки 7–8).

TIP: Имена: значение — **именительный** падеж (`count`, `user`), сеттер — `set` + заглавная (`setCount`, `setUser`). Для «флагов» — `isOpen`, `setOpen`. Читаемые имена — половина отладки.

## Пример
Мини-«стекляшка» с состоянием:
```jsx
import { useState } from "react";

function App() {
  const [likes, setLikes] = useState(3);
  const [text, setText] = useState("Привет, React!");
  const [items, setItems] = useState(["яблоко"]);

  return (
    <div>
      <h1>{text}</h1>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        style={{ display: "block", marginBottom: 8 }}
      />
      <button onClick={() => setLikes((p) => p + 1)}>❤️ {likes}</button>
      <button
        onClick={() => setItems((prev) => [...prev, `item ${prev.length + 1}`])}
      >
        Добавить в список
      </button>
      <ul>
        {items.map((it) => (
          <li key={it}>{it}</li>
        ))}
      </ul>
    </div>
  );
}
export default App;
```
Разбор: три состояния — число `likes`, строка `text`, массив `items`. Обновление `likes` и `items` — **функциональной** формой. `text` одновременно и **состояние**, и **value** инпута (контролируемый компонент — урок 7). Каждое `set*` вызывает **перерендер**, и UI «догоняет» данные.

## Частые ошибки
WARN: **Мутация массива/объекта**: `items.push(x)` или `obj.a = 1` + `setItems(items)` — React видит **ту же ссылку** и **не перерендеривает**. Всегда **копируйте**: `setItems([...items, x])`, `setObj({ ...obj, a: 1 })`.
WARN: **Перезаписали состояние переменной**: `const [n, setN] = useState(0); n = n + 1;` — `n` это **константа-снимок** текущего рендера, присваивание `n = …` либо ошибка (`const`), либо не влияет на React. Обновляйте **только** через `setN(…)`.
WARN: **Начальное значение из пропса без учёта изменений**: `const [val] = useState(props.initial)` — пропс поменялся, а состояние **не** (нормально по смыслу), но если нужно «синхронно» — это другая задача (урок 15, `useEffect`). Не путайте «состояние-копия пропса» и «состояние-источник».
WARN: **Обновление «не сработало»** — потому что вы мутировали (первая ошибка) или создали состояние **внутри условия/цикла** (нарушение правил хуков, урок 13). Хуки — только на **верхнем уровне** компонента.
