# Урок 5. Условный рендеринг: &&, тернарник, early return

## Цель
После урока студент сможет: рендерить разные куски UI в зависимости от данных; уверенно использовать тернарный оператор, логическое `&&` и early return; строить UI по паттерну «loading / error / data».

## Теория
### UI зависит от данных
Главная формула React — `UI = f(состояние)`. Раз состояние может быть разным, **UI тоже должен быть разным**. Для этого в JSX используются те же условные конструкции, что в JavaScript.

### Три основных способа
**1. Тернарный оператор** — когда нужно показать **одно из двух**:
```jsx
{isDone ? <Done /> : <Pending />}
```
**2. Логическое `&&`** — когда кусок рендерится **только если условие истинно** (иначе — вообще ничего):
```jsx
{user.isAdmin && <AdminPanel />}
```
Внимание: `&&` возвращает **левый операнд**, если он «ложный». Поэтому `0 && <X />` отрендерит **`0`** на страницу (React печатает `0` как текст). Безопаснее — тернарник или явная проверка.
**3. Early return** — когда **весь** компонент зависит от условия, вынесите его в начало:
```jsx
function Profile({ user, loading, error }) {
  if (loading) return <p>Загружаем…</p>;
  if (error) return <p>Ошибка: {error}</p>;
  if (!user) return <p>Пользователь не найден</p>;
  return <h1>{user.name}</h1>;
}
```

### Паттерн «loading / error / data»
Это **самый частый** паттерн React-приложения: при загрузке данных UI проходит три состояния.
```jsx
function Users() {
  // loading — пока идёт запрос
  // error — если запрос упал
  // data  — если данные пришли
  if (loading) return <p>Загрузка…</p>;
  if (error) return <p>Ошибка: {error}</p>;
  if (!data || data.length === 0) return <p>Пусто</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
```
Этот паттерн — мост к урокам 10–11, где данные приходят из API.

### Фрагменты для нескольких корневых элементов
Если условие возвращает **несколько** элементов, оберните их в Fragment:
```jsx
{isLoggedIn && (
  <>
    <Welcome />
    <LogoutButton />
  </>
)}
```

TIP: Не усложняйте. **Тернарник** — для «А или Б», **`&&`** — для «А, если можно», **early return** — для «весь компонент зависит от X». Три инструмента закрывают 99% случаев.

## Пример
Компонент-«светофор» статуса заказа:
```jsx
function OrderStatus({ status }) {
  if (status === "loading") return <p>Оформляем заказ…</p>;
  if (status === "error") return <p style={{ color: "red" }}>Не удалось оформить, попробуйте ещё раз</p>;
  if (status === "done") return <p style={{ color: "green" }}>Заказ оформлен!</p>;
  return <p>Заказ не начат</p>;
}

export default function App() {
  return (
    <div>
      <OrderStatus status="loading" />
      <OrderStatus status="error" />
      <OrderStatus status="done" />
      <OrderStatus status="idle" />
      <hr />
      <p>{false && <span>Этого не будет</span>}</p>
      <p>{0 && <span>А это — цифра 0!</span>}</p>
    </div>
  );
}
```
Разбор: `OrderStatus` — чистая функция от `status`, рендерит один из четырёх вариантов. Обратите внимание на `0 && <span>…</span>` — на странице отобразится **`0`**, а не пустота. Это классическая ловушка `&&`.

## Частые ошибки
WARN: **`0 && <X />` / пустая строка** — рендерит `0` или `""` как текст на страницу. Для «показать, если есть число» используйте тернарник: `{count > 0 && <X />}` или `{count ? <X /> : null}`.
WARN: **`if/else` прямо в JSX**: `{if (x) {…}}` — синтаксическая ошибка. `if` — это **утверждение**, не выражение; в JSX нужны **выражения** (тернарник, `&&`). `if` работает только **до** `return` (early return).
WARN: Забыли **закрыть Fragment** `</>` или использовали `<>` там, где нужен `key` (в списке) — в списках вместо `<>` нужен `<React.Fragment key={…}>` (урок 8).
WARN: **Условие всегда истинно/ложно** из-за опечатки: `{user.admin && <X/>}` вместо `user.isAdmin` — `undefined && …` → рендерится **ничего** (или `0`), и вы долго ищете «почему не показывается». Проверяйте **имя** поля.

## Практическое задание
1. Создайте компонент `TrafficLight({ color })`, который по `color` (`"red" | "yellow" | "green"`) рендерит круг соответствующего цвета (early return или тернарник).
2. Создайте `Notification({ type, message })`: если `type === "error"` — красный, `"success"` — зелёный, иначе серый; текст — `message`.
3. В `App` отрендерите `Notification` три раза с разными `type`.
4. Добавьте в `App` переменную `const count = 0` и блок `{count && <p>Есть элементы</p>}` — увидите, почему это плохая идея, затем поправьте через тернарник.
5. Бонус: напишите `Profile({ user, loading, error })` по паттерну early return и отрендерите в трёх состояниях.
