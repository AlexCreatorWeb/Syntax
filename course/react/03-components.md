# Урок 3. Компоненты: композиция и разбивка

## Цель
После урока студент сможет: разбивать большой UI на мелкие компоненты; понимать композицию (компоненты внутри компонентов) и роль «деревья компонентов»; знать, когда компонент стоит вынести отдельно.

## Теория
### Композиция — главная сила React
React-приложение — это **дерево компонентов**: родитель рендерит дочерних, те — своих. Это называется **композицией** — вы строите сложное UI из простых, переиспользуемых кусочков, точно так же, как строите дом из кирпичей.
```jsx
function Card({ title, children }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      {children}
    </div>
  );
}

function App() {
  return (
    <div>
      <Card title="Профиль">
        <p>Имя: Анна</p>
        <p>Город: Москва</p>
      </Card>
      <Card title="Настройки">
        <p>Тема: тёмная</p>
      </Card>
    </div>
  );
}
```
`Card` — **переиспользуемый** контейнер: он не знает, что внутри, а принимает «содержимое» через специальный пропс `children`. Это и есть композиция: один компонент — много применений.

### `children` — «слот» для содержимого
**`children`** — специальный пропс, который React автоматически передаёт всему, что находится **между** открывающим и закрывающим тегом компонента:
```jsx
<Card title="Профиль">
  <p>Имя: Анна</p>   {/* это и есть children */}
</Card>
```
Внутри `Card` вы просто делаете `return <div>{children}</div>` — и получаете «слот», куда родитель кладёт любой JSX. Так создаются универсальные обёртки: `Card`, `Modal`, `Sidebar`, `Layout`.

### Как разбивать UI на компоненты
Эвристика **«один компонент — одна забота»**:
- **По визуальному блоку**: шапка, карточка товара, форма — каждый свой компонент.
- **По переиспользованию**: если кусок разметки повторяется — выносите в компонент.
- **По данным**: если часть UI зависит от своих данных/состояния — ей быть отдельным компонентом.
- **По глубине вложенности**: если `return` стал «лесом» на 50+ строк — разбивайте на под-компоненты, даже одноразовые.

Разбивка **не требует** отдельных файлов: несколько компонентов можно держать в одном `App.jsx` (как в этом курсе). Вынесение в файл — организационный вопрос, а не технический.

### Как React рисует дерево
Когда вы пишете `<App />`, React **рекурсивно** вызывает компоненты: `App` → возвращает JSX с `<Card />` → React вызывает `Card` → и так по всему дереву, до «листов» (обычных тегов). Результат — плоское дерево виртуальных узлов, которое React сравнивает с предыдущим и минимально обновляет в настоящем DOM.

TIP: Начните с **одного** большого компонента, а затем **выносите** повторяющиеся куски в отдельные функции. Не проектируйте архитектуру «сверху вниз» до первой строки — разбивка приходит по мере того, как UI становится объёмным.

## Пример
Постепенная разбивка «списка задач»:
```jsx
function TaskItem({ text, done }) {
  return (
    <li style={{ textDecoration: done ? "line-through" : "none" }}>
      {text}
    </li>
  );
}

function TaskList({ tasks }) {
  return (
    <ul>
      {tasks.map((t, i) => (
        <TaskItem key={t.id} text={t.text} done={t.done} />
      ))}
    </ul>
  );
}

function Header({ title }) {
  return <h2>{title}</h2>;
}

export default function App() {
  const tasks = [
    { id: 1, text: "Выучить JSX", done: true },
    { id: 2, text: "Понять композицию", done: false },
  ];
  return (
    <div>
      <Header title="Мои задачи" />
      <TaskList tasks={tasks} />
    </div>
  );
}
```
Разбор: `App` хранит **данные** (`tasks`) и **собирает** дерево. `Header`, `TaskList`, `TaskItem` — независимые, «глупые» компоненты: они получают данные пропсами и рисуют. `TaskList` знает, как рендерить **список**, а `TaskItem` — **одну** строку. Каждый компонент можно переиспользовать и тестировать отдельно.

## Частые ошибки
WARN: **Огромный `App`** на 100+ строк, где и данные, и разметка, и логика — «бог-компонент». Разбивайте по блокам: выносите `Header`, `List`, `Item`. Композиция — смысл React.
WARN: Компонент **передаёт `children`, но не рендерит их** — родитель кладёт содержимое между тегами, а компонент его игнорирует (забыл `{children}` в `return`). Содержимое «пропадает».
WARN: Вызывали компонент как функцию `TaskItem()` внутри `return` — так React **не увидит** его как компонент (потеряется состояние, key, жизненный цикл). Всегда — теговая форма `<TaskItem />`.
WARN: **Глубоко вложенные одноразовые компоненты**, объявленные внутри других (`function App() { function Inner() {…} return <Inner/> }`) — `Inner` **создаётся заново** при каждом рендере `App` и теряет состояние. Вложенные компоненты объявляйте **на верхнем уровне** файла.

## Практическое задание
1. Создайте компонент `Section({ title, children })`, который рендерит `<section><h3>{title}</h3>{children}</section>`.
2. В `App` используйте **два** `Section` с разными заголовками и разным содержимым внутри.
3. Создайте компонент `Avatar({ name })`, возвращающий `<div className="avatar">{name[0].toUpperCase()}</div>` (первую букву имени).
4. Соберите компонент `UserCard({ user })`, который использует `Avatar` и показывает имя и роль пользователя из объекта `user`.
5. Бонус: отрендерите **три** `UserCard` в цикле `.map()` по массиву `users`.
