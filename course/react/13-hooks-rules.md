# Урок 13. Правила хуков и кастомные хуки

## Цель
После урока студент сможет: сформулировать **два** правила хуков и объяснить, **почему** они важны; писать **кастомный хук** (функция с хуками внутри) и переиспользовать его в нескольких компонентах.

## Теория
### Хуки — это функции с особыми правилами
**Хук** (hook) — функция, начинающаяся с `use` (`useState`, `useEffect`, `useMemo`, …), которая «привязывает» компонент к **функциям** React (состояние, эффекты). Вы уже пользуетесь хуками с урока 6. Теперь — **правила** и **свои**.

### Два правила хуков
**Правило 1: хуки вызывайте только на «верхнем уровне» компонента.** Не внутри **циклов**, **условий**, **вложенных функций**:
```jsx
function Bad({ isAdmin }) {
  if (isAdmin) {
    const [x, setX] = useState(0); // ❌ внутри if
  }
  return <p>…</p>;
}
```
**Почему**: React «запоминает» хуки **по порядку** вызова (внутренний список: 1-й `useState` → состояние A, 2-й → B). Если порядок **меняется** от рендера к рендеру (из-за `if`/цикла), React **соединяет** состояния **не с теми** хуками — **баг**. Поэтому порядок должен быть **стабильным** — хуки только **наверху**.

**Правило 2: хуки вызывайте только из React-компонентов (или кастомных хуков).** Не из обычных функций, колбэков DOM (если не через хук), классов. **Кастомные хуки** — **исключение** (см. ниже), потому что **по сути** они — компоненты-хелперы.

### Как React «помнит» порядок (на пальцах)
При каждом рендере React **идёт** по компонентам и **вызывает** хуки **в том же порядке**, что и раньше. Внутренне он держит **список** состояний, привязанный к **индексу** вызова. Условный/циклический вызов **меняет** индексы → **рассинхрон**. Это **главная** причина правила 1.

### Кастомный хук — «свой» хук
**Кастомный хук** — просто **функция**, имя которой **начинается** с `use`, и внутри которой **вызываются** другие хуки. Это **не** новый механизм React, а **паттерн** **переиспользования** логики.
```jsx
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);
  return width;
}

function Header() {
  const width = useWindowWidth(); // «хук внутри хука»
  return <p>Ширина: {width}</p>;
}
```
`useWindowWidth` **собирает** состояние **и** эффект, **возвращает** готовое значение. Любой компонент может его **вызвать** — логика **одна**, а не **копипаст**.

### Что **вынести** в кастомный хук
- **Повторяющаяся** логика (запрос к API + loading/error — урок 14).
- **Связка** «состояние + эффект» (подписка, таймер, localStorage).
- Всё, что **начинается** с `use` и **возвращает** данные/функции для компонента.

TIP: Имя кастомного хука — **глагол** + **сущность**: `useWindowWidth`, `useFetch`, `useLocalStorage`, `useDebounce`. Имя говорит, **что** делает. Хук — **не** «компонент», а **функция**; он **не** возвращает JSX (хотя и может, если обёртка, но обычно — данные/функции).

## Пример
Хук `useLocalStorage` (состояние, синхронизированное с браузером):
```jsx
import { useState, useEffect } from "react";

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    const stored = window.localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initial;
  });
  useEffect(() => {
    window.localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}

function App() {
  const [theme, setTheme] = useLocalStorage("theme", "light");
  const [count, setCount] = useLocalStorage("count", 0);

  return (
    <div style={{ background: theme === "dark" ? "#111" : "#f5f5f5", color: theme === "dark" ? "#fff" : "#000", padding: 16 }}>
      <h2>Тема: {theme}</h2>
      <button onClick={() => setTheme((t) => (t === "dark" ? "light" : "dark"))}>Переключить</button>
      <p>Счётчик: {count}</p>
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <p>Оба значения **переживут** перезагрузку страницы (localStorage).</p>
    </div>
  );
}
export default App;
```
Разбор: `useLocalStorage` — **один** хук, **две** задачи: читает **из** `localStorage` при инициализации (ленивый `useState(() => …)`) и **пишет** обратно при изменении (`useEffect`). `App` использует его **дважды** (`theme`, `count`) — логика **не** продублирована. При **перезагрузке** значения **сохраняются**.

## Частые ошибки
WARN: **Хук внутри `if`/цикла/вложенной функции** — порядок вызовов **меняется**, состояния **рассинхронизируются** (непредсказуемый баг). Хуки **только** на верхнем уровне.
WARN: **Вызов хука из «обычной» функции** (не компонента, не хука) — `useState` «напрямую» в `function helper() { … }` — **ошибка** (React не знает, к какому компоненту привязать). Оберните в **кастомный хук** `use…` и вызывайте **из компонента**.
WARN: **Кастомный хук без префикса `use`** (`function windowWidth() { useState(…) }`) — линтер **не поймёт**, что это хук, и **не** проверит правила; вы сами можете **забыть** правила. Всегда **`use`** в имени.
WARN: **Возврат «голого» объекта** из хука **без** мемоизации: `return { data, loading }` — **новый** объект каждый рендер, что **ломает** `useMemo`/`useEffect` у вызывающего (зависимость-объект **всегда** новая). Возвращайте **массив** (как `useState`) или **мемоизированный** объект.

## Практическое задание
1. Напишите `useCount()` — хук с `useState(0)` и функциями `increment`, `decrement`, `reset`; верните `[count, increment, decrement, reset]`.
2. Используйте `useCount` **в двух** компонентах (`CounterA`, `CounterB`) в `App` — убедитесь, что счётчики **независимы**.
3. Напишите `useInterval(callback, delay)` — хук, который вызывает `callback` каждые `delay` мс (с cleanup), `deps = [callback, delay]`.
4. Используйте `useInterval` для «тикающих» секунд в компоненте.
5. Бонус: объясните **в комментарии**, почему `useCount` в двух компонентах даёт **разные** значения (а не общее).
