# Урок 12. Производное состояние: useMemo и useCallback

## Цель
После урока студент сможет: отличать «производные» значения от «источников» состояния; использовать `useMemo` для дорогих вычислений и `useCallback` для стабильных функций; понимать, **когда** оптимизация нужна, а когда — лишний шум.

## Теория
### Не храните в состоянии то, что можно вычислить
**Производное состояние** — то, что **полностью определяется** другими данными. Его **не** нужно (и **не** стоит) хранить в отдельном `useState` — просто **считайте** при рендере:
```jsx
const [items, setItems] = useState([...]);
const total = items.reduce((s, x) => s + x.price, 0); // вычислено, а не «состояние»
```
Попытка «синхронизировать» такое значение через `useEffect` + `setState` — **лишний** рендер и источник багов. **Считайте, а не храните.**

### `useMemo` — мемоизация значения
**`useMemo(fn, deps)`** — «запомните» результат **вычисления** `fn` и **пересчитывайте** его **только** когда изменились `deps`. Полезно, когда вычисление **дорогое** (большой `filter`/`sort`/`reduce`), чтобы не делать его **каждый** рендер.
```jsx
const filtered = useMemo(
  () => items.filter((i) => i.name.includes(query.toLowerCase())),
  [items, query]
);
```
Если `items` и `query` **не** изменились — `filtered` **тот же** (React **не** пересчитывает).

### `useCallback` — мемоизация функции
**`useCallback(fn, deps)`** — «запомните» **саму функцию**, чтобы она была **той же** ссылкой между рендерами (пока `deps` не изменились). Нужно, когда функцию **передаёте** дочерним компонентам как пропс (иначе — **новая** функция каждый рендер → лишние перерисовки у детей, см. урок 4).
```jsx
const addItem = useCallback((text) => {
  setItems((prev) => [...prev, { id: crypto.randomUUID(), text }]);
}, []); // setItems стабилен → deps []
```
Теперь `addItem` — **одна и та же** функция; дочерний компонент, получающий её, **не** перерисовывается «зря».

### Когда это **нужно**, а когда — **шум**
- **Нужно**: **дорогое** вычисление каждый рендер; передача **функций/объектов** в **оптимизированные** (`React.memo`) дети; **зависимости** `useEffect` от функции.
- **Шум**: мелкие вычисления (`a + b`, короткий `filter`), «мемоизация ради мемоизации». `useMemo` **сам** имеет цену (хранит кэш, сравнивает `deps`) — для простого кода он **замедлит**, а не ускорит.

**Правило**: сначала **напишите просто**, оптимизируйте **по замерам** (профилировщик React DevTools). Мемоизация — **точечный** инструмент, а не стиль.

TIP: `useMemo`/`useCallback` — **под капотом** опираются на тот же механизм, что и сравнение `deps` в `useEffect`. Логика одна: «пересчитать/пересоздать **только** если изменились зависимости».

## Пример
Поиск по «большому» списку с мемоизацией:
```jsx
import { useState, useMemo, useCallback } from "react";

const PRODUCTS = Array.from({ length: 5000 }, (_, i) => ({
  id: i,
  name: `Товар ${i}`,
  price: (i % 50) * 10 + 10,
}));

function Item({ p, onPick }) {
  return (
    <li>
      {p.name} — {p.price} ₽ <button onClick={() => onPick(p.id)}>Выбрать</button>
    </li>
  );
}

function App() {
  const [query, setQuery] = useState("");
  const [picked, setPicked] = useState(null);

  // Дорогое: фильтруем 5000 элементов — считаем только при смене query
  const filtered = useMemo(
    () => PRODUCTS.filter((p) => p.name.toLowerCase().includes(query.toLowerCase())),
    [query]
  );

  // Стабильная функция для детей (не пересоздаётся каждый рендер)
  const handlePick = useCallback((id) => setPicked(id), []);

  return (
    <div>
      <input value={query} onChange={(e) => setQuery(e.target.value)} placeholder="Поиск" />
      <p>Найдено: {filtered.length}. Выбрано: {picked ?? "—"}</p>
      <ul>
        {filtered.slice(0, 100).map((p) => (
          <Item key={p.id} p={p} onPick={handlePick} />
        ))}
      </ul>
    </div>
  );
}
export default App;
```
Разбор: `filtered` — **производное** от `query` (не хранится в `state`, а **вычисляется** через `useMemo`). `handlePick` — **стабильная** функция (`useCallback`, `deps []`, т.к. использует только `setPicked`). `PRODUCTS` — **вне** компонента, чтобы не пересоздаваться. `slice(0, 100)` — рендерим не все 5000, а **первые** 100 (иначе DOM «затянет»).

## Частые ошибки
WARN: **Храните производное в `useState`** и «синхронизируете» через `useEffect` — лишний рендер и рассинхрон. **Считайте** при рендере (или `useMemo`), а **не** храните.
WARN: **`useMemo` для дешёвого** вычисления (`a + b`) — «оптимизация», которая **замедляет** (кэш + сравнение `deps` дороже вычисления). Мемоизируйте **дорогое**.
WARN: **Забраковали `deps`** в `useMemo`/`useCallback** (положили `[]`, хотя читаете `query`) — результат **застревает** на старом значении (stale, как в уроке 11).
WARN: **Мемоизируете, но ребёнок **не** оптимизирован** (`React.memo`) — стабильная функция **не** остановит перерисовку ребёнка, если **родитель** перерисовывается и ребёнок **не** обёрнут в `React.memo`. Мемоизация работает **в паре**.
