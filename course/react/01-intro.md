# Урок 1. React: компонентный подход и первое приложение

## Цель
После урока студент сможет: объяснить, что такое декларативный подход «UI = f(состояние)»; создать первое React-приложение через `createRoot`; написать функциональный компонент и понять, что React перерисовывает UI при изменении данных.

## Теория
### Что такое React и зачем он нужен
**React** — библиотека JavaScript для построения интерфейсов из **компонентов** — независимых, переиспользуемых кусочков UI со своей логикой. Главная идея React — **декларативность**: вы не управляете DOM вручную (как в чистом JS: `document.querySelector`, `el.textContent = …`), а **описываете**, как UI должен выглядеть при каждом состоянии данных. React сам следит за данными и **минимально** обновляет DOM.

Формула, вокруг которой строится весь React:
```
UI = f(состояние)
```
Состояние изменилось → React пересчитал компонент → сравнил «старый» и «новый» результат (реконцилиация) → обновил только то, что изменилось в DOM.

### Первое приложение: createRoot
React 18 монтирует приложение функцией `createRoot` из пакета `react-dom/client`:
```jsx
import { createRoot } from "react-dom/client";

function App() {
  return <h1>Привет, React!</h1>;
}

const root = createRoot(document.getElementById("root"));
root.render(<App />);
```
`createRoot` создаёт «корень» — точку, в которую React управляет DOM. `root.render(<App />)` — рендерит компонент `App` внутрь. В нашем редакторе это делает **раннер** автоматически: вы пишете только компонент `App` (файл `App.jsx`), а `createRoot` уже подключён.

NOTE: В редакторе Syntax файл задания — `App.jsx`. Напишите компонент с именем `App`, нажмите **Run**, и приложение отрисуется в панели превью (React 18 загружается с CDN, JSX компилируется на лету). Тот же код без изменений работает в локальном проекте на Vite (`npm create vite@latest -- --template react`) и в песочницах CodeSandbox/StackBlitz.

### Компонент — это функция
**Компонент** — обычная JavaScript-функция, которая **возвращает JSX** (расширенный HTML). Имя компонента — **с заглавной буквы** (`App`, `Header`, `Button`), а HTML-теги — строчные (`div`, `span`). Это важное различие: React по имени понимает, что `Header` — ваш компонент, а `div` — обычный тег.
```jsx
function Header() {
  return <h1>My App</h1>;
}

function App() {
  return (
    <div>
      <Header />
      <p>Контент</p>
    </div>
  );
}
```
Компонент может содержать другие компоненты — так строится **дерево** интерфейса. Компонент возвращает **один** корневой элемент (или несколько — через React Fragment `<>...</>`).

### Декларативность на пальцах
В «императивном» коде вы пишете **как**: `const el = document.querySelector("#out"); el.textContent = "Привет";` В React вы пишете **что**: `<p>{text}</p>` — и React сам поставит текст в нужное место DOM. Вы думаете о данных и структуре, а не о манипуляциях с DOM. Это и есть **компонентный подход**: интерфейс разбит на независимые функции-компоненты, каждая описывает свой кусок UI.

TIP: Мыслите **состоянием → UI**. Спросите себя: «Какие данные у меня есть и как UI должен выглядеть при каждом их значении?» — а не «Какие кнопки я нажму и какой DOM я поменяю». Эта смена мышления — самое главное, что даёт React.

## Пример
Полное `App.jsx` (работает в раннере и в Vite):
```jsx
function Title() {
  return <h1>Моё первое React-приложение</h1>;
}

function Greeting({ name }) {
  return <p>Привет, {name}!</p>;
}

function App() {
  const users = ["Анна", "Борис", "Чарли"];
  return (
    <div>
      <Title />
      {users.map((u) => (
        <Greeting key={u} name={u} />
      ))}
    </div>
  );
}
```
Разбор: `Title` и `Greeting` — независимые компоненты. `App` — «корневой» компонент, который **собирает** дерево из других. `Greeting` принимает имя через **пропс** `name` и подставляет его в текст через `{name}`. `users.map(...)` — рендерит по одному `Greeting` на каждый элемент массива (про списки и `key` — урок 8). Всё это React отрисует в DOM **сам** — ни одного `document.querySelector` в коде.

## Частые ошибки
WARN: Компонент назван со строчной буквы (`function app() { ... }`) и используется как `<app />` — React решит, что это **неизвестный HTML-тег**, а не ваш компонент, и ничего не отрендерит (или отрендерит пустой тег). Компоненты — **только** с заглавной буквы.
WARN: Забыли **импорт** хуков/функций или `createRoot` в локальном проекте — в раннере Syntax `createRoot` уже подключён, но в Vite/CodeSandbox нужно `import { createRoot } from "react-dom/client"` и `<div id="root"></div>` в index.html.
WARN: Компонент **ничего не возвращает** (нет `return <…>`) — React получит `undefined` и отрендерит пустоту без ошибки. Каждый компонент обязан вернуть JSX (или `null`).
WARN: Путаете **компонент** и **вызов**: `<Header />` — это элемент (описание), а `Header()` — прямой вызов функции (обойдёт React). Всегда используйте **теговую** форму `<Header />`.

## Практическое задание
1. В `App.jsx` создайте компонент `Title`, который возвращает `<h1>Мой трек в React</h1>`.
2. Создайте компонент `Info`, который принимает пропс `text` и возвращает `<p>{text}</p>`.
3. В компоненте `App` используйте `Title` и **два** компонента `Info` с разными текстами.
4. Добавьте массив `const skills = ["JSX", "Компоненты", "Props"]` и отрендерите для каждого элемента `<Info text={…} />` внутри `App`.
5. Бонус: оберните несколько корневых элементов в React Fragment `<>...</>` и убедитесь, что всё отрисовалось.
