# Урок 11. Подводные камни: бесконечные циклы, deps, stale closure

## Цель
После урока студент сможет: находить и **чинить** бесконечные циклы в `useEffect`; правильно заполнять массив зависимостей; понимать **stale closure** и почему **функциональная** форма `setState` от него спасает.

## Теория
### Бесконечный цикл: классика новичков
Самый частый «баг первого дня» в `useEffect`:
```jsx
const [list, setList] = useState([]);

useEffect(() => {
  fetch("/api").then((r) => r.json()).then(setList);
}, [list]); // ← Зависимость от list, а эффект её МЕНЯЕТ
```
Цикл: рендер → эффект (т.к. `list` «изменился») → `setList` → **новый** объект массива → `list` «изменился» → эффект **снова** → … **бесконечно**.

**Причина**: в `deps` стоит **значениe**, которое эффект **обновляет**, и при этом обновление **создаёт новое** значение (новый массив/объект), даже если содержимое **то же**.

**Как чинить**:
1. **Уберите** то, что **не нужно** в `deps` (здесь `list` не нужно — эффект **не зависит** от `list`, он **только** его заполняет): `deps = []`.
2. Если значение **нужно** в эффекте — **оставайтесь**, но **убедитесь**, что обновление **стабильно** (не создаёт новый объект каждый раз).

### Правило `deps`: «всё, что эффект читает»
React **не** знает, какие значения «важны» для эффекта — **вы** объявляете их в `deps`. Правило: **все** изменяемые значения из **области видимости** компонента, которые эффект **использует**, — **в массиве зависимостей**.
```jsx
useEffect(() => {
  console.log(count); // читает count
}, [count]); // count — в deps
```
Если забыли — эффект будет работать со **старым** значением (см. ниже). Если перестарались (положили **всё**) — эффект будет **слишком** часто.

### Stale closure (устаревшее замыкание)
**Замыкание** — функция «помнит» переменные из того рендера, в котором **создана**. Если эффект (или колбэк) **создан** при `count = 0`, но **вызывается** позже, он увидит **`count = 0`** (то, что было в момент создания), а не актуальное значение. Это **stale closure**.
```jsx
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1); // ← всегда читает count из ПЕРВОГО рендера (0!)
  }, 1000);
  return () => clearInterval(id);
}, []); // deps [] — колбэк создан один раз
```
**Решение** — **функциональная** форма `setState`, которая берёт **самое свежее** значение:
```jsx
setCount((prev) => prev + 1); // всегда актуально
```
Или добавить `count` в `deps` (тогда эффект будет **пересоздавать** интервал каждый тик — **хуже**). **Функциональная** форма — **правильный** ответ для «увеличить на 1».

### Стрелки и инлайн-функции в `deps`
Если в `deps` попадает **инлайн-функция** (`onClick={() => …}`), она **новая** каждый рендер → эффект будет **срабатывать каждый** раз. Обёрните такую функцию в `useCallback` (урок 12) или **вынесите** наружу.

TIP: Если **не уверены**, что положить в `deps`, — включите **ESLint-плагин** `react-hooks` (он в шаблоне Vite). Правило `exhaustive-deps` **предупреждает** о забытых и лишних зависимостях. Это **лучший** ваш друг.

## Пример
Четыре типичные «аварии» и их лечение:
```jsx
import { useState, useEffect } from "react";

// ❌ БЕСКОНЕЧНЫЙ ЦИКЛ
function Bad() {
  const [n, setN] = useState(0);
  useEffect(() => {
    setN(n + 1); // меняет n
  }, [n]); // и зависит от n → ЦИКЛ
  return <p>{n}</p>;
}

// ✅ ЛЕЧЕНИЕ: эффект не зависит от n → deps []
function Good() {
  const [n, setN] = useState(0);
  useEffect(() => {
    setN(1); // один раз
  }, []);
  return <p>{n}</p>;
}

// ❌ STALE CLOSURE
function Stale() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setCount(count + 1), 1000); // count всегда 0
    return () => clearInterval(id);
  }, []);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// ✅ ЛЕЧЕНИЕ: функциональная форма
function Fixed() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setCount((prev) => prev + 1), 1000); // prev — свежий
    return () => clearInterval(id);
  }, []);
  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}

export default function App() {
  return (
    <div>
      <Fixed />
    </div>
  );
}
```
Разбор: `Bad` зацикливается, `Good` — один раз. `Stale` «застревает» на `0`, `Fixed` считает **вверх**. Запомните паттерн: **зависимость, которую эффект меняет** → **цикл**; **закрытие над старым значением** → **функциональный** `setState`.

## Частые ошибки
WARN: **`deps = [state, setState]`** — `setState` **стабилен** (React гарантирует, что он **тот же** между рендерами), поэтому **не нужен** в `deps`. Ставьте только **значения**, которые **читаете**.
WARN: **Объект/массив прямо в `deps`**: `useEffect(…, [user])`, где `user` **новый** объект каждый рендер (создаётся инлайн) → эффект **каждый** раз. Ставьте **стабильные** поля (`user.id`) или мемоизируйте объект (`useMemo`).
WARN: **Две независимые задачи в одном `useEffect`** (запрос **и** таймер) с разными `deps` — они «стянуты» в один массив и будут перезапускаться **лишние** раз. Разделяйте на **несколько** `useEffect`.
WARN: **Добавили в `deps` всё подряд**, чтобы «закрыть» линтер, не думая — эффект стал **слишком** частым. Поймите **зачем** каждая зависимость; для сложных случаев — `useCallback`/`useMemo` (урок 12) или **переписывание** логики.

## Практическое задание
1. Воспроизведите **бесконечный цикл** (компонент `Bad` из Примера) — увидите в консоли, как React «уходит в закат». Затем **почините** (`deps = []`).
2. Воспроизведите **stale closure** (`Stale`): кнопка **не** увеличивает число. **Почините** функциональной формой.
3. Напишите `Greet({ name })`: `useEffect` логирует «Привет, {name}» **только** при смене `name` (`deps = [name]`).
4. Создайте `Timer({ interval })`: `setInterval` с `deps = [interval]` — при смене пропса таймер **пересоздаётся** (не забудьте cleanup).
5. Бонус: объясните **в комментарии**, почему `setCount` не нужно в `deps`, а `count` — **нужно**.
