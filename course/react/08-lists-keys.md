# Урок 8. Списки и ключи (key)

## Цель
После урока студент сможет: рендерить списки через `.map()`; понимать, зачем нужен `key` и почему **индекс** — плохой ключ; уметь добавлять/удалять элементы списка в состоянии.

## Теория
### Рендер списка: `.map()` → массив элементов
Чтобы отрисовать **много** одинаковых элементов по данным, прогоняем массив через `.map()` и возвращаем JSX. React **принимает массив** элементов (в отличие от одиночного элемента, массив **не** нужно оборачивать).
```jsx
const names = ["Анна", "Борис", "Чарли"];
return (
  <ul>
    {names.map((name) => (
      <li key={name}>{name}</li>
    ))}
  </ul>
);
```
`.map()` возвращает **массив** `<li>`, и React отрисует все. Это эквивалент цикла `for` в чистом JS, только декларативно.

### Зачем нужен `key`
**`key`** — это **уникальный идентификатор** элемента в списке. Он помогает React **сопоставить** элементы между рендерами: когда список меняется, React по `key` понимает, **какой** элемент остался, какой добавился, какой удался — и **минимально** обновляет DOM.

**Почему это важно**: без стабильного `key` React не сможет «узнать» элементы при перестановке/удалении — возможны **лишние перерисовки** и **баги с состоянием** (например, input в списке «переезжает» значение).

### Правильные и неправильные ключи
**Хороший ключ** — **стабильный** и **уникальный** для элемента:
- `key={user.id}` — **идеально**, если данные имеют `id`.
- `key={name}` — допустимо, если значения гарантированно уникальны и **не меняются**.

**Плохой ключ** — **индекс**:
```jsx
{items.map((item, i) => <li key={i}>{item.text}</li>)}
```
Индекс — **позиция**, а не **идентичность**. При **вставке/удалении в начале** списка индексы **сдвигаются**, и React ошибочно сопоставит элементы: состояние (например, введённый текст в input) «перепрыгнет» на другой элемент.

**Правило**: используйте `id` из данных. Если `id` нет, а элементы **статичны и не переупорядочиваются** — индекс допустим. Если нет `id` и список **динамический** — генерируйте уникальный ключ (например, `crypto.randomUUID()` при создании).

### Добавление и удаление из списка
Список — это **состояние-массив**. Операции — всегда **копия** (иммутабельность, урок 6):
```jsx
setItems([...items, newItem]);            // добавить
setItems(items.filter((x) => x.id !== id)); // удалить
setItems(items.map((x) => x.id === id ? { ...x, done: true } : x)); // обновить
```

TIP: Если у данных **нет** `id`, **создайте** его при генерации списка (например, `id: Date.now()` или `crypto.randomUUID()`). Стабильный ключ экономит React'у работу и спасает от багов со состоянием.

## Пример
Мини-список задач с ключами:
```jsx
import { useState } from "react";

function App() {
  const [tasks, setTasks] = useState([
    { id: 1, text: "Выучить key", done: true },
    { id: 2, text: "Не использовать индекс", done: false },
  ]);

  const addTask = (text) =>
    setTasks((prev) => [...prev, { id: crypto.randomUUID(), text, done: false }]);

  const toggle = (id) =>
    setTasks((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));

  const remove = (id) => setTasks((prev) => prev.filter((t) => t.id !== id));

  return (
    <ul>
      {tasks.map((t) => (
        <li key={t.id}>
          <label>
            <input type="checkbox" checked={t.done} onChange={() => toggle(t.id)} />{" "}
            {t.text}
          </label>
          <button onClick={() => remove(t.id)}>×</button>
        </li>
      ))}
    </ul>
  );
}
export default App;
```
Разбор: `tasks` — массив объектов с **стабильным** `id`. Каждая операция — **копия** через `map`/`filter`/спрэд. `key={t.id}` — React корректно сопоставляет строки при любом изменении. `crypto.randomUUID()` даёт уникальный `id` новым задачам.

## Частые ошибки
WARN: **`key={индекс}`** в **динамическом** списке — при удалении/вставке элементы «сдвигаются», состояние «переезжает». Используйте `id` из данных.
WARN: **Забыли `key`** — React рендерит список, но в консоли **предупреждение** «Each child in a list should have a unique key», и при изменениях возможны **лишние перерисовки**. Всегда ставьте `key` на **корневой** элемент внутри `.map()`.
WARN: **Дублирующиеся `key`** (одинаковый `id`) — React не знает, какой элемент какой; поведение непредсказуемое. `key` должен быть **уникальным** в рамках списка.
WARN: Ставите `key` **на `<ul>`** (родитель), а не на `<li>` (элемент списка) — ключ нужен на **том** элементе, который **повторяется** (результат `.map()`).
