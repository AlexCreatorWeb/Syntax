# Урок 15. useRef: DOM и неразмечные значения

## Цель
После урока студент сможет: понимать, **чем** `useRef` отличается от `useState`; использовать `ref` для **доступа** к DOM-элементу; хранить в `ref` **значения, не вызывающие** перерендер (счётчик, предыдущее значение, таймер).

## Теория
### `useRef` — «коробочка», которую React **не** обновляет
**`useRef(initial)`** возвращает **объект** `{ current: initial }`. Главное свойство: **изменение** `ref.current` **не** вызывает **перерендер** (в отличие от `useState`). `ref.current` **живёт** между рендерами (как состояние), но **не** «перерисовывает» компонент.
```jsx
const [count, setCount] = useState(0); // смена → ПЕРЕРЕНДЕР
const box = useRef(0);                  // box.current = 5 → НЕ перерендер
```
Это **ключевое** отличие: `useState` — **данные для UI** (React **следит** и **перерисовывает**); `useRef` — **данные «в обход»** (React **не** следит, **не** перерисовывает).

### Случай 1: доступ к DOM-элементу
`ref` можно **повесить** на элемент (`<input ref={inputRef} />`) — тогда `inputRef.current` станет **самого** DOM-узла. Это способ **императивно** управлять элементом (фокус, scroll, размер), когда **декларативный** путь неудобен.
```jsx
const inputRef = useRef(null);
function focusIt() {
  inputRef.current.focus(); // прямой доступ к DOM
}
return (
  <>
    <input ref={inputRef} />
    <button onClick={focusIt}>Сфокусировать</button>
  </>
);
```
**Когда**: автофокус, `scrollIntoView`, вызов **не-React** методов (например, у `<video>`), чтение **размеров** (`offsetWidth`). Для **большинства** задач (значение input) лучше **контролируемый** компонент (`useState`), а `ref` — для **императивных** операций.

### Случай 2: хранить значение **без** перерендера
`ref` — идеальное место для **«служебных»** данных, которые **нужны** между рендерами, но **не** должны **перерисовывать** UI:
- **Предыдущее** значение (сравнить «что было»): `const prev = useRef(value); prev.current = value;`
- **Счётчик** «сколько раз был рендер» (для **логи**, не для UI).
- **ID таймера** (`setTimeout`) — чтобы **очистить** его позже.
- **Первый** рендер: `const first = useRef(true); if (first.current) { …; first.current = false; }`

**Важно**: если значение **должно** **отображаться** — это **`useState`**, а **не** `ref` (изменение `ref` UI **не** обновит!).

### Как это работает «под капотом»
`useRef` создаёт **один** объект при **первом** рендере и **возвращает** **тот же** объект каждый раз (ссылка **стабильна**). Вы **мутируете** `.current` — React **не знает** (и **не** пытается) перерисовать. Это **порядок**: `ref` — **не** «состояние», а **хранилище**.

TIP: **Правило выбора**: «Нужно ли **UI** отразить изменение?» → **Да** = `useState`, **Нет** (служебное, императивное) = `useRef`. Не храните в `ref` то, что **видит** пользователь, и не обновляйте `useState` ради «служебного» счётчика.

## Пример
Автофокус + «сколько раз нажат Enter» (счётчик без перерендера) + предыдущее значение:
```jsx
import { useState, useRef, useEffect } from "react";

function App() {
  const inputRef = useRef(null);
  const [text, setText] = useState("");
  const enterCount = useRef(0); // служебный счётчик (без перерендера)
  const prevText = useRef("");  // «что было»

  // Каждые 2 рендера — пишем в консоль (ref не вызывает перерендер)
  const renders = useRef(0);
  renders.current += 1;
  if (renders.current % 2 === 0) console.log("рендер №", renders.current);

  const onKeyDown = (e) => {
    if (e.key === "Enter") {
      enterCount.current += 1; // не перерендериваем
      console.log("Enter нажат", enterCount.current, "раз(а)");
    }
  };

  const focus = () => inputRef.current.focus();

  return (
    <div>
      <input
        ref={inputRef}
        value={text}
        onChange={(e) => setText(e.target.value)}
        onKeyDown={onKeyDown}
        placeholder="Печатайте…"
      />
      <button onClick={focus}>Сфокусировать</button>
      <p>Введено: {text}</p>
      <p>Было: {prevText.current}</p>
      {/* Обновляем «было» ПОСЛЕ рендера, чтобы не «опережать» текущее */}
      <SyncPrev text={text} prevText={prevText} />
    </div>
  );
}

// Маленький хелпер: в useEffect (после рендера) пишем текущее в ref
function SyncPrev({ text, prevText }) {
  useEffect(() => {
    prevText.current = text;
  }, [text, prevText]);
  return null;
}
export default App;
```
Разбор: `inputRef` — **доступ к DOM** (фокус). `enterCount` — **счётчик** Enter **без** перерендера (только `console`). `renders` — **лог** рендеров. `prevText` — **предыдущее** значение (обновляется в `useEffect`, чтобы не «опережать» текущий рендер). Обратите внимание: **UI** обновляется только за счёт `text` (`useState`); всё «служебное» — в `ref`.

## Частые ошибки
WARN: **Храните «видимое» значение в `ref`** и ждёте, что UI **обновится** — **нет**: изменение `ref.current` **не** перерендеривает. Для **UI** — **`useState`**.
WARN: **Пытаетесь «прочитать» `ref` при рендере** для **логики UI** (например, `if (ref.current > 5)`), чтобы **показать** что-то — **нестабильно** (значение **не** триггерит рендер). Если **показываете** — это **состояние**.
WARN: **Забраковали `ref` как «ещё одно состояние»** и держите в нём **данные, которые должны** синхронизироваться/отображаться — **рассинхрон** с UI. `ref` — **служебное**, не «данные приложения».
WARN: **Путаете `ref` и «ссылку на компонент»**: `ref` на **функциональный** компонент **не** работает (без `forwardRef`). `ref` вешайте на **DOM-узлы** (или на компоненты с `forwardRef`/`ref`-пропсом в React 19).

## Практическое задание
1. Создайте `FocusInput`: `useRef` на `<input>`, кнопка «Сфокусировать» вызывает `inputRef.current.focus()`.
2. Добавьте **счётчик** «сколько раз нажали Enter» в `useRef` (лог в `console`, **без** перерендера).
3. Создайте `PrevValue`: `useState` `value`, `useRef` `prev`; в `useEffect` (deps `[value]`) пишите текущее в `prev.current`; показывайте «Было: {prev.current}».
4. В `App` объедините `FocusInput` и `PrevValue`.
5. Бонус: добавьте `useRef` для **счётчика рендеров** и логируйте каждый **второй** рендер в `console`.
