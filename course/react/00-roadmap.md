# Курс «React с нуля» (React 18+) — дорожная карта (18 уроков)

Целевая аудитория: студент, прошедший курсы HTML, CSS и JavaScript (знает DOM-базу, функции, замыкания, массивы/объекты, async/await, fetch). Результат: студент пишет современный React (функциональные компоненты + хуки, React 18) — от первого `createRoot` до CRUD-приложения с API. Без классовых компонентов, без legacy-API (life-cycle-методов, `ReactDOM.render`).

Источники: react.dev (официальная документация, «Thinking in React», «Escaping React», hooks reference), create-react-app → Vite (стандартная сборка), лучшие практики (иммутабельность, правила хуков, паттерны состояния).

## Логическая цепочка

1. **Что такое React** (01): декларативность «UI = f(состояние)», createRoot, первый рендер. Без этого нет контекста для всего остального.
2. **JSX** (02): синтаксис, выражения, атрибуты — язык, на котором мы описываем UI.
3. **Компоненты** (03): разбивка UI на части, композиция — основа архитектурного мышления.
4. **Пропсы** (04): данные «вниз» — компоненты становятся параметризованными.
5. **Условия** (05): UI реагирует на данные — ветвление.
6. **useState** (06): данные «изнутри» — интерактивность.
7. **События** (07): пользователь → состояние.
8. **Списки + key** (08): рендер коллекций и главная ошибка новичков.
9. **useEffect** (09): всё, что «извне» (таймеры, подписки, сеть) — и cleanup.
10. **useEffect + данные** (10): классический паттерн загрузки.
11. **Ловушки эффектов** (11): бесконечные циклы, deps, stale closure — то, что ломает 90% новичков.
12. **useMemo/useCallback** (12): оптимизация, когда она нужна.
13. **Правила хуков** (13): почему хуки — только на верхнем уровне.
14. **useFetch** (14): переиспользуемая асинхронная логика — переход от «уровня компонента» к «уровню хука».
15. **useRef** (15): что храним НЕ в состоянии.
16. **Context** (16): состояние «вглубь» без prop drilling.
17. **Асинхронные паттерны** (17): debounce, abort, гонки запросов — взрослый React.
18. **Финальный проект** (18): всё вместе — CRUD-приложение.

## Контракт урока (фиксированный, QC в сидере)

5 разделов в строгом порядке:
1. `## Цель` — «После урока студент сможет: …»
2. `## Теория` — простые объяснения, `###`-подзаголовки
3. `## Пример` — рабочий код в ```jsx-блоке (полный App.jsx — воспроизводим в Vite/CodeSandbox и в раннере платформы)
4. `## Частые ошибки` — минимум 1 `WARN:` (по одной на ловушку)
5. `## Практическое задание` — нумерованный список с TODO

Правила контента:
- минимум 1 `TIP:` и 1 `WARN:`-callout; `NOTE:` — для «как это работает в платформе Syntax»
- без таблиц, без markdown-ссылок `[t](u)` (ссылки — прозой)
- объём content 4000–7000 зн.
- **кодовое задание `code/NN.jsx` = скелет ЗАДАНИЯ** (НЕ решение): исполняемый `App.jsx` со `// TODO`-комментариями; компонент называется **App** (раннер платформы маунтит его в превью); `import … from "react"` — современный синтаксис, работает и в Vite/CodeSandbox
- React 18: `createRoot`, функциональные компоненты, хуки; классовые компоненты НЕ используем

## Механика платформы

- Файл задания React-трека = `App.jsx` (taskFileMap в MainContent).
- **React-раннер** (CodeEditor): `App.jsx` → Babel standalone (JSX, automatic runtime) → blob-module → `createRoot` в превью-iframe; React 18.3.1 с esm.sh (import map), Babel с unpkg. Консоль перехватывается, ошибки с номерами строк файла.
- Материал урока (markdown-lite): `##`/`###`, **жирный**, *курсив*, `код`, ```jsx-блоки (Copy), TIP:/NOTE:/WARN:-callout'ы.
- Сидер `seed-react-course.mjs`: IDEMPOTENT (удаляет ВСЕ tech='react', вставляет 18, id `40000000-…00NN`), встроенный QC (5 разделов, TIP/WARN, ```jsx, объём, ссылки) — падает до БД при нарушении; `DRY=1 node …` — только проверка.
