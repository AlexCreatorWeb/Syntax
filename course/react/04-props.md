# Урок 4. Пропсы (Props): передача данных вниз

## Цель
После урока студент сможет: передавать данные от родителя к ребёнку через пропсы; принимать пропсы с деструктуризацией; задавать значения по умолчанию и передавать функции как пропсы.

## Теория
### Пропсы — аргументы компонента
**Пропсы** (properties) — данные, которые родитель передаёт дочернему компоненту. Это **единственный** способ отправить данные «вниз» по дереву. Пропсы работают как аргументы функции: компонент — это функция, пропсы — её параметры.
```jsx
function Greeting({ name, role = "студент" }) {
  return <p>{name}, {role}</p>;
}

export default function App() {
  return (
    <div>
      <Greeting name="Анна" role="разработчица" />
      <Greeting name="Борис" />
    </div>
  );
}
```
Второй `<Greeting>` не получил `role` — сработало **значение по умолчанию** `"студент"`. Пропсы передаются как атрибуты тега, как в HTML.

### Как компонент получает пропсы
Компонент получает **один** объект-пропс. Два привычных стиля доступа:
```jsx
// Стиль 1: деструктуризация в параметре (рекомендуется)
function Card({ title, text }) {
  return (
    <div>
      <h3>{title}</h3>
      <p>{text}</p>
    </div>
  );
}

// Стиль 2: весь объект props
function Card(props) {
  return (
    <div>
      <h3>{props.title}</h3>
      <p>{props.text}</p>
    </div>
  );
}
```
Деструктуризация чище и компактнее — используйте её по умолчанию.

### Типы значений пропсов
Пропсы могут быть **любым** JavaScript-значением:
- **Примитивы**: строки, числа, булевы — `<Item count={5} active={true} />`
- **Объекты и массивы**: `<UserCard user={user} />`, где `user = { name, avatar, roles: [] }`
- **JSX**: `<Layout header={<Header />} />`
- **Функции**: `<Button onClick={handleClick} />` — ребёнок «звонит» родителя, когда что-то происходит (события — урок 7).

**Важно**: атрибут в кавычках — это **строка**, без кавычек — **выражение**: `<Item count="5" />` даст строку `"5"`, а `<Item count={5} />` — число `5`.

### Односторонняя связь: props — только «вниз»
Данные по пропсам текут **только от родителя к ребёнку**. Ребёнок не может «перезаписать» пропс родителя — пропсы **read-only** на входе. Если ребёнку нужно что-то «сообщить» родителю, родитель передаёт ему **функцию** (обработчик), и ребёнок вызывает её. Это называется **подъём состояния** (state lifting) — подробно в уроках 7–8.

TIP: Имена пропсов — **camelCase** и в именительном падеже: `title`, `userName`, `onSubmit`, `isVisible`. Это делает JSX читаемым как разметка: `<Avatar src={…} alt={…} />`.

## Пример
Проф-«сборка» из компонентов:
```jsx
function Badge({ color = "gray", children }) {
  return (
    <span style={{ background: color, color: "white", padding: "2px 8px", borderRadius: 12 }}>
      {children}
    </span>
  );
}

function UserRow({ user, onSelect }) {
  return (
    <li style={{ display: "flex", gap: 8, alignItems: "center" }}>
      <strong>{user.name}</strong>
      <Badge color={user.active ? "green" : "gray"}>{user.active ? "активен" : "офлайн"}</Badge>
      <button onClick={() => onSelect(user.id)}>Выбрать</button>
    </li>
  );
}

export default function App() {
  const users = [
    { id: 1, name: "Анна", active: true },
    { id: 2, name: "Борис", active: false },
  ];
  return (
    <ul>
      {users.map((u) => (
        <UserRow key={u.id} user={u} onSelect={(id) => console.log("выбран", id)} />
      ))}
    </ul>
  );
}
```
Разбор: `Badge` принимает `children` и опциональный `color`. `UserRow` получает объект `user` и **функцию** `onSelect`; внутри он вызывает её с `user.id` — так «вниз» идут данные, а «вверх» — событие. `App` владеет `users` и логикой выбора.

## Частые ошибки
WARN: **Прописали пропс в кавычках**, когда нужно выражение: `<Card count="3" />` — это строка `"3"`, а не число `3`. Сравнивать `"3" === 3` → `false`. Выражения — **в фигурных скобках**: `count={3}`.
WARN: Ребёнок **мутирует пропс** (`props.user.name = "новый"`) — пропсы read-only, мутация не вызывает перерендер и ломает «односторонний поток». Меняйте данные там, где они **хранятся** (в родителе).
WARN: **Путаете атрибут и пропс компонента**: `<MyButton className="x" myProp="1" />` — для HTML-тегов `className`, для вашего компонента имя пропса как вы его **приняли** (camelCase, без `className`, если не передаёте её дальше).
WARN: Передаёте **новый объект/массив/функцию** каждый рендер инлайн (`<Row data={{…}} onClick={() => …} />`) — это нормально для простых случаев, но может вызывать **лишние перерисовки** у детей (оптимизация через `useCallback`/`useMemo` — урок 12).

## Практическое задание
1. Создайте компонент `Price({ value, currency = "₽" })`, возвращающий `<strong>{value.toLocaleString("ru-RU")} {currency}</strong>`.
2. Создайте `ProductCard({ name, price, inStock })`, показывающую название, `<Price value={price} />` и статус (`inStock ? "В наличии" : "Нет"`).
3. В `App` храните массив из трёх товаров и отрендерите `ProductCard` через `.map()` (не забудьте `key`).
4. Добавьте пропс `onOrder` (функция) к `ProductCard` и кнопку «Заказать», которая её вызывает с `name` товара.
5. Бонус: передайте в `App` `onOrder = (name) => console.log("заказ:", name)` и проверьте консоль после клика.
