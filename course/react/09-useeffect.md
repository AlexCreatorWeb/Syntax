# Урок 9. useEffect: побочные эффекты и cleanup

## Цель
После урока студент сможет: объяснять, что такое «побочный эффект» и зачем нужен `useEffect`; писать эффект с массивом зависимостей; понимать **cleanup**-функцию и когда она вызывается.

## Теория
### Что такое «побочный эффект»
**Побочный эффект** — это всё, что происходит **вне** процесса рендера и **касается мира за пределами** компонента: сетевые запросы, таймеры (`setInterval`), подписки (события окна, вебсокет), ручная работа с DOM, запись в `localStorage`. Рендер должен быть **чистым** (принял данные → вернул JSX), а всё «внешнее» выносится в **`useEffect`**.

### Синтаксис `useEffect(fn, deps)`
```jsx
import { useEffect } from "react";

function Timer() {
  useEffect(() => {
    console.log("эффект выполнен");
  }, []); // deps — массив зависимостей
  return <p>Таймер</p>;
}
```
- **Первый аргумент** — функция, которую React вызовет **после** рендера.
- **Второй аргумент** — **массив зависимостей** (`deps`):
  - **`[]` (пустой)** — эффект выполнится **один раз** после **первого** рендера (и при «монтировании»).
  - **`[a, b]`** — эффект выполнится при **изменении** `a` или `b` (React сравнивает **по `Object.is`**).
  - **без массива** — эффект будет выполняться **после каждого** рендера (редко нужно).

### Cleanup-функция
Если эффект **устанавливает** что-то (таймер, подписку, запрос), его нужно **убрать** — иначе «утечка». React вызывает **возвращённую** из эффекта функцию **перед** следующим выполнением эффекта и **при размонтировании** компонента:
```jsx
useEffect(() => {
  const id = setInterval(() => console.log("тик"), 1000);
  return () => clearInterval(id); // cleanup
}, []);
```
Паттерн: **установить → вернуть «разустановить»**. Это гарантирует, что старых таймеров/подписок не остаётся.

### «Когда» выполняется эффект
Порядок: **рендер** → браузер **рисует** → **выполняется эффект**. Поэтому эффект — **не** момент создания данных (для этого есть `useState(инициал)`), а момент «я уже на странице, можно взаимодействовать с миром». В **development** (StrictMode) React **намеренно** монтирует компонент **дважды**, чтобы вы ловили «утечки» — эффект и cleanup сработают попарно. Это **норма**, а не баг.

TIP: Если вам **нужно** выполнить что-то **при каждом** изменении определённых данных — это **дедупликация** (запрос, логирование). Если же вы просто **вычисляете** значение из пропсов/состояния — **не** используйте `useEffect`, а считайте **прямо в рендере** (это быстрее и проще). «Если это можно посчитать при рендере — считайте при рендере».

## Пример
Часы + подписка на размер окна:
```jsx
import { useState, useEffect } from "react";

function App() {
  const [now, setNow] = useState(new Date());
  const [size, setSize] = useState({ w: window.innerWidth, h: window.innerHeight });

  // 1) тикающие часы: устанавливаем интервал, возвращаем cleanup
  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);
  }, []);

  // 2) подписка на resize: установка + отписка
  useEffect(() => {
    const onResize = () => setSize({ w: window.innerWidth, h: window.innerHeight });
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);

  return (
    <div>
      <h2>{now.toLocaleTimeString("ru-RU")}</h2>
      <p>
        Окно: {size.w} × {size.h}
      </p>
    </div>
  );
}
export default App;
```
Разбор: два независимых эффекта, каждый с **cleanup**. Часы обновляют состояние `now` раз в секунду (React перерендеривает). Подписка на `resize` обновляет `size`. Оба эффекта — **`[]`**, потому что устанавливаются **один раз**. Обратите внимание: **обновление состояния** (setNow/setSize) **не** перезапускает эффекты, т.к. их `deps` пустые.

## Частые ошибки
WARN: **Забыли cleanup** — таймер/подписка продолжают работать после размонтирования: «утечка», двойные логи, попытки обновить **состояние** размонтированного компонента (предупреждение в консоли). Если **установили** — **верните** «разустановку».
WARN: **Пустой `deps` там, где нужны зависимости**: эффект читает `props.count`, но `deps = []` — эффект не перезапустится, когда `count` изменится. Добавляйте **все** изменяемые значения, которые эффект **использует**, в `deps`.
WARN: **Эффект без `deps`** (выполняется после **каждого** рендера) из-за лени — часто приводит к **бесконечному циклу**, если эффект **меняет** состояние, которым сам же зависит (подробно — урок 11).
WARN: Выносите **вычисления** (filter/map/форматирование) в `useEffect` + `setState`, хотя их можно **считать при рендере**. Это лишний рендер и лишняя сложность. Эффект — для **взаимодействия с внешним миром**, а не для вычислений.

## Практическое задание
1. Напишите `Clock` — `useState(new Date())` + `useEffect` с `setInterval` и **cleanup** (`clearInterval`), `deps = []`.
2. Напишите `WindowSize` — подписка на `resize` в `useEffect` с cleanup (`removeEventListener`).
3. Сделайте компонент `CopyLog({ message })`: в `useEffect` (с `deps = [message]`) пишит `console.log("копия:", message)` — эффект перезапускается **только** при смене `message`.
4. В `App` объедините `Clock` и `WindowSize`.
5. Бонус: добавьте `useEffect`, который при **размонтировании** (через кнопку «Скрыть»/показ) логирует «компонент скрыт» (используйте cleanup).
