# Урок 18. Финальный проект: приложение «Заметки» (CRUD + API)

## Цель
Собрать **целое** приложение, объединяя **весь** курс: компоненты и композиция, пропсы, `useState`, события, **контролируемые** формы, **списки** с `key`, **`useEffect`** + **API**, **кастомный хук** `useFetch`, **дебаунс**, **условный рендер** и **иммутабельные** обновления. Результат — **работающий** CRUD.

## Теория
### Что такое CRUD
**CRUD** — **Create, Read, Update, Delete**: четыре базовые **операции** с данными. «Заметки» — классический CRUD: **добавить** заметку, **просмотреть** список, **изменить** (переименовать/отметить), **удалить**.

### Архитектура проекта (разбивка на компоненты)
```
App (состояние: notes, query, idEditing)
├── NoteForm        — контролируемая форма создания
├── SearchBar       — ввод + useDebounce
├── NoteList        — рендер списка (map + key)
│   └── NoteItem    — одна заметка (редактирование, удаление)
└── useNotes        — кастомный хук: состояние + CRUD + (опц.) API
```
**Состояние** (`notes`) — **один** источник правды в `App` (или в **хуке** `useNotes`). **Дочерние** компоненты **не** хранят его — **принимают** **пропсами** и **звонят** **функции** (`onAdd`, `onDelete`, `onUpdate`). Это **подъём состояния** (state lifting): **общее** — **выше**, **локальное** (ввод в поле) — **внутри** компонента.

### Паттерн «локальный ввод → общее состояние»
**Поле** в `NoteForm` — **локальное** `useState` (мгновенный отклик, **не** перерисовывает **всё**). При **отправке** формы значение **поднимается** в `App` через **`onAdd(text)`**. Так мы **разделяем** «частое» (печать) и «важное» (добавление).

### Опционально: синхронизация с API
Если **нужно** **сохранять** заметки «на сервере» — **кастомный хук** `useFetch` + **методы** `fetch`/`POST`. В **этом** проекте основной сценарий — **локальные** `notes` (+ **бонус** `localStorage` через `useLocalStorage` из урока 13), а **API** — для **чтения** примеров.

### Чек-лист «всё из курса»
- **Компоненты/композиция** (ур. 3) — разбивка на `NoteForm`, `NoteList`, `NoteItem`.
- **Пропсы** (ур. 4) — `notes`, `onAdd`, `onDelete`, `onUpdate`.
- **Условия** (ур. 5) — `loading`/`error`/пусто.
- **`useState`** (ур. 6) — `notes`, `query`, `editingId`.
- **События/формы** (ур. 7) — `onSubmit` + `preventDefault`, **контролируемые** input.
- **Списки/`key`** (ур. 8) — `.map()` + **стабильный** `id`.
- **`useEffect`** (ур. 9–11) — (опц.) **загрузка**, **cleanup**.
- **`useMemo`/`useCallback`** (ур. 12) — **фильтр**, **стабильные** обработчики.
- **Кастомные хуки** (ур. 13–14) — **`useNotes`**, (опц.) **`useFetch`**.
- **`useRef`** (ур. 15) — **автофокус** в форме.
- **Debounce** (ур. 17) — **живой** поиск.

TIP: Не пытайтесь **написать всё** в `App`. **Сначала** разбейте на **компоненты** (черновик на бумаге), **потом** **состояние** (что **общее**, что **локальное**), **затем** **логика**. **Архитектура** — **до** кода.

## Пример
Структура **готового** приложения (скелет — в задании, здесь **каркас**):
```jsx
import { useState, useMemo, useCallback, useRef } from "react";

function useNotes() {
  const [notes, setNotes] = useState([]);
  const add = useCallback(
    (text) => setNotes((p) => [{ id: crypto.randomUUID(), text, done: false }, ...p]),
    []
  );
  const remove = useCallback((id) => setNotes((p) => p.filter((n) => n.id !== id)), []);
  const toggle = useCallback(
    (id) => setNotes((p) => p.map((n) => (n.id === id ? { ...n, done: !n.done } : n))),
    []
  );
  return { notes, add, remove, toggle };
}

function App() {
  const { notes, add, remove, toggle } = useNotes();
  const [query, setQuery] = useState("");
  const visible = useMemo(
    () => notes.filter((n) => n.text.toLowerCase().includes(query.toLowerCase())),
    [notes, query]
  );
  return (
    <div>
      <h1>Заметки</h1>
      <NoteForm onAdd={add} />
      <SearchBar value={query} onChange={setQuery} />
      <NoteList notes={visible} onRemove={remove} onToggle={toggle} />
    </div>
  );
}
// NoteForm, SearchBar, NoteList, NoteItem — по одному заботу (ур. 3)
```
Разбор: `useNotes` **собирает** состояние **и** CRUD-операции (**кастомный** хук, **ур. 13**). `visible` — **производное** через `useMemo` (**ур. 12**). `add/remove/toggle` — **`useCallback`** (стабильные **пропсы**). **Компоненты** — **тонкие**: **принимают** данные, **звонят** функции.

## Частые ошибки
WARN: **Всё в одном `App`** (данные + форма + список + поиск) — **нечитабельно**, **не** переиспользуется. **Разбейте** на компоненты **по** заботам.
WARN: **Храните `notes` в каждом `NoteItem`** (каждая заметка «думает» о себе) — **рассинхрон** с остальным списком. **Общий** массив — **один** источник (в `App`/хуке).
WARN: **`key={индекс}`** в списке заметок — при **удалении** **первой** заметки **индексы** **сдвигаются**, **редактирование** «прыгает». **`key={id}`**.
WARN: **Синхронизируете «производное» (`visible`)** в `useState` + `useEffect` — **лишние** рендеры. **Считайте** `visible` **`useMemo`** (или прямо в рендере).

## Практическое задание
Соберите **приложение «Заметки»** по **чек-листу**:
1. `useNotes()` — `useState([])` + `add`/`remove`/`toggle` через `useCallback` (иммутабельно).
2. `NoteForm` — **контролируемый** input, `onSubmit` + `preventDefault`, **автофокус** через `useRef`, **очистка** поля после добавления.
3. `SearchBar` — input + **`useDebounce`** (400 мс), передаёт **debounced** значение вверх.
4. `NoteList` + `NoteItem` — `.map()` с `key={id}`, **checkbox** (toggle), **кнопка** «×» (remove), **условный** стиль для `done`.
5. В `App` — `visible` через `useMemo`, **условный** рендер «Пусто» / «Найдено N».
6. Бонус: **`useLocalStorage`** (ур. 13) — заметки **переживают** перезагрузку; или **`useFetch`** для **чтения** стартовых заметок с API.
