# Урок 16. Context: глобальное состояние без prop drilling

## Цель
После урока студент сможет: объяснить проблему **prop drilling**; создать **контекст** (`createContext`), **Provider** и читать его через `useContext`; понять, **когда** Context уместен, а когда — **избыток**.

## Теория
### Проблема: «спуск пропсов» (prop drilling)
Когда **глубоко** вложенный компоненту нужно **общее** значение (тема, текущий пользователь, язык), приходится **прокидывать** его пропсами **сквозь** все промежуточные компоненты, которые его **не используют**:
```jsx
<App user={user}>
  <Layout user={user}>
    <Sidebar user={user}>
      <DeepChild user={user} />   // «нужен только» здесь
    </Sidebar>
  </Layout>
</App>
```
Каждый «промежуточный» компонент **принимает** и **передаёт** `user`, хотя **не** пользуется. Это **prop drilling** — **шум**, который усложняет **каждый** уровень.

### Context — «общий доступ» для дерева
**Context** — способ дать **группе** вложенных компонентов **одни** данные **без** прокидывания пропсов. Вы создаёте **контекст**, **оборачиваете** часть дерева в **`<Provider>`** (задав **значение**), и **любой** компонент внутри **читает** его через **`useContext`**.
```jsx
// 1) Создаём контекст (со значением по умолчанию)
const ThemeContext = createContext("light");

// 2) Провайдер задаёт значение для всего, что ВНУТРИ
<ThemeContext.Provider value="dark">
  <App />
</ThemeContext.Provider>

// 3) Любая вложенность читает — без пропсов
function DeepChild() {
  const theme = useContext(ThemeContext); // "dark"
  return <p style={{ color: theme === "dark" ? "#fff" : "#000" }}>Тема: {theme}</p>;
}
```
**Никаких** `user={user}` по цепочке — значение «лежит» в **контексте**, и `DeepChild` его **достаёт** напрямую.

### Как устроено: `createContext` → `Provider` → `useContext`
- **`createContext(default)`** — создаёт **объект** контекста (с **дефолтным** значением на случай, если **нет** провайдера выше).
- **`<Context.Provider value={…}>`** — **устанавливает** значение для **десцендентов**.
- **`useContext(Context)`** — **возвращает** текущее значение контекста **на ближайшем** провайдере выше.
Если **нужно** и **значение**, и **функция** (например, «тема + сменить тему»), **объектом**: `value={{ theme, toggle }}`.

### Когда Context **нужен**, а когда **нет**
- **Нужен**: **редко** меняющиеся **глобальные** данные (тема, язык, авторизация, «текущий» объект) для **многих** уровней вложенности.
- **Не нужен**: если данные нужны **только** паре компонентов — **проще** прокинуть **пропсом**. Если значение **меняется часто** и **перерисовывает** большую часть дерева — Context может **замедлить** (все `useContext` перерисуются). Тогда рассмотрите **управление состоянием** выше (в общем родителе) или **библиотеку** состояний.

TIP: Context — **не** «хранилище на всё». Это **точечный** инструмент против **prop drilling** для **общих**, **редко** меняющихся данных. Не «выносите» в Context **каждое** состояние — это **размывает** архитектуру.

## Пример
Переключатель темы через Context:
```jsx
import { useState, createContext, useContext } from "react";

const ThemeContext = createContext("light");

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");
  const toggle = () => setTheme((t) => (t === "light" ? "dark" : "light"));
  return (
    <ThemeContext.Provider value={{ theme, toggle }}>
      {children}
    </ThemeContext.Provider>
  );
}

function useTheme() {
  return useContext(ThemeContext);
}

function Card({ title }) {
  const { theme } = useTheme();
  return (
    <div style={{ background: theme === "dark" ? "#222" : "#fff", color: theme === "dark" ? "#fff" : "#000", padding: 12, borderRadius: 8 }}>
      <h3>{title}</h3>
      <p>Тема без единого пропса.</p>
    </div>
  );
}

function Toggle() {
  const { theme, toggle } = useTheme();
  return <button onClick={toggle}>Тема: {theme}</button>;
}

export default function App() {
  return (
    <ThemeProvider>
      <Toggle />
      <Card title="Одна" />
      <Card title="Две" />
    </ThemeProvider>
  );
}
```
Разбор: `ThemeProvider` хранит **тему** и **функцию** переключения, отдаёт их **объектом** через **Provider**. `Card` и `Toggle` **не** получают `theme` **пропсом** — **запрашивают** через `useTheme`. Добавьте **девятый** уровень вложенности — **никаких** новых пропсов.

## Частые ошибки
WARN: **Context для «частого» состояния** (например, `cursor`/`input` на каждый символ) — **каждое** изменение **перерисовывает** всех `useContext`. Для **частых** локальных данных — **`useState`** в **ближайшем** родителе.
WARN: **Забраковали `default value`** в `createContext` — если компонент **вне** провайдера, `useContext` вернёт **`undefined`** (или ваш дефолт), и будет **падать** при обращении к свойствам. Всегда задавайте **разумный** дефолт.
WARN: **Один «гигантский» Context** на **всё** приложение (тема + юзер + корзина + язык) — любое изменение **перерисовывает** **всех** потребителей. **Дробите** на **несколько** узких контекстов.
WARN: **Путаете «создать контекст» и «использовать»**: `const Ctx = createContext()` — это **объект**, а не «хранилище». Значение **задаётся** только **в** `<Ctx.Provider value={…}>`. Вне провайдера — **дефолт**.
