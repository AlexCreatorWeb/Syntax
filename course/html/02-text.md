# Урок 2. Текст и заголовки

## Цель
После урока студент сможет: разметить текст статьи, правильно выбрав уровень заголовка и семантику выделения (жирный ≠ `<b>`, акцент ≠ `<i>`), и использовать служебные текстовые элементы (`br`, `hr`, `blockquote`, `code`, `pre`, `mark`, `abbr`).

## Теория

**Заголовки — это структура, а не шрифт.** Браузер, поисковик и скринридер используют `h1–h6` чтобы «прочитать оглавление» страницы. `h1` — самая важная тема, `h6` — самая мелкая. Визуально любой заголовок можно стилизовать под что угодно через CSS — но семантический уровень выбирается по **иерархии содержания**, а не по размеру шрифта.

Правила:
- Один `h1` на страницу (тема страницы).
- Не «прыгаем» через уровни без нужды: `h1 → h3` без `h2` ломает оглавление. Иерархия отражает структуру, а не дизайн.
- Заголовки не должны содержать другие заголовки, и в `<h1>` не пишут «вводный абзац».

**Выделение имеет смысл, а не только вид:**

| Тег | Значение | Визуал по умолчанию |
|---|---|---|
| `<strong>` | важность, значимость | жирный |
| `<em>` | интонационный акцент | курсив |
| `<b>` | выделено без особой важности (ключевые слова, теги) | жирный |
| `<i>` | другой режим: идиомы, термины, мысленная речь | курсив |
| `<mark>` | помечено (например, совпадение с поиском) | жёлтый фон |
| `<del>` / `<ins>` | удалено / вставлено | зачёркнутый / подчёркнутый |

Практическое правило: почти всегда нужны `strong` и `em`. `b`/`i` — когда значение «выделено, но не «важно»/«акцент» (например, `<b>Продажи</b>` в тексте о компании — просто термин).

**Пары «блока и инлайна»:**
- `<p>` — абзац (блок). Вложенные `p` друг в друга быть не могут — соседствуют.
- `<code>` — фрагмент кода (инлайн). `<pre>` — предформатированный блок: сохраняет пробелы и переносы, обычно оборачивает `code` (`<pre><code>...`).
- `<blockquote>` — цитата блока (чужое мнение, отдельный фрагмент). Внутри `p`, источник — в `cite` или обычном тексте.
- `<br>` — перенос строки ВНУТРИ абзаца (адрес, подпись песни). Не для разделения абзацев!
- `<hr>` — тематическая смена темы в тексте (блок).

## Пример

Статья «Как браузер читает страницу» (валидный HTML5, вставьте в body урока 1):

```html
<main>
  <h1>Как браузер читает страницу</h1>

  <p>HTML — это <strong>разметка структуры</strong>, а не инструкция
  по рисованию. Браузер сначала строит дерево элементов,
  а уже потом применяет к нему стили.</p>

  <h2>Парсинг</h2>
  <p>Разбор идёт <em>сверху вниз</em>, один символ за другим.</p>

  <h2>Цитата из спецификации</h2>
  <blockquote>
    <p>Авторы должны использовать один h1 на страницу.</p>
    <cite>— HTML Living Standard</cite>
  </blockquote>

  <h2>Код в тексте</h2>
  <p>Тег <code>&lt;p&gt;</code> создаёт абзац. Фрагмент:</p>
  <pre><code>const x = 1;
console.log(x); // 1</code></pre>

  <p>Правило: <mark>структура важнее шрифта</mark>.</p>
  <hr>
  <p>Адрес автора:
    <br>ул. Веб, д. 5, кв. 42</p>
  <p>Правка от 01.02: <del>три уровня заголовка</del> <ins>четыре</ins>.</p>
  <p>Сокращения: <abbr title="HyperText Markup Language">HTML</abbr>,
  <abbr title="Application Programming Interface">API</abbr>.</p>
</main>
```

Обратите внимание:
- `&lt;` и `&gt;` — HTML-сущности: символ `<` в тексте «съедается» парсером как начало тега, поэтому кодируем. Частые: `&amp;` (&), `&lt;` (<), `&gt;` (>), `&quot;` ("), `&copy;`.
- `<abbr title="...">` — при наведении показывается расшифровка; скринридеры озвучивают её.

## Частые ошибки новичков

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Все заголовки `h2` «чтобы были одного размера» | Оглавление страницы пустое, a11y и SEO страдают | Размер — CSS, уровень — структура |
| Два `h1` (шапка сайта + тема страницы) | Конфликтует с логотипом-`h1`, скринридер «теряет тему» | Один `h1` на страницу |
| `<b>` вместо `<strong>` (и наоборот) в 90% случаев | Потеря смысла: скринридер не меняет интонацию | `strong` = важно, `em` = акцент |
| `<center>`, `<font>` | Мёртвые теги HTML 4 | Выравнивание и шрифт — в CSS |
| `<br><br>` между абзацами | Невидимая структура, нельзя стилизовать | Каждый абзац — свой `<p>` |
| `<div>`/`<span>` «на всякий случай» вокруг всего | Семантика нулевая, дерево из мусора | Сначала ищем смысловой тег, потом — `div` |
| Текст «<» в абзаце: `if (a < b) ...` | Парсер ждёт закрывающий тег, ломает страницу | Кодируем: `if (a &lt; b)` |
| `blockquote` для обычного выделения цитатой-одной-строки | Блок для блоков | Короткая фраза в тексте — `q` или просто кавычки |

## Практическое задание

1. Возьмите страницу с урока 1. Замените её содержимое на текст статьи (≥ 5 абзацев, 2 уровня заголовков, цитата).
2. Разметьте: `strong` (≥2), `em` (≥2), `mark` (1), `code` (1), `pre` (1), `blockquote` с `cite` (1), `abbr` (2), `hr` (1), `br` в адресе (1).
3. Проверьте валидатором. В DevTools → вкладка Accessibility (или расширением) посмотрите tree-view: заголовки должны образовать иерархию h1 → h2.
4. Бонус: найдите статью на любимом сайте, скопируйте её текст (не код!) и разметьте заново, выбирая теги осознанно.
