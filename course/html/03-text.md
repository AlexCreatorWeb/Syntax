# Урок 3. Текст и заголовки

## Цель
После урока студент сможет: разметить текст статьи, правильно выбрав уровень заголовка и семантику выделения (важность ≠ «жирный»), и использовать служебные элементы: `blockquote`, `code`/`pre`, `mark`, `del`/`ins`, `abbr`, `br`, `hr`.

## Теория
### Заголовки — это структура, а не шрифт
`h1`–`h6` — это «оглавление» страницы для браузера, поисковика и скринридера. `h1` — самая важная тема, уровни ниже — более мелкая структура. Визуально любой заголовок можно сделать каким угодно через CSS, но уровень выбирается по иерархии содержания, а не по размеру шрифта.

Правила: один `h1` на страницу; не «прыгаем» через уровни без нужды (h1 → h3 без h2 ломает оглавление); заголовок не содержит других заголовков.

### Выделение имеет смысл, а не только вид
`<strong>` — важность, значимость (визуал: жирный). `<em>` — интонационный акцент (визуал: курсив). `<b>` — выделено без особой важности (ключевые термины), `<i>` — другой режим речи (идиомы, названия). `<mark>` — «помечено» (совпадение с поиском, жёлтый фон). `<del>`/`<ins>` — «удалено/вставлено» (правки).

Практическое правило: в 90% случаев нужны `strong` и `em` — скринридер подчёркивает их интонацией. `b`/`i` — когда «выделено, но не важно/акцент».

### Параграфы и служебные элементы
`<p>` — абзац (блок): вложенных `p` друг в друга не бывает, они соседствуют. `<code>` — фрагмент кода в строке; `<pre>` — предформатированный блок: сохраняет пробелы и переносы, обычно оборачивает `code`. `<blockquote>` — цитата-блок (чужое мнение, отдельный фрагмент), источник — в `<cite>`. `<br>` — перенос строки ВНУТРИ абзаца (адрес, строки подписи) — не для разделения абзацев! `<hr>` — тематическая смена темы. `<abbr title="...">` — сокращение с расшифровкой (при наведении и для скринридера).

TIP: перед написанием статьи сформулируйте оглавление (h1 → h2 → h3) — разметка текста тогда идёт «по скелету», и пропущенные уровни видны сразу.

NOTE: абзац — это 3–5 предложений. Если абзац «не помещается в экран» — разбейте его или вынесите часть в отдельную секцию с заголовком: читатель (и скринридер) воспринимает текст блоками.

## Пример
Статья «Как браузер читает страницу» (вставьте в body):
```html
<main>
  <h1>Как браузер читает страницу</h1>
  <p>HTML — это <strong>разметка структуры</strong>, а не инструкция
  по рисованию. Сначала дерево элементов, потом стили.</p>
  <h2>Парсинг</h2>
  <p>Разбор идёт <em>сверху вниз</em>, один символ за другим.</p>
  <h2>Цитата из спецификации</h2>
  <blockquote>
    <p>Авторы должны использовать один h1 на страницу.</p>
    <cite>— HTML Living Standard</cite>
  </blockquote>
  <h2>Код в тексте</h2>
  <p>Тег <code>&lt;p&gt;</code> создаёт абзац. Фрагмент:</p>
  <pre><code>const x = 1;
console.log(x); // 1</code></pre>
  <p>Правило: <mark>структура важнее шрифта</mark>.</p>
  <hr>
  <p>Адрес автора:
    <br>ул. Веб, д. 5, кв. 42</p>
  <p>Правка от 01.02: <del>три заголовка</del> <ins>четыре</ins>.</p>
  <p>Сокращения: <abbr title="HyperText Markup Language">HTML</abbr>.</p>
</main>
```
Обратите внимание: `<` внутри `code` закодировано как `&lt;` (урок 2) — иначе парсер сожрёт его как тег.

## Частые ошибки
WARN: все заголовки h2 «чтобы были одного размера» — оглавление страницы пустое, a11y и SEO страдают; размер — дело CSS.
WARN: два h1 (логотип + тема) — скринридер «теряет» тему страницы; оставляем один.
WARN: <b> вместо <strong> и наоборот почти всегда — потеря смысла: скринридер не меняет интонацию.
WARN: мёртвые теги HTML 4 — <center> и <font> — выравнивание и шрифт давно в CSS.
WARN: <br><br> между абзацами — структура невидима и не стилизуется; каждый абзац — свой <p>.

## Практическое задание
1. В стартовом файле выполните TODO: вводные абзацы (с strong и em), h2-подзаголовки, блокquote с cite.
2. Добавьте блок с инлайн-кодом и <pre><code> (2–3 строки кода).
3. Разметьте: mark, del/ins, два abbr, hr, адрес с br.
4. Запустите и проверьте на validator.w3.org — 0 ошибок.
5. Бонус: в DevTools проверьте иерархию: h1 один, под ним только h2, внутри h2 — h3.
