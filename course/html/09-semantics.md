# Урок 9. Семантическая структура страницы

## Цель
После урока студент сможет: собрать каркас любой страницы из семантических landmarks (`header`, `nav`, `main`, `article`, `section`, `aside`, `footer`), применить правила вложенности и объяснить, почему `div` — последнее средство.

## Теория

Все предыдущие уроки давали «атомы» (текст, ссылки, картинки, списки, таблицы, формы). Семантика — это **сборка атомов в осмысленные блоки**, у каждого из которых есть «роль» в структуре страницы. Браузер, поисковик и скринридер видят landmarks и «перемещаются» по странице по ролям, а не по пикселям.

**Каркас из landmarks (HTML Living Standard, раздел Landmarks):**

```
<body>
  <header>   — вводный блок: логотип, навигация, hero.
  <nav>      — группа ссылок (может быть несколько: меню, пагинация, breadcrumbs).
  <main>     — УНИКАЛЬНЫЙ контент страницы. Один на страницу!
    <article>— самодостаточный блок (пост, карточка товара, комментарий).
    <section>— тематический раздел (имеет СВОЙ заголовок h2/h3...).
    <aside>  — «смежный» контент (виджет, реклама, «ещё по теме»).
  <footer>   — служебный блок: авторы, копирайт, доп. ссылки.
```

**Ключевые правила:**
1. **`<main>` — ровно один на страницу**, и он не должен быть вложен в `article`, `section`, `aside`, `nav`, `header`, `footer` (и наоборот: они не должны быть внутри `main`… точнее — `main` не должен ИХ содержать как «родителя» landmarks-контейнеров на верхнем уровне). Практика: `main` — прямой ребёнок `body`, внутри него — контент.
2. **`<article>` — «самодостаточность»**: блок, который имеет смысл ОТДЕЛЬНО от остального (публикация в ленте, карточка товара, tweet). Тест: можно ли вынести блок в RSS/архив и он остаётся понятным? Да → `article`.
3. **`<section>` — тематический разрез, КТОРЫЙ ИМЕЕТ ЗАГОЛОВОК** (`h2`/`h3`/... внутри). Раздел без заголовка — просто `<div>` (или переосмыслить: нужен ли он вообще).
4. **`<header>`/`<footer>`** — не только «шапка/подвал сайта»: у `article` и `section` могут быть СВОИ `header`/`footer` (например, футер статьи «обновлено: …»).
5. **`<aside>`** — контент, СВЯЗАННЫЙ с основным, но второстепенный: sidebar, «связанные статьи», автор в карточке.
6. **`<div>`/`<span>`** — «безымянные» контейнеры для CSS/JS, когда семантический тег не найден. Это нормально — но сначала ищем осмысленный.

**`nav` vs «группа ссылок»**: `nav` — для ПОВТОРЯЮЩЕЙСЯ навигации (меню, хлебные крошки, пагинация). Разовые «ссылки в тексте» — не навигация, `nav` не нужны.

**Частый вопрос: «section или article в блоге?»** Пост = `article` (самодостаточен). Категории/темы внутри поста = `section`. Сайдбар с «популярным» = `aside`.

**Иерархия заголовков + landmarks:** `h1` — тема страницы (в `main`), `h2` — секции, `h3` — подразделы. Landmarks не заменяют заголовки — они их РАМЯТ.

## Пример

Страница «Блог о вёрстке» (собираем из всех уроков):

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Блог о вёрстке — Syntax</title>
</head>
<body>
  <header>
    <h1>Блог о вёрстке</h1>
    <nav aria-label="Разделы">
      <a href="/">Главная</a>
      <a href="/blog">Статьи</a>
      <a href="/about">О нас</a>
    </nav>
  </header>

  <main>
    <!-- Карточка поста: самодостаточный блок -->
    <article>
      <header>
        <h2>Как мы переверстали сайт на семантике</h2>
        <p><time datetime="2026-01-15">15 января 2026</time> · 7 мин</p>
      </header>

      <p>Рассказываем, как отказались от вёрстки на div'ах...</p>

      <section aria-labelledby="why">
        <h3 id="why">Почему семантика</h3>
        <p>Landmarks дают скринридеру «карту» страницы...</p>
        <figure>
          <img src="tree.png" alt="Дерево DOM: header, main, article, section"
               width="800" height="400">
          <figcaption>Дерево элементов после переделки</figcaption>
        </figure>
      </section>

      <section aria-labelledby="result">
        <h3 id="result">Результат</h3>
        <ul>
          <li>WCAG-аудит: 0 блокирующих проблем</li>
          <li>+12% к CTR из поиска (структура индексируется лучше)</li>
        </ul>
      </section>

      <footer>
        <p>Метки: <a href="/tag/html">html</a>,
           <a href="/tag/a11y">a11y</a></p>
      </footer>
    </article>

    <!-- Смежный контент: aside -->
    <aside aria-label="Похожие статьи">
      <h2>Ещё по теме</h2>
      <ul>
        <li><a href="/post/tables">Таблицы: данные, а не вёрстка</a></li>
        <li><a href="/post/forms">Формы без JS-боли</a></li>
      </ul>
    </aside>
  </main>

  <footer>
    <p>© 2026 Syntax · <a href="/privacy">Конфиденциальность</a></p>
  </footer>
</body>
</html>
```

Разбор:
- Один `main` на странице, внутри — `article` (пост) + `aside` (сайдбар).
- У `article` СВОИ `header` (заголовок поста + дата) и `footer` (теги) — допустимо.
- `time datetime="2026-01-15"` — машинно-читаемая дата (урок 12).
- `section` имеет `h3` внутри — правило «section = с заголовком».
- `aria-labelledby` — в уроке 11; пока просто видим паттерн.
- В `header` — `h1` (тема страницы) и `nav`.

## Частые ошибки новичков

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Два `main` (или `main` внутри `article`) | Нарушение уникальности, landmarks-хаос | Один `main`, прямой ребёнок body |
| `div` на всё, «потому что CSS не cares» | Landmarks не объявлены, a11y-навигация слепая | Сначала семантика, потом div |
| `<section>` без заголовка | «Секция без темы» — валидно, но бессмысленно | Заголовок внутри (h2/h3) или div |
| `<article>` на каждый блок текста | «Самодостаточность» нарушена — это просто section/div | Тест RSS: можно вынести отдельно? |
| `<footer>` только «подвал сайта» | Потеряны футеры статей/секций | footer может быть у article/section |
| `<nav>` на каждую группу ссылок в тексте | «Навигация» = повторяющаяся навигация, не «список ссылок» | nav — меню/крошки/пагинация |
| `h1` на каждый «большой заголовок» (карточки, секции) | Иерархия сломана: 5 h1 на странице | h1 — один, h2/h3 по структуре |
| `aside` для «главного» контента | aside = второстепенный | Основной — в `main` |
| `header` внутри `footer` (и наоборот) | Не валидная вложенность landmarks | Каждый landmark — в «своём» контексте |

## Практическое задание

1. Возьмите любую простую страницу (например, landing «о сервисе»). Переделайте её каркас: `header` (лого + nav), `main` (3–4 `section` с h2), `aside` («отзывы» или «FAQ»), `footer`.
2. Внутри `main` сделайте 2 `article` (например, «кейсы» — самодостаточные блоки со своими header/footer).
3. Проверьте в DevTools → вкладка Elements: вкладки «Accessibility»/tree — landmarks объявлены (banner, navigation, main, contentinfo).
4. Валидатор: 0 ошибок.
5. Бонус: добавьте `time datetime` для дат, `aria-labelledby` для 2 секций (готовимся к уроку 11).
