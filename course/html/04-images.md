# Урок 4. Изображения: img, srcset, picture

## Цель
После урока студент сможет: добавить картинку с правильным `alt`, подготовить адаптивные изображения через `srcset`/`sizes` и `picture`, оформить подпись через `figure`/`figcaption` и включить ленивую загрузку.

## Теория

**`<img>` — пустой элемент, всё в атрибутах.**

Базовые атрибуты:
- `src` — адрес картинки.
- `alt` — **текстовая замена**: если картинку нельзя увидеть, что сказать/прочитать вместо неё. Это НЕ «описание картинки для SEO», это альтернатива содержимому.
- `width`/`height` — размеры в px. Обязательны в современной вёрстке: браузер резервирует место ДО загрузки → нет «прыжков» макета (CLS).

**Правила `alt` (самая частая боль новичков):**
- Информативная картинка (график, схема, фото товара) — `alt` несёт её смысл: `alt="Выручка за 2025 год выросла на 18% к 2024"`.
- Картинка-ссылка — `alt` = цель ссылки: `alt="Купить подписку"`.
- Чисто декоративная картинка (фоновая иконка, орнамент) — `alt=""` (пустая строка): скринридер пропустит. «Не писать alt» и «alt пустой» — разные вещи.
- Не пишем: «картинка», «фото», «image123» — мусор в озвучке.

**Адаптивность.** Одна и та же картинка может понадобиться в 320px (телефон), 768px (планшет) и 1920px (монитор). Загружать 4 МБ на телефон — медленно и дорого. Инструменты:

1. **`srcset` + `sizes`** (выбор РАЗМЕРА того же изображения):
```html
<img
  src="hero-800.webp"
  srcset="hero-400.webp 400w, hero-800.webp 800w, hero-1600.webp 1600w"
  sizes="(max-width: 600px) 100vw, 700px"
  alt="Команда на конференции"
  width="1600" height="900">
```
- `srcset` — список «файл — его реальная ширина в px».
- `sizes` — «сколько px займёт картинка в макете при разных ширинах окна» (CSS media query).
- Браузер сам считает, какой файл нужен: `ширина в макете × плотность экрана`.
- `src` обязателен как fallback.

2. **`<picture>`** (выбор ФОРМАТА/СОДЕРЖАНИЯ): разные изображения для разных условий — WebP/AVIF против JPEG, кроп для мобильных (обрезанный кадр), тёмная версия.
```html
<picture>
  <source type="image/avif" srcset="hero.avif">
  <source type="image/webp" srcset="hero.webp">
  <img src="hero.jpg" alt="..." width="1600" height="900">
</picture>
```
Браузер идёт сверху вниз и берёт ПЕРВЫЙ поддерживаемый формат. Финальный `<img>` — обязательный fallback.

3. **Ленивая загрузка** — `loading="lazy"`: картинки вне первого экрана грузятся при скролле. Картинку в «первом кадре» (LCP) наоборот помечаем `fetchpriority="high"`.

**`<figure>` + `<figcaption>`** — картинка с подписью, которая К НЕЙ относится (иллюстрация к тексту, не просто картинка с абзацем). `figcaption` — обычно первый или последний элемент `figure`.

## Пример

```html
<!-- 1. Простое информационное изображение -->
<figure>
  <img src="chart.png" alt="График: пользователи выросли с 10 тыс. до 45 тыс. за год"
       width="800" height="450">
  <figcaption>Рост аудитории за 12 месяцев</figcaption>
</figure>

<!-- 2. Декоративный элемент — скринридеру незачем -->
<p>Мы делаем вёрстку <img src="sparkle.svg" alt="" width="20" height="20"> аккуратно.</p>

<!-- 3. Адаптивное изображение по размеру -->
<img src="team.jpg"
     srcset="team-400.jpg 400w, team-800.jpg 800w, team-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 800px"
     alt="Наша команда на хакатоне"
     width="1600" height="900"
     loading="lazy">

<!-- 4. Адаптивное изображение по формату -->
<picture>
  <source type="image/avif" srcset="banner.avif">
  <source type="image/webp" srcset="banner.webp">
  <img src="banner.jpg" alt="Обложка: закат над горами" width="1920" height="640">
</picture>

<!-- 5. Картинка-ссылка (из урока 3) -->
<a href="/products/">
  <img src="card.png" alt="Открыть каталог товаров" width="320" height="200"
       loading="lazy">
</a>
```

## Частые ошибки новичков

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| `alt="картинка"` / `alt="image"` / alt пропущен | Скринридер читает «картинка» N раз или молчит без причины | alt = смысл, декор — `alt=""` |
| `alt` длиной в абзац, «фотография красивого котика на диване, который смотрит влево» | Засоряет озвучку | 1–2 предложения, только несущее смысл |
| Нет `width`/`height` | Страница «прыгает» при загрузке, плохой CLS | Всегда пишем собственные размеры картинки |
| `<div>` с фоном `background-image` для контента | Фон не грузится при «показать только картинки», неиндексируется, не имеет alt | Контентное изображение — `<img>` |
| `srcset` без `sizes` | Браузер угадывает размер → выбирает файл не того веса | Для адаптивной ширины — пара srcset+sizes |
| `<picture>` без финального `<img>` | Не валидно, старые браузеры не покажут ничего | `<img>` — обязательный fallback |
| `loading="lazy"` на LCP-картинке первого экрана | Главный скриншот грузится позже | LCP — `fetchpriority="high"`, lazy — ниже экрана |
| `<figure>` для любого блока с картинкой | figure = «иллюстрация, относящаяся к тексту», не контейнер-вёртка | figure только с figcaption-смыслом |
| Пасхалки-атрибуты: `title="кот"` у img | Скринридер может озвучить дублирование | title — только для уточнений (расшифровки), не описаний |

## Практическое задание

1. Возьмите 3 картинки: инфографика, фото, декоративная иконка. Разметьте их с правильными `alt` (3 разных стратегии), `width`/`height`.
2. Для фото подготовьте 3 версии (400/800/1600 px — можно через `sips`/`ImageMagick`/ онлайн) и подключите через `srcset` + `sizes`. В DevTools → Network проверьте: при сужении окна грузится меньший файл.
3. Оберните инфографику в `figure` с `figcaption`.
4. Добавьте `loading="lazy"` на вторую и третью картинки; скрольте и в Network посмотрите, когда началась загрузка.
5. Бонус: сконвертируйте одну картинку в WebP (например, `cwebp`) и подключите через `<picture>` (webp + jpg-fallback).
