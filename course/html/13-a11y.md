# Урок 13. a11y: ARIA, клавиатура, чек-лист

## Цель
После урока студент сможет: объяснить «первое правило ARIA», добавить необходимые `aria-*` атрибуты, проверить страницу с клавиатуры и по чек-листу WCAG 2.2.

## Теория
### Доступность — страница для всех
Доступность (a11y) — страница работает для ВСЕХ: со скринридером (не видит экран), с клавиатурой (нет мыши), при слабом зрении, на маленьком экране. HTML-семантика (урок 11) — БЕСПЛАТНАЯ a11y: landmarks, заголовки, таблицы, формы уже «читаются» скринридером. ARIA — дополнение для случаев, где семантики не хватает.

### Первое правило ARIA
«Не используй ARIA, если есть нативный элемент»: `<button>` лучше `<div role="button">`, `<nav>` лучше `<div role="navigation">`, `<label for>` лучше `aria-label` на input. ARIA нужна, когда: имя у элемента без видимой подписи (`aria-label` на иконку-кнопку, на nav); имя из существующего элемента (`aria-labelledby` на id заголовка); «скрыть от скринридера» (`aria-hidden` на декор); «объяви изменения» (`aria-live="polite"`, готовый `role="status"` на «Сохранено»); состояние (`aria-expanded` у бургера); «текущий» (`aria-current="page"`).

### Клавиатура — первый пользователь
Чек: Tab/Shift+Tab ходит по интерактивным элементам, фокус ВИДИМ (не outline:none без замены); Enter/Space активируют (у a — Enter, у button — оба); Esc закрывает модалку/меню; фокус не «застревает» в скрытых элементах. Ловушка: `<div onclick>` без tabindex/role — не фокусируется и недоступен.

### Контраст и размеры (WCAG 2.2, AA)
Текст ≥ 24px (или 32px bold) — контраст ≥ 3:1; прочий текст — ≥ 4.5:1. Целевой размер кликабельного — не меньше ~24×24px. Инструменты: DevTools → Lighthouse, WebAIM Contrast Checker.

### Как это слышно
Скринридер объявляет: «Вопросы и ответы, раздел, уровень 2» (заголовок), «Таблица, 4 колонки, 3 строки» (таблица с caption), «Кнопка, Поиск» (кнопка с aria-label), «Сохранено, статус» (live-область). Если объявление «голое» («кнопка», «текстовое поле») — имя где-то потеряно: ищите label/aria-label.

TIP: самый быстрый а11y-аудит — 10 минут клавиатуры: Tab по странице вслух («куда сфокусировался, что активирую Enter»). Всё, где «застрял» или «перескочил» — баг.

## Пример
```html
<button type="button" aria-label="Поиск">
  <svg width="20" height="20" aria-hidden="true">…</svg>
</button>
<p>Отлично! <span aria-hidden="true">✔</span></p>
<section aria-labelledby="faq-h">
  <h2 id="faq-h">Вопросы и ответы</h2>
</section>
<p id="save-status" role="status" aria-live="polite"></p>
<button type="button" aria-expanded="false" aria-controls="menu">Меню</button>
<nav id="menu" hidden></nav>
<nav aria-label="Разделы">
  <a href="/" aria-current="page">Главная</a>
  <a href="/blog">Блог</a>
</nav>
<table>
  <caption>Сравнение тарифов</caption>
  <thead>
    <tr>
      <th scope="col">Тариф</th>
      <th scope="col">Цена</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Базовый</th>
      <td>0 ₽</td>
    </tr>
  </tbody>
</table>
```
Каждый фрагмент — типичная «точка a11y»: иконка с именем, декор-скрипка, секция с заголовком, живая область, бургер, текущий пункт, таблица.

## Частые ошибки
WARN: outline: none на :focus без замены — фокус «невидим», клавиатурный пользователь «слеп».
WARN: role="button" на <div> — нарушение первого правила ARIA; нужен <button>.
WARN: aria-label на элемент с видимым текстом — дублирование: скринридер читает дважды.
WARN: «Кликните здесь» / «Подробнее» без контекста — скринридер: «ссылка, кликните здесь» — КУДА? Текст ссылки = цель.
WARN: aria-hidden="true" на блоке с фокусируемыми элементами — скрыто, но Tab «застревает».
