# Урок 6. Изображения: img, srcset, picture

## Цель
После урока студент сможет: добавить картинку с правильным `alt`, подготовить адаптивные изображения через `srcset`/`sizes` и `picture`, оформить подпись через `figure`/`figcaption` и включить ленивую загрузку.

## Теория
### Базовые атрибуты
`<img>` — пустой элемент: всё в атрибутах. `src` — адрес; `width`/`height` — размеры в px, обязательны в современной вёрстке: браузер резервирует место ДО загрузки, нет «прыжков» макета (CLS).

`alt` — текстовая замена: что сказать/прочитать, если картинку нельзя увидеть. Три стратегии: информационная картинка (график, фото товара) — alt несёт смысл («Выручка выросла на 18%»); картинка-ссылка — alt = цель ссылки («Купить»); декоративная (орнамент, фоновая иконка) — `alt=""` (пустая строка: «пропусти, скринридер»). «Не писать alt» и «alt пустой» — разные вещи.

### Адаптивность: srcset и sizes
Одна и та же картинка нужна в 400px (телефон), 800px (планшет), 1600px (монитор). Загружать 4 МБ на телефон — медленно и дорого. `srcset` — список «файл — его реальная ширина»; `sizes` — «сколько px картинка займёт в макете при разных ширинах окна». Браузер сам считает и берёт нужный файл. `src` остаётся как fallback.

### picture: выбор формата
`<picture>` — разные изображения для разных условий: WebP/AVIF против JPEG, кроп для мобильных. Браузер идёт сверху вниз и берёт ПЕРВЫЙ поддерживаемый формат; финальный `<img>` — обязательный fallback.

### Ленивая загрузка и figure
`loading="lazy"` — изображения вне первого экрана грузятся при скролле. Главное изображение первого экрана (LCP) наоборот помечаем `fetchpriority="high"`. `<figure>` + `<figcaption>` — картинка с подписью, которая К НЕЙ относится.

### Форматы и вес
JPEG — универсал, но тяжёл; WebP и AVIF при том же качестве на 25–50% легче. На практике: генерируете картинку в WebP/AVIF + JPEG-fallback через `picture` (или `srcset` с разными форматами). На телефоне с мобильным интернетом экономия — секунды загрузки. Для иконок и логотипов — SVG (масштабируется, крошечный вес).

TIP: в DevTools → Network → Img видно, какой файл реально запросил браузер. Сузьте окно и перезагрузите — с srcset поменяется размер скачанного файла.

## Пример
```html
<figure>
  <img src="chart.png"
       alt="График: пользователи выросли с 10 тыс. до 45 тыс. за год"
       width="800" height="450">
  <figcaption>Рост аудитории за 12 месяцев</figcaption>
</figure>
<p>Мы делаем вёрстку <img src="sparkle.svg" alt="" width="20" height="20"> аккуратно.</p>
<img src="team.jpg"
     srcset="team-400.jpg 400w, team-800.jpg 800w, team-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 800px"
     alt="Наша команда на хакатоне"
     width="1600" height="900"
     loading="lazy">
<picture>
  <source type="image/webp" srcset="banner.webp">
  <img src="banner.jpg" alt="Обложка: закат над горами" width="1920" height="640">
</picture>
<a href="/products/">
  <img src="card.png" alt="Открыть каталог" width="320" height="200"
       loading="lazy">
</a>
```
Четыре паттерна в одном примере: figure с подписью, декор с пустым alt, адаптивная пара srcset+sizes с lazy, выбор формата через picture.

## Частые ошибки
WARN: alt="картинка", alt="image" или alt пропущен — скринридер N раз прочитает «картинка» или замолчит без причины.
WARN: alt длиной в абзац («фотография котика, который смотрит влево…») — засоряет озвучку; 1–2 предложения, только несущее смысл.
WARN: нет width/height — страница «прыгает» при загрузке, плохая метрика CLS.
WARN: srcset без sizes — браузер угадывает ширину и выбирает файл не того веса; для адаптивной ширины — пара.
WARN: picture без финального <img> — невалидно, старые браузеры покажут ничего.

## Практическое задание
1. В стартовом файле добавьте картинку (любой URL): alt по смыслу, width/height.
2. Оберните инфографику в figure с figcaption.
3. Добавьте декоративный img с пустым alt внутрь абзаца.
4. Сделайте картинку-ссылку (a вокруг img, alt = цель).
5. Бонус: подготовьте 2–3 версии одной картинки разных размеров и подключите srcset + sizes; в Network проверьте, что при сужении окна грузится меньший файл.
