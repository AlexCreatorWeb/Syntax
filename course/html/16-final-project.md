# Урок 16. Финальный проект: семантическая страница

## Цель
Собрать ПОЛНУЮ страницу (лендинг продукта/курса) по чек-листу курса: валидный HTML5, семантика, доступность, адаптивные изображения, формы, медиа, современные элементы — и проверить её как QA.

## Теория
### Правила, которые держим на проекте
Один main и один h1; landmarks на каркасе (урок 11); у каждой картинки alt + width/height (урок 6); у каждого поля label (урок 9); у таблиц caption и th scope (урок 8); head полностью заполнен (урок 14); фокус видим, Tab-порядок логичен (урок 13); валидатор — 0 ошибок (всегда).

### Как работать
Не «всё сразу», а слоями: 1) каркас landmarks — пустые section с h2; 2) контент в секции (текст, списки, картинки); 3) формы и медиа; 4) a11y-проход (ария, фокус, контраст); 5) head (мета, OG, favicon); 6) валидация и Lighthouse. Каждый слой — закрывает блок чек-листа, и «откат» не ломает остальное. Если на каком-то слое «зависли» — вернитесь к уроку: каждый TODO в скелете ссылается на номер урока.

### Что считается «готово»
Валидатор 0 ошибок; Lighthouse Accessibility ≥ 90; landmarks видны в tree-view; мобильный вьюпорт (375px) без горизонтального скролла; страница «читается» с отключённым CSS (семантика работает); диалог закрывается по Esc.

### Чек-лист приёмки (выжимка)
1. Валидатор: 0 ошибок. 2. Один main, один h1; landmarks в tree-view. 3. У каждого img — alt + width/height. 4. У каждого input — label; радио в fieldset. 5. Таблицы: caption + th scope. 6. Head: description, canonical, 4 og:*, favicon, 2 theme-color. 7. Контраст ≥ 4.5:1; фокус видим. 8. Dialog: Esc/backdrop/aria-labelledby. 9. Мобильный 375px: без горизонтального скролла. 10. Lighthouse Accessibility ≥ 90.

NOTE: не пытайтесь сделать «всё идеально с первого раза» — пройдите слои по порядку, чек-лист — в конце. Проект, прошедший 10 пунктов, — уже уровень «младший вёрстальщик».

TIP: перед финальной проверкой перечитайте страницу вслух (скринридер или голосом) — «заедающие» формулировки и отсутствующие alt слышны сразу.

## Пример
Структура финальной страницы (скелет):
```html
<header>  <!-- лого + nav: 4 пункта, aria-current -->
<main>
  <section id="hero">      <!-- h1, 2 абзаца, CTA-кнопка (открывает dialog) -->
  <section id="features">  <!-- h2, ul из 3 пунктов, figure + img (srcset) -->
  <section id="how">       <!-- h2, ol из 4 шагов -->
  <section id="pricing">   <!-- h2, table: caption + th scope, 3 тарифа -->
  <section id="video">     <!-- h2, video + track -->
  <section id="faq">       <!-- h2, 4 details -->
  <section id="contact">   <!-- h2, form: text/email/tel/date, select, textarea,
                              checkbox, required×3, pattern, 2 button -->
  <aside>                  <!-- 2 article: отзывы -->
</main>
<footer>  <!-- копирайт, nav доп. ссылки, time datetime pubdate -->
<dialog>  <!-- модалка «Подписаться» -->
```
Каждый блок — это урок: hero (11), features (6, 7), how (7), pricing (8), video (12), faq (15), contact (9, 10), aside (11), footer (11, 15), dialog (15). Собрать все десять блоков «из памяти» — и курс пройден.

## Частые ошибки
WARN: «красота» важнее валидности — мёртвые теги (center, font) и div-спагетти в финальной сборке.
WARN: head «на последнем слое» забыт — нет description/OG: карточка шаринга пустая.
WARN: a11y-проход после «всего готово» — поздно: ария и label вставляйте по ходу, а не «краской» в конце.
WARN: мобильный вьюпорт с горизонтальным скроллом — фиксированные px ширины; проверяйте на 375px.

## Практическое задание
1. Возьмите стартовый скелет (в редакторе) и заполните секции по TODO-комментариям.
2. Соберите форму контактов: 5 полей (label у каждого), 1 select с optgroup, textarea, checkbox, 2 кнопки.
3. Добавьте 2 картинки (alt по смыслу, width/height, loading="lazy" на нижнюю), 1 video с track.
4. Проход a11y: aria-label на иконки, aria-current в меню, role="status", контраст текста.
5. Заполните head: description, canonical, 4 og:*, favicon, 2 theme-color.
6. Финал: validator.w3.org — 0 ошибок; Lighthouse Accessibility ≥ 90; Tab-проход без «застреваний».
