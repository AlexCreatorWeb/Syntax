# Урок 2. Кодировки и символы

## Цель
После урока студент сможет: сделать так, чтобы кириллица, латиница, эмодзи и «опасные» символы корректно отображались в любом браузере; писать HTML-сущности и не попадать в ловушки «кракозябр» и BOM.

## Теория
### Зачем нужна кодировка
Файл на диске — это байты, а не буквы. Кодировка — соглашение, как эти байты читать: в UTF-8 латинская «A» — 1 байт, кириллическая «Я» — 2, эмодзи — 4. UTF-8 выиграл: он совместим с ASCII, компактен и покрывает все языки мира.

Браузер определяет кодировку по нескольким сигналам: meta-тег, HTTP-заголовок, BOM файла. Самый надёжный — написать `<meta charset="utf-8">`, причём строго ПЕРВОЙ строкой `<head>`: браузер ищет эту мета-строку в первых байтах файла, и если не нашёл — уже «угадал» кодировку и менять решение не будет.

### HTML-сущности
Некоторые символы ломают разметку — их кодируют сущностями: амперсанд → `&amp;`, меньше → `&lt;`, больше → `&gt;`, кавычка → `&quot;`. Зачем: символ `<` в тексте парсер «съедает» как начало тега, `&` — как начало сущности. Частые символ-сущности: `&nbsp;` (неразрывный пробел), `&copy;`, `&mdash;` (длинное тире —), `&laquo;` («). Есть и числовая форма: `&#8470;`.

В практике обязательно только пять: `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&nbsp;` — остальные (тире, кавычки, ©) спокойно печатаются напрямую, файл же UTF-8.

### BOM и «чужие» символы
BOM (Byte Order Mark) — невидимые байты в начале файла. Для HTML он безвреден, но проблематичен, если файл будет склеен с другими (JS/CSS). В редакторах сохраняем как UTF-8 без BOM (в VSCode — в правом нижнем углу статус-бара).

При копировании текста с сайтов и PDF часто прилетают неразрывные пробелы (U+00A0) и «ёлочки» — в поиске по странице «10 000» с таким пробелом не совпадёт с «10000».

TIP: в VSCode в правом нижнем углу — «UTF-8». Если файл открылся кракозябрами: клик по кодировке → Reopen with Encoding → Windows-1251, затем Save with Encoding → UTF-8.

### lang
`<html lang="ru">` говорит скринридеру и поисковику, на каком языке страница. Иностранные вставки в тексте помечаем отдельно: `<span lang="en">hello</span>`.

## Пример
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Кодировки и символы</title>
</head>
<body>
  <h1>Символы</h1>
  <p>Кириллица, латиница, цифры и эмодзи — всё это UTF-8: Привет, Hello, 42, 🎉</p>
  <p>Опасные символы: &lt;p&gt; — это тег, &amp; — «и», &quot; — кавычка.</p>
  <p>Пунктуация: длинное тире &mdash;, кавычки «ёлочки», неразрывный пробел: 10&nbsp;000, авторское право &copy;.</p>
  <p>Иностранная вставка: <span lang="en">Hello, world</span>.</p>
</body>
</html>
```
Все пять обязательных сущностей на месте: браузер показывает «<p>», «&», кавычки, тире и «10 000» без переноса.

## Частые ошибки
WARN: в файле нет meta charset вообще — браузер угадывает кодировку, русский превращается в «Ð Ð° Ð· ...».
WARN: meta charset стоит после title или скриптов — до него браузер уже прочитал файл «не в той» кодировке.
WARN: в тексте «if (a < b)» — парсер ждёт закрывающий тег и ломает страницу; пишем if (a &lt; b).
WARN: «&» вместо «&amp;» в тексте и URL-параметрах — разметка ломается на первом пробеле: &color=red читается как сущность.
WARN: скопированный текст несёт неразрывные пробелы — поиск и сравнение строк молча «не сходятся»; заменяем U+00A0 на обычный пробел.

## Практическое задание
1. Откройте стартовый файл в редакторе и выполните TODO-комментарии: абзацы с амперсандом, с «if (a < b)», с тире и кавычками, иностранная вставка с lang.
2. Запустите страницу — все символы отрисовались, валидатор не ругается на неизвестные сущности.
3. На минуту уберите meta charset: браузер, скорее всего, «угадает» UTF-8 — но на старом сервере с CP-1251 угадает неверно. Верните строку.
4. Проверьте страницу на validator.w3.org — 0 ошибок и 0 предупреждений.
5. Бонус: найдите на developer.mozilla.org список HTML-сущностей и добавьте в страницу ещё три (например, товарный знак, кавычка-«лапка», делитель).
