# Урок 8. Таблицы и их доступность

## Цель
После урока студент сможет: разметить табличные данные со всеми обязательными частями (`caption`, `th` с `scope`, `thead`/`tbody`/`tfoot`), разобрать двухуровневую шапку и понять, когда таблицу использовать НЕ нужно.

## Теория
### Таблица — это данные, а не вёрстка
Таблица описывает структуру информации: строки × столбцы, где каждая ячейка относится к заголовку своего ряда/колонки. Сетки и карточки (вёрстка «в 3 колонки») — это дело CSS Grid/Flexbox; «табличка-конструктор» 2005 года — антипаттерн.

Критерий: если данные можно выразить как «столбец X по строкам Y» — это таблица. Если «карточка из трёх колонок» — нет.

### Анатомия валидной таблицы
`<table>` — контейнер. `<caption>` — заголовок таблицы, ПЕРВЫЙ дочерний элемент; скринридер объявляет его как «имя» таблицы. `<thead>` — строки заголовков, `<tbody>` — тело, `<tfoot>` — итоги. `<th>` — ячейка-заголовок; ключевой атрибут — `scope`: `scope="col"` — «я заголовок столбца» (th в thead), `scope="row"` — «я заголовок строки» (левая колонка с названиями показателей). `<td>` — обычная ячейка данных.

Зачем scope: в режиме «навигация по таблице» скринридер при фокусе на ячейке скажет «145, строка 2, колонна 3: Q2» — имя берёт из связанного `th`. Без scope — «колонка 3» без имени.

### Сложные схемы
Объединение ячеек: `colspan` (по горизонтали), `rowspan` (по вертикали). Когда у ячейки данных ДВА заголовка (двухуровневая шапка), scope не работает — связываем вручную: `id` на `th` и `headers="id1 id2"` на `td`. Для сводных таблиц иногда честнее дать ДВЕ простые таблицы, чем одну с headers-архитектурой. Правило-thumb: если на объяснение схемы ушло больше минуты — упростите данные или разбейте на две таблицы.

### colgroup
`<colgroup>` + `<col>` описывают СТОЛБЦЫ как целое: ширина, класс, span для группы. Редко нужен, но для «подсветить/осиротить» группу столбцов без повтора классов на каждой ячейке — единственный чистый способ.

### Где таблицы встречаются в жизни
Сравнение тарифов, расписание, отчёт по месяцам, характеристики товаров, курс валют. Если в макете «таблица» — посмотрите на данные: цифры/текст в ячейках, связанные заголовками? Значит, `table`. А если «таблица» — это сетка карточек с картинками и кнопками — это Grid, не таблица.

TIP: перед вёрсткой «таблицы» из макета спросите: «что здесь строки, что — столбцы, где заголовки?» Если ответить нельзя — это не таблица, это сетка.

## Пример
```html
<table>
  <caption>Выручка по кварталам, млн ₽</caption>
  <thead>
    <tr>
      <th scope="col">Квартал</th>
      <th scope="col">2024</th>
      <th scope="col">2025</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Q1</th>
      <td>120</td>
      <td>145</td>
    </tr>
    <tr>
      <th scope="row">Q2</th>
      <td>132</td>
      <td>158</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row">Итого</th>
      <td>252</td>
      <td>303</td>
    </tr>
  </tfoot>
</table>
```
Левая колонка («Q1», «Итого») — тоже заголовки строк: th scope="row". Итог в tfoot (браузер может вывести его сверху — это норма).

## Частые ошибки
WARN: таблица для вёрстки страницы (карточки в 3 колонки) — скринридер читает «таблица» для контента, который не данные.
WARN: заголовки сделаны <td> (жирные через CSS) — у ячеек нет «имени столбца» для доступности; пишем th scope.
WARN: нет <caption> — таблица без имени: «таблица из 4 колонок, тема неизвестна».
WARN: border="1" и другие атрибуты HTML 4 — мёртвые в HTML5; границы и раскраску — в CSS.
WARN: две «независимые» таблицы в одном <table> через пустую строку — одна логическая таблица = одни заголовки; разнесите.

## Практическое задание
1. В стартовом файле добавьте <caption> и замените заголовки td на th scope="col".
2. Сделайте левую колонку (филиалы) заголовками строк: th scope="row".
3. Добавьте <tfoot> с итоговой строкой.
4. Проверьте на validator.w3.org — 0 ошибок; в DevTools → Accessibility — таблица объявлена с именем.
5. Бонус: добавьте rowspan/colspan (объедините ячейки) и свяжите их через headers.
