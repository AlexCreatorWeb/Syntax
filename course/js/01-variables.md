# Урок 1. Переменные: let, const и var-всплытие

## Цель
После урока студент сможет: объявить переменную через let/const и выбрать между ними по правилам; объяснить, что такое всплытие (hoisting) и почему var — «артефакт»; отследить область видимости переменной в блоке.

## Теория
### Переменная — именованная «коробка»
Переменная — это имя, которое указывает на значение в памяти. JS — язык с **динамической типизацией**: тип «прилипает» к значению, а не к переменной — одно имя может держать число, потом строку (но по такой практике код быстро становится нечитаемым).

Объявление: `let age = 25;` — имя `age`, значение 25. Переназначение: `age = 26;` (без слова let/const — просто присваивание).

### let и const: два способа объявления
- **let** — «переменная, которую можно переназначить»: счётчики, «текущее» состояние;
- **const** — «константа»: переназначить нельзя (`const x = 1; x = 2;` → TypeError). const не делает значение НЕИЗМЕНЯЕмым: объект/массив в const можно мутировать (урок 21) — const защищает именно СВЯЗЬ «имя → значение».

**Правило современности: по умолчанию const; let — только когда переназначение нужно по смыслу.** В новом коде var не пишут вообще.

### var и всплытие (hoisting)
**var** — устаревший способ объявления. У него две «болезни»:
1. **Всплытие**: var «переезжает» наверх области видимости при парсинге — код `if (true) { var x = 1; } console.log(x);` выведет 1, хотя x «объявлен» внутри if (на самом деле — наверху функции/скрипта, а внутри if только присваивание);
2. **Нет блочной области**: var не «видит» фигурные скопки — переменная из if/for «утекает» наружу и «затекает» в соседние блоки.

let/const объявляются **в блоке**, где написаны, и не всплывают. А до строки объявления let/const переменной «ещё нет» — это «временная мёртвая зона» (TDZ, подробно урок 11): `console.log(a); let a = 1;` → ReferenceError.

TIP: читая чужой код, где «все» переменные let — задайте вопрос «а тут const нельзя?». Если переназначение не по смыслу — const. Это сразу делает код «предсказуемее»: читатель не ищет, где значение «меняется».

NOTE: в редакторе Syntax ваш JS-файл исполняется как обычный скрипт (не модуль): верхний уровень файла — «глобальная» область. Все переменные этого урока видны друг из друга — удобно для экспериментов: меняйте строки и нажимайте Run.

## Пример
Скопируйте в index.js (это и есть скелет задания) и запускайте — смотрите консоль:
```js
const name = "Syntax";
let level = 1;

level = 2; // let: можно переназначить

// name = "Other"; // TODO: раскомментируйте и посмотрите TypeError

if (level > 1) {
  const passed = true; // const живёт в этом блоке
  console.log("level:", level, "| passed:", passed);
}

// console.log(passed); // TODO: раскомментируйте → ReferenceError (блочная область)

let total = 10;
for (let i = 1; i <= 3; i++) {
  total += i;
}
console.log("total:", total); // 13
// console.log(i); // TODO: раскомментируйте → ReferenceError (i не утёк — в отличие от var)
```
Разбор: `const name` — имя не меняем. `let level` — «растём». `passed` — «локален» для if: снаружи его «нет». `i` — «локален» для цикла. Попробуйте «заменить» let на var в цикле — и `console.log(i)` снаружи «заговорит» (4): «утёкшая» переменная.

## Частые ошибки
WARN: var в новом коде — «утёкшие» переменные и «всплывший» код: два блока «пишут» в одну var-переменную, и логика «ломается» незаметно; var — только при чтении legacy.
WARN: const «всем» — и «переназначаете» (счётчик, флаг) через let... нет, через «обход»: obj.count += 1 «работает» (мутиация), но obj = newObj «падёт» (TypeError); решите осознанно: const на объект + «меняю» свойства.
WARN: объявили переменную БЕЗ let/const/let (x = 5) — в «строгом» режиме (модули) это ReferenceError, в обычном — «глобальная» переменная (загрязнение window); «всегда» пишите let/const.
WARN: «переназначили» const и «не поняли» почему — `const user = {}; user.name = "A";` — ОК (мутиация), `user = {};` — TypeError (переназначение связи); const = «имя закреплено», не «значение заморожено».
WARN: сравнение «до объявления»: console.log(x) «выше» строки let x — ReferenceError (TDZ), а не undefined — частая «загадка» при «перестановке» кода.
