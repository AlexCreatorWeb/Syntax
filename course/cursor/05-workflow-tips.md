# Рабочий процесс: 12 лайфхаков, которые делают быстрее

## Цель

После урока студент сможет: применить к своему рабочему дню набор из 12 рабочих привычек Cursor — от «Esc быстрее, чем назад-кнопка» до «правило трёх файлов», — объяснить, почему каждая экономит время, и выбрать пять, которые встроить в практику уже сегодня.

## Теория

Лайфхаки — это не «трюки», а устоявшиеся паттерны работы, которые суммарно дают кратно-больший выигрыш, чем «быстрый палец». Разберём 12 штук, сгруппированных по слоям: руки, контекст, агенты.

Слой «руки» (клавиатура). 1) Esc — универсальный «отменить»: отбрасывает предсказание Tab, закрывает палитру, отменяет Ctrl+K, сворачивает чат. Знание этого одного символа снимает половину «кликов мышкой». 2) Палитра команд (Ctrl+Shift+P) — быстрее меню: «composer», «theme», «open settings» — печатаешь и нажимаешь Enter. 3) Переходы: Ctrl+P (по имени файла), Ctrl+T (по символам — имя функции/класса), Ctrl+B (сложить боковую панель). 4) Блочное выделение и копирование (Ctrl+Alt+двойной клик — слово, Ctrl+D — следующее вхождение): с выделением работает и Ctrl+K.

Слой «контекст» (что ИИ видит). 5) Открытый файл — уже контекст: Cursor сам кладёт в запрос активный буфер, поэтому «о чём спрашиваешь — то и открываешь». 6) @-упоминания — явный контекст: @File, @Folder, @Codebase, @Web, @Docs (подробно — урок 7). 7) Правила проекта (.cursorrules / .cursor/rules) — постоянный контекст, который не надо повторять (урок 6). 8) Правило «трёх файлов»: если задача не описывается в одном предложении — она не задача, а проект; разбей её на задачи, каждая из которых трогает не больше трёх файлов.

Слой «агенты». 9) Задача агенту — в формате «контекст — цель — критерий»: «(в forms.js) сделай валидацию поля email; критерий: пустой и не-email показывают ошибку под полем». Один абзац — и агент не гадает. 10) Дифф до принятия: у агента всегда есть «отменить всё» (revert) — пользуйся без жалости: reverted-задача дешевле, чем починка «почти правильной». 11) «Агенту — скучное, себе — интересное»: рутину (каркас, связки, тесты) отдавай агенту, архитектурные решения оставляй себе — агенту доверяй исполнение, а не проектирование. 12) Терминал — часть агента: агент сам запускает команды (npm, git, тесты); не переключайся на терминал для «быстрого проверить» — попроси агента: он и запустит, и прочитает вывод.

Общий принцип всех двенадцати: сократить «переключения». Каждое переключение (мышь, вкладка, окно, контекст) стоит 5–20 секунд; суммарно за день это часы. Лайфхаки — это не «быстрее нажмать», а «не переключаться».

TIP: не внедряй 12 сразу: выбери 5 (рекомендую: Esc-всё, Ctrl+P/T, правило трёх файлов, формат «контекст — цель — критерий», revert без жалости) и держи их неделю. Остальные подберутся сами, когда первые станут рефлексом.

NOTE: часть привычек зависит от версии (клавиши, названия команд): если в твоей сборке что-то «не там» — проверь Keyboard Shortcuts и доки. Логика (почему это работает) от версии не зависит.

## Пример

```bash
# Практика «одного дня» по проекту «Зерно» — 12 привычек в действии:
# 1. Ctrl+P → styles.css (переход без мыши)
# 2. Ctrl+K на блоке секции → «переименуй классы в БЭМ-стиле .menu__item»
# 3. Esc — не устроило? revert; повторить с уточнением
# 4. Ctrl+Shift+P → composer
# 5. Задача в формате «контекст — цель — критерий»:
#    «В menu.html секция меню: добавь 4 позиции; критерий — каждая с ценой и description-атрибутом»
# 6. Агент сам: правит файл, запускает preview, показывает дифф
# 7. Дифф → принять / revert
# 8. git add -A && git commit -m "menu: 4 позиции с ценами"  (агент предложит текст)
```

Замеры: «каркас секции + контент + коммит» по описанной цепочке занимает 3–5 минут. Тот же объём «вручную + с чатом» — 15–25. Разница — и есть 12 привычек.

## Частые ошибки

WARN: учить 12 лайфхаков «на потом»: без ежедневного применения они исчезают за две недели. Правильно — 5 штук в практику сразу, остальные — по мере надобности.

WARN: «агенту — всё», включая архитектурные решения: агент отлично исполняет, но проектирует он «средне по выборке» — то есть по чужим проектам, не по твоему. Архитектуру и неочевидные решения оставь себе (привычка 11).

WARN: бояться revert: «зачем зря тратили агенту». Revert — не потеря, а сигнал: задача была сформулирована плохо. Пересформулируй и запусти снова — второй запуск почти всегда удаётся.

WARN: мерить «быстрее» количеством принятых правок: метрика — скорость движения проекта (готовые фичи, чистые диффы), а не «агент принятых 47 раз». Много мелких принятых правок с revert'ами — признак плохих формулировок задач.

## Практическое задание

В .cursorrules добавь раздел «Мой процесс»: (1) выбери 5 привычек из 12, которые берёшь в работу (одной строкой каждая — зачем); (2) запиши свой шаблон задачи для агента («контекст — цель — критерий» в твоих словах); (3) правило revert — в каком случае отменяешь без сожаления. Убери TODO. В следующих уроках (6–9) эти правила будут «сидеть» в файле и попадать в контекст каждого запроса.
