# Режим Agent: передача задач агенту

## Цель

После урока студент сможет: формулировать задачи для агентного режима (Composer/Agent) по проверенной схеме «контекст — цель — критерий», управлять разрешениями агента (команды, файлы, авто-принятие) и читать дифф так, чтобы ловить лишнее до принятия.

## Теория

Агентный режим — это другой способ работы, а не «крупная кнопка». Чат отвечает словами, а агент действует: читает файлы, правит несколько сразу, запускает команды в терминале и возвращает готовый результат. Качество агентной работы на 80% определяется тем, как ты её управляешь: формулировкой задачи, разрешениями и ревью диффа. Три этих рычага и разбираем.

Формулировка. Рабочая схема — три строки: контекст (где и о чём), цель (что сделать, глаголом), критерий (как поймём, что готово). Пример: «Контекст: секция меню в menu.html и стили в styles.css. Цель: добавь 4 позиции с ценами. Критерий: каждая карточка — название, описание, цена; сетка 2×2; мобильная версия — колонка». Без критерия агент решает сам, когда «готово» — и «готово» у него и у тебя разные. С критерием — приёмка по чек-листу: либо всё есть, либо нет.

Разрешения. Агент действует в песочнице с правилами. Команды терминала — по умолчанию с подтверждением (агент хочет запустить npm run build — ты нажимаешь Enter); файлы — агент правит те, что считает нужными (дифф покажет, какие именно). Настройки разрешений: (1) auto-accept — принимать правки файлов автоматически (для доверенной рутины: «переименуй классы», «обнови цены в JSON»); (2) список команд — какие команды запускать без подтверждения (npm run, git status), а какие — с подтверждением (git push, npm publish); (3) «план» перед выполнением — агент сначала показывает план (какие файлы тронет, какие команды запустит), и только потом делает. Для новых проектов включай «план» — это страховка от «агент уехал в сторону».

Дифф. Результат агента — набор правок по файлам. Чтение диффа — отдельный навык: (1) сначала — список файлов (агент тронул то, что обещал?); (2) потом — каждая правка (то, что просили + мелочи); (3) искать «лишнее» — правки, которые агент «добавил сам» (очистка кода, «улучшение» имен, удаление «лишних» строк). Лишнее — не всегда плохо (иногда агент реально убрал мусор), но принимать его нужно осознанно, а не вместе с основным. Кнопка revert (отменить всё) — твой друг: откат задачи дешевле, чем починка «почти правильной».

Масштаб задач. Агенту — задачи, а не проекты: одна задача = 1–3 файла, 10–50 строк правок, проверяемый критерий. «Сделай мне сайт» — не задача (а проект — см. урок 18: как его разбивать). «Добавь секцию галереи с 6 фото и адаптивной сеткой» — задача. Правило трёх файлов (урок 5) работает и для агента: больше трёх файлов — разбей на две задачи.

TIP: держи «золотую фразу» для задач-повторов: «Перед выполнением покажи план (файлы + команды), после — сводку по критериям». Одна фраза — и агент становится предсказуемым: план до, отчёт после, дифф посередине.

NOTE: набор разрешений и названий режимов меняется от версии к версии (в новых сборках «Agent mode» объединяет Composer и облачных агентов, разрешения — в настройках). Три рычага — формулировка, разрешения, дифф — постоянные: они работают и в 1.x, и в 2.x, и в следующих.

## Пример

```bash
# Задача по схеме «контекст — цель — критерий» (в Agent mode):
# Контекст: index.html (секция hero), styles.css.
# Цель: добавь кнопку «Заказать» в hero, ведёт на секцию меню.
# Критерий: кнопка с классом .btn--primary, якорь #menu, hover-состояние;
#           мобильная версия — на всю ширину.
#
# Агент: план (2 файла, без команд) → правки → дифф.
# Проверка по критериям: класс есть? якорь есть? hover есть? мобильная?
# Всё есть → принять. Нет → revert или уточнить задачу.

# Команда, которую агент сам предложит (с подтверждением):
npm run preview   # посмотреть результат в браузере
```

Смотри на последовательность: план → правки → критерии → принять/revert. Если пропустил план и сразу увидел 5 изменённых файлов — это сигнал: задача была расплывчатая, а не «агент плохой».

## Частые ошибки

WARN: задачи без критерия: «сделай секцию контактов» — и ждать «как получится». Критерий — 20 секунд на формулировке, которые экономят цикл «не то — переделай». Без критерия агент и ты каждый раз договариваете заново.

WARN: auto-accept на «всё подряд»: авто-принятие — для доверенной рутины (переименования, генерация контент-заглушек). На архитектурных правках auto-accept — путь к «агент уехал, а я заметил через час».

WARN: не читать дифф «потому что доверяю»: доверие — хорошо, но приёмка по диффу — это и есть контроль качества. 30 секунд на дифф дешевле, чем 30 минут на «почему меню сломалось».

WARN: одна задача на полпроекта: «сделай лендинг целиком» в одном промпте — агент сделает «средний лендинг» (по чужим примерам, не по твоим правилам). Разбей: hero → меню → галерея → контакты → сборка (так мы идём в уроке 18).
