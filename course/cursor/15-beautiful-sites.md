# Практика: три подхода к красивым сайтам

## Цель

После урока студент сможет: объяснить три рабочих подхода к «красивому» сайту в Cursor (по референсу, по описанию, по дизайн-токенам) и для каждой задачи «Зерно» выбрать правильный, а не «пробовать все и смотреть».

## Теория

«Сделай красиво» — худший промпт в мире: «красиво» у каждого своё, и ИИ будет «красиво» по средней по выборке (то есть — по чужим сайтам, не по твоему). Красота — это не «прилагательное», а «набор решений»: палитра, типографика, отступы, сетка, анимации. И есть три рабочих способа эти решения «донести» до Cursor.

Подход 1 — по референсу (изображение/сайт). Даёшь ИИ «образец»: скриншот сайта, который «вот так», URL (@Web), Figma (MCP, урок 10). ИИ «видит» референс и переносит: палитру, типографику, композицию. Сильная сторона: скорость («за 10 минут — сайт как такой-то»). Слабая: «копия» (иногда слишком близкая — юридический риск), и «дух» референса не переносится (переносятся «цвета и шрифты», а не «почему это работает»). Когда: «нужно быстро», «есть конкретный образец».

Подход 2 — по описанию (текст). Описываешь «на словах»: «тёплые тона, крупная типографика, много воздуха, минимализм, ощущение ручной работы». ИИ интерпретирует. Сильная сторона: «свой» результат (не копия). Слабая: «размытость» (описание «красивый минимализм» — это 10 разных сайтов). Когда: «свой стиль», «есть ощущение, но нет образца». Лайфхак: описание = «дизайн-бриф» (5–10 строк: аудитория, настроение, палитра (хотя бы «тёплая/холодная»), типографика («крупная/воздушная»), отсылки («в духе X, но без Y»)) — и результат «в точку» чаще, чем «красиво».

Подход 3 — по дизайн-токенам (точные значения). Дашь ИИ «цифры»: палитра (hex), шрифты (имена + размеры), отступы (scale: 4/8/16/32), сетка (колонки, gutter). ИИ «работает по чертежу». Сильная сторона: точность и консистентность (каждая секция — «из одного набора»). Слабая: нужны токены (и «вкус» в их выборе — «цифры» не делают «красиво» сами по себе). Когда: «сайт растёт» (много секций, много «авторов» — людей и агентов), «нужна консистентность».

Как выбрать. (1) «Быстро + есть образец» → референс. (2) «Свой стиль + есть ощущение» → описание (бриф). (3) «Растёт + нужна консистентность» → токены. На практике — «комбо»: начинаешь с референса/описания (быстрый «черновик»), а когда сайт «встаёт» — выносишь токены (урок «дизайн-система») и дальше работаешь «по чертежу». «Зерно» (урок 15–18): референс → бриф → токены (по мере роста).

Роль .cursorrules. Дизайн-решения (какой бы подход ты ни выбрал) «живут» в правилах: палитра, шрифты, отступы — в разделе «Дизайн» (тогда каждая новая секция «из одного набора», а не «как в прошлый раз»). Без правил — «каждая секция — новый сайт».

Глаз + MCP-браузер. Красота — «видимое» (урок 14): вайбкодинг здесь — основной режим. Цикл: «сделай секцию» → preview (MCP-скриншот) → «поправь» → preview. Через 2–3 итерации секция «в точку». Без MCP — «открой браузер руками» (медленнее, но работает).

TIP: держи «дизайн-папку» в репозитории: референсы (скриншоты), бриф (md-файл), токены (css-переменные). Агент «видит» папку (@Folder) — и результат «из одного набора». Папка = «дизайн-память» проекта.

NOTE: «красиво» — subjective, и ИИ «красиво» = «среднее по выборке». Поэтому «красота» — это «набор решений» (палитра/типографика/отступы), а не «прилагательное в промпте». Решения — в токенах (или в брифе), «красиво» — в промпте не работает.

## Пример

```bash
# «Зерно»: три подхода по порядку.
# 1. Референс: «Смотри на [скриншот кофейни] — возьми палитру и
#    типографику, сделай hero в этом духе» → черновик за 5 минут.
# 2. Бриф: «Тёплые тона (#2A211C, #C8A27A, #F5EFE6), Playfair Display
#    + Inter, много воздуха, минимализм, ощущение ручного» → «свой» стиль.
# 3. Токены (когда секций стало 5+):
#    :root { --bg: #F5EFE6; --ink: #2A211C; --accent: #C8A27A;
#            --font-display: 'Playfair Display'; --font-body: 'Inter';
#            --space-1: 4px; --space-2: 8px; --space-4: 32px; }
#    → каждая новая секция «из одного набора».
```

Смотри на «комбо»: референс дал «направление» (быстро), бриф — «свой стиль», токены — «консистентность на рост». Три подхода — три фазы жизни сайта.

## Частые ошибки

WARN: «сделай красиво» без решений: «красиво» — прилагательное, а не набор решений. Палитра/типографика/отступы — в промпте (или в правилах) — и результат «в точку».

WARN: референс = «копия»: «сделай как X» — и получается X (с другим логотипом). «Возьми палитру и типографику X, но композицию — свою» — и результат «в духе», а не «копия».

WARN: токены без «вкуса»: цифры не делают «красиво» сами. Токены — «чертёж», «красота» — в «вкусе» (в выборе цифр). Если токены «не те» — поправь цифры (не секции).

WARN: «каждая секция — новый промпт» (без правил): без .cursorrules (раздел «Дизайн») — каждая секция «как в прошлый раз» (а «прошлый раз» — другой промпт). Правила = «одна дизайн-память».

## Практическое задание

Заполни в .cursorrules раздел «Дизайн»: (1) подход, который выбираешь для «Зерно» (референс/бриф/токены — и почему); (2) палитра (3–5 hex) + шрифты (2) + отступы (scale); (3) «дизайн-папка» (что в ней лежит: референсы, бриф, токены).
