# Git и коммиты с Cursor

## Цель

После урока студент сможет: объяснить, как Cursor интегрируется с git (встроенный Source Control, генерация сообщений, агентные коммиты), настроить «дисциплину коммитов» для проекта с ИИ-агентами и разобрать типичные проблемы (агент забыл коммитнуть, конфликт параллельных агентов, «мусорные» коммиты).

## Теория

Git — «скелет» работы с агентами. Каждый агент (локальный, облачный) работает через git: делает правки, коммитит (или собирает PR), ты ревьюишь и сливаешь. Поэтому git-дисциплина в Cursor-команде важнее, чем в «человеческой»: количество правок растёт в разы, и без ясной истории коммитов репозиторий превращается в «кучу диффов непонятно от кого».

Что даёт Cursor «из коробки». (1) Встроенный Source Control (как в VS Code): ветки, статус файлов, staging, коммиты — всё в панели. (2) Генерация сообщений: кнопка «сообщение» (или агент в Composer) смотрит на staged-дифф и предлагает commit message — это экономит 30–60 секунд на каждый коммит и, что важнее, выравнивает стиль сообщений (агент пишет в одном формате). (3) Агентные коммиты: агент в Composer сам коммитит после задачи (если разрешено) — с сообщением, описывающим задачу. (4) Cloud-агенты работают «через» git: ветка → правки → коммиты → PR (урок 9). Git для них — не «дополнительный шаг», а среда.

Дисциплина. (1) Формат сообщений: «тип: что сделали» (feat: секция галереи; fix: валидация email; refactor: вынес валидацию в модуль). Агента «научи» формату правилом в .cursorrules (урок 6) — и все сообщения (человеческие и агентные) будут в одном стиле. (2) Размер коммита: один коммит = одна логическая единица (одна фича, один фикс, одна чистка). «Коммит на 300 строк трёх разных тем» — это три коммита. (3) Частота: чаще, чем «раз в день». С агентами «опасные окна» (время между коммитами) укорачиваются: агент сделал — закоммитили — следующая задача. (4) Ветки: main — стабильный (только слитое), задачи — в ветках (локальный агент — в рабочей ветке, облачный — в своей, PR-слияние).

Проблемы и лечение. «Агент забыл коммитнуть» — включи «коммит после задачи» в правилах (или делай вручную: staging + сообщение). «Конфликт параллельных агентов» — границы областей (урок 9): один агент — одна область; если конфликт всё же случился — git merge, ручной разбор (агент поможет: «разбери конфликт в styles.css, сохрани обе секции»). «Мусорные коммиты» («fix», «wip», «test») — правило формата + «не коммитить без описания»; если «wip» — честно (это нормально), но с пометкой.

Отдельно — revert как инструмент. С агентами revert (откатить коммит) — не «проблема», а «кнопка»: агент сделал «не то» → git revert (или в UI: «отменить коммит») → переформулировать задачу → запустить снова. Это дешевле, чем «чинить поверх». Привычка: каждое «не то» — revert, а не «ну, подправим».

TIP: держи в .gitignore то, что агенту «не надо видеть» (локальные конфиги, кэш, build-артефакты): индекс кодовой базы и диффы не должны «засоряться» мусором. Чистый репозиторий = чистый контекст агента.

NOTE: Cursor не заменяет git (нет «магии слияний»): весь git — стандартный, как в терминале. Если ты уверен в git — в Cursor ты уверен на 100%; если нет — урок 11 курса по git (или любой базовый) закрывает пробел.

## Пример

```bash
# Цикл «задача → коммит» с агентом:
# 1. Агент (Composer) сделал секцию галереи.
# 2. Дифф принят. Коммит:
git add -A
git commit -m "feat: секция галереи (6 фото, адаптивная сетка)"

# Агент предложил сообщение сам (по staged-диффу) — ты отредактировал и принял.

# Параллельный облачный агент (урок 9) — в своей ветке:
git fetch origin
git log --oneline origin/agent/mobile-adapt -3
# → PR → ревью → merge:
git merge --no-ff origin/agent/mobile-adapt

# «Не то» → revert, а не «чинить поверх»:
git revert HEAD
# (переформулировать задачу и запустить агента снова)
```

Смотри ритм: задача → дифф → коммит → следующая. «Опасное окно» (время между коммитами) — минуты, а не часы: revert дешёвый, история чистая.

## Частые ошибки

WARN: коммиты «раз в день» на 500 строк: с агентами «окно между коммитами» = потерянный контекст (агент «что я тут делал?»). Коммит — после каждой логической задачи, а не «в конце дня».

WARN: один формат сообщений «на глаз»: агент пишет «Update styles.css», ты — «пофиксил вёрстку». Правило формата в .cursorrules — и стиль выравнивается сам.

WARN: «чинить поверх» вместо revert: «ну, подправим» — путь к коммитам «fix fix fix» и потере истории. Revert — 5 секунд, и задача чистая.

WARN: параллельные агенты в одной ветке: конфликт слияний = потеря времени. Границы: один агент — одна ветка/область (урок 9). Merge-конфликт — норма, но его можно не иметь.
