# Вайбкодинг: что это и как начать

## Цель

После урока студент сможет: объяснить, что такое вайбкодинг (vibe coding) и чем он отличается от «классической» разработки с ИИ-помощником, сформулировать правила, при которых вайбкодинг работает (а не превращается в «сайт, который работает, пока не смотришь»), и запустить первый вайб-цикл по проекту.

## Теория

Вайбкодинг — термин, популяризованный Энди Карпаши в начале 2025-го (и быстро ставший общим): способ разработки, где ты «включаешь вайб» — описываешь, чего хочешь (на языке, без кода), и даёшь ИИ сделать; код читаешь мало или не читаешь вообще, ориентируясь на результат (как выглядит, как работает). Контраст с «классикой + ИИ»: там ты пишешь код (или ревьюишь каждый дифф), а ИИ — помощник; во вайбкодинге ты — «режиссёр/продюсер», а ИИ — «команда из исполнителей».

Важно: вайбкодинг — не «лень» и не «хуже классики». Это другой режим с другими правилами. Где он работает: (1) прототипы и внутренние инструменты (там, где «сломалось — переделаем»); (2) фронтенд/дизайн-макеты (результат виден глазом — «не то» видно сразу); (3) эксперименты («а что, если сделать так?» — час, не неделя). Где он опасен: критичная логика (деньги, безопасность), большие команды (когда код читают другие), «навсегда»-системы (долголетние проекты с SLA).

Правила, при которых вайбкодинг работает (а не «работает, пока не смотришь»): (1) результат виден — фронтенд, визуал, интерактив: «не то» видно за секунды (и это главный критерий «можно ли вайбкодить эту задачу»); (2) маленькие циклы — не «сделай мне сайт», а «сделай hero-секцию» → глядишь → «поправь отступы» → глядишь; (3) правила проекта ( .cursorrules ) — твой «контракт» с ИИ: стек, стиль, запретное (урок 6); (4) git-частые коммиты — каждый «не то» = revert (урок 11); (5) тесты-страховки на «чистых» функциях (урок 12) — вайбкодинг без тестов на логике = лотерея.

Чем вайбкодинг отличается от «агентов». Агент (уроки 8–9) — «исполнитель с контролем»: задача с критерием, дифф, приёмка. Вайбкодинг — «режиссёр без строгого сценария»: короткие итерации «сделай — гляну — поправь». На практике они смешиваются: вайбкодинг — это «агент + маленький цикл + глаз вместо критериев». Разница — в размере цикла и в том, что ты проверяешь (глазом, а не по чек-листу).

Что «глаз» видит (и не видит). Глаз отлично видит: вёрстку, цвета, отступы, анимации, UX-«неудобно». Глаз плохо видит: утечки памяти, гонки (race conditions), производительность на больших данных, безопасность. Поэтому: вайбкодинг — для «видимого» (фронтенд), классический контроль — для «невидимого» (логика). «Зерно» (лендинг) — 100% «видимое»: вайбкодинг здесь — основной режим.

TIP: первый вайб-цикл — на «мелочи» (изменение отступов, цвета, текста), не на «архитектуру». Через 3–5 циклов «сделал — глянул — поправил» ты почувствуешь ритм (и поймёшь, где глаз видит, а где — нет).

NOTE: «вайбкодинг» — не только про Cursor (работает в Claude Code, Copilot, любой агентной среде) и не только про фронтенд (есть «вайб-бэкенд» для прототипов). Но Cursor — среда, где цикл «сделал — глянул» быстрее всего: preview встроен, браузер — через MCP (урок 10), revert — одна кнопка.

## Пример

```bash
# Вайб-цикл по «Зерну» (hero-секция):
# 1. «Сделай hero: название кофейни, слоган, кнопка «Заказать»,
#    фото кофе на фоне (тёплые тона)» → агент сделал → preview.
# 2. Гляжу: «фон слишком тёмный, кнопка теряется».
#    «Сделай фон светлее, кнопку — крупнее и контрастнее» → preview.
# 3. Гляжу: «отступы сверху слишком большие, слоган — мельче».
#    «Уменьши padding-top, слоган — 1.2em» → preview.
# 4. Гляжу: «вот это оно». Коммит (урок 11):
git add -A && git commit -m "feat: hero-секция (вайб-цикл, 3 итерации)"
```

Смотри на размер итераций: каждая — одна-две фразы, результат виден сразу, «не то» — revert (или следующая итерация). Три итерации — и секция «готова для глаз».

## Частые ошибки

WARN: вайбкодить «невидимое»: логику, безопасность, производительность — «глаз» их не видит. Вайбкодинг — для «видимого» (фронтенд, UX); «невидимое» — по классике (тесты, диффы, критерии).

WARN: большие циклы: «сделай мне лендинг целиком» → «ну, не то» → revert → «сделай ещё раз». Маленькие циклы (секция за секцией) — и «не то» дешевле, и направление ясне.

WARN: вайбкодинг без .cursorrules: без «контракта» ИИ каждый раз «придумывает» стек/стиль заново — и «вайб» превращается в «каждый раз по-разному». Правила (урок 6) — фундамент вайбкодинга.

WARN: «работает — не трогаю» на критичных местах: вайб-код без тестов на логике — «работает, пока не смотришь». «Чистые» функции (валидация, расчёты) — с тестами (урок 12), даже во вайб-режиме.

## Практическое задание

Заполни в .cursorrules раздел «Вайб-режим»: (1) список задач «Зерно», которые будешь вайбкодить (2–3, «видимые»); (2) размер цикла (сколько итераций на задачу — твоё число); (3) правило «глаз vs критерии» (что проверяешь глазом, что — по чек-листу).
