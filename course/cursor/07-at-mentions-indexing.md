# @Файлы, @директории, @docs и индексация кодовой базы

## Цель

После урока студент сможет: объяснять, как Cursor строит и использует индекс кодовой базы (semantic search), подбирать правильный контекст для запроса (@File, @Folder, @Codebase, @Web, @Docs) и перестать получать «общие» ответы, которые «правильно звучат, но не про мой проект».

## Теория

«Общий» ответ — главный враг работы с ИИ в редакторе. Причина почти всегда одна: агенту не показали, о чём говорить. Cursor решает это двумя механизмами: индексом кодовой базы и @-упоминаниями. Понимание обоих — рубеж между «ИИ гадает» и «ИИ работает».

Индекс кодовой базы — это «память о всём проекте». При открытии репозитория Cursor (на локальной машине, через облако) разбивает код на блоки, превращает их в векторы (эмбеддинги) и хранит; при запросе агент семантически ищет релевантные блоки — не по ключевым словам, а по смыслу: «валидация формы» находит не только файлы с именем validate, но и handler-обработчики, где валидация де-факто живёт. Индекс обновляется по мере правок (фоновая пересборка изменённых файлов), поэтому в «живом» проекте семантический поиск остаётся точным. Масштаб: для проектов в десятки тысяч файлов индексация занимает минуты; для гигантских монорепо — дольше, и тут на помощь приходят фильтры (каталоги, файлы, которые «вне индекса»).

@-упоминания — явный контекст: то, что ты сам кладёшь в запрос. (1) @File — конкретный файл целиком: «@menu.html добавь сюда подпункты». (2) @Folder — каталог целиком (или его семантическую выжимку): «@src пересобери структуру». (3) @Codebase — саму семантическую базу: «@Codebase где у нас обработка ошибок?». (4) @Web — URL: «@Web адрес-дока-браузера объясни, как работает этот API, и примени у нас». (5) @Docs — подключённые внешние документы (например, PDF/доки компании): их можно загрузить в проект и упоминать, как файлы. Разница между «агент сам поищет» и «ты показал файл» — в определительности: показанный файл гарантированно в контексте, «сам поищет» — в контексте, если поиск нашёл.

Правило контекста (запомни одной фразой): чем конкретнее задача — тем конкретнее контекст. «Переименуй класс» — @File (и то не нужно: активный файл уже в контексте). «Пересобери модуль» — @Folder. «Найди, где это устроено» — @Codebase. «Как это работает в библиотеке X» — @Web. «Что у нас в политике дизайна» — @Docs.

Отдельный класс ошибок — «контекст наоборот»: показать агенту 5 файлов, хотя задача в одном. Каждый файл в контексте — это токены и «размывание внимания»: агент начнёт «улучшать» то, что ты не просил. Минимальный достаточный контекст — не скупость, а точность.

TIP: перед важным запросом посмотри, что агент уже видит (панель контекста в чате: активный файл, @-упоминания, правила). Если в контексте нет нужного файла — добавь @File. Это 2 секунды, которые экономят 10 минут «перевопросов».

NOTE: @Web и @Docs работают через облако (дока подгружается и индексируется): если интернета нет — будут только локальные контексты. Для офлайн-работы держи нужные куски доков копиями в репозитории (docs/notes) — тогда они в @Codebase.

## Пример

```bash
# Практика на «Зерне»: та же задача в трёх вариантах контекста.
# 1) Без контекста:
#    «Почему форма не отправляется?» → «проверь submit-обработчик, fetch…» (общее)
# 2) С @File:
#    «@main.js форма не отправляется, в консоли ошибка TypeError — найди»
#    → агент видит код и отвечает: «строка N: form.addEventListener…» (точное)
# 3) С @Codebase:
#    «@Codebase где у нас все обращения к API и как обрабатываются ошибки?»
#    → агент перечисляет файлы и паттерны (карта, а не предположение)
```

Сравни три ответа: первый — «правильно звучит», второй — «вот строка», третий — «вот карта проекта». Разницу делает не модель, а контекст.

## Частые ошибки

WARN: «общие» ответы винить в модели: 80% «ИИ не понимает мой проект» — это «ИИ не видел мой проект». Сначала контекст (@-упоминания, правила), потом — выводы о качестве.

WARN: тащить в контекст полпроекта «на всякий»: каждый лишний файл — токены и размывание внимания. Минимальный достаточный контекст; «на всякий» — антипаттерн.

WARN: верить семантическому поиску вслепую: эмбеддинги находят «похожее по смыслу», а не «единственно верное». На критичные задачи («найдите все места, где парсится дата») добавляй текстовый поиск (Ctrl+Shift+F) — два инструмента, один результат.

WARN: держать устаревшие @Docs: подключённые PDF/доки, которые никто не обновляет, — источник «правильных советов из прошлого». Док в контексте = док в репозитории: с датой, с владельцем, с периодическим обновлением.

## Практическое задание

Заполни в .cursorrules раздел «Контекст»: (1) список @-упоминаний, которые ты используешь (каждое — одной строкой: когда); (2) 3 «стандартных запроса» по проекту «Зерно» с правильным контекстом (по одному на @File, @Codebase, @Web); (3) правило минимального контекста — как ты решаешь, сколько файлов показывать. Убери TODO: с этого урока «общие» ответы — редкость.
