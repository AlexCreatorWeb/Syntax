# Финальный проект: сайт с нуля на Cursor (без ручного кода)

## Цель

После урока студент сможет: собрать лендинг «Зерно» целиком на Cursor — от пустого каталога до рабочего сайта — используя всё, что пройдено (правила, агенты, MCP, git, тесты, вайбкодинг, экономику), и держать «ручное» написание кода на уровне «нулевых» строк.

## Теория

Финал курса — «Зерно» целиком: лендинг кофейни из 6–7 секций (hero, меню, галерея, «о нас», контакты, футер), с рабочей формой, адаптивом и базовыми тестами. Сценарий — «сайт без ручного кода»: ты не пишешь строки (или почти не пишешь), ты «руководишь» — ставишь задачи, ревьюишь диффы, смотришь preview. Всё, что за 17 уроков «накопилось» в .cursorrules (правила, инструменты, агенты, дизайн, git, тесты, отладка, экономика), здесь «работает».

Разбивка (правило трёх файлов + «маленькие» циклы, уроки 8/14): не «сделай сайт», а «последовательность» задач, каждая 1–3 файла, с критерием. Для «Зерно»: (1) каркас (index.html: skeleton секций, styles.css: токены из урока 15); (2) hero (референс/бриф → вайб-цикл, урок 14); (3) меню (контент: позиции с ценами, сетка); (4) галерея (6 фото, адаптивная сетка); (5) «о нас» (текст + фото); (6) контакты + форма (валидация — урок 12); (7) адаптив (мобильная версия — облачный агент, урок 9); (8) тесты (Vitest: валидация + smoke-структура); (9) «полировка» (вайб-циклы: отступы, цвета, анимации). Каждая задача — «отдельный» коммит (урок 11).

«Смешанные» режимы (главный «инсайт» курса): разные задачи — «разные» режимы (урок 3): печать/контент — Tab; мелкие правки — Ctrl+K; «красивое» — вайбкодинг (урок 14); «большое» (адаптив, тесты) — облачный агент (урок 9); «умное» (валидация, «не то») — агент + отладка (уроки 8/13). «Один» режим на «всё» — «дорого» (экономика, урок 17) и «медленно». «Смешанный» подход — «оптимальный».

«Контроль» без «ручного» кода. «Без ручного кода» — не «без контроля» (иначе «работает, пока не смотришь», урок 14). Контроль — «на трёх» уровнях: (1) дифф (что «изменилось» — урок 8); (2) preview (что «видит» пользователь — MCP-браузер, урок 10); (3) тесты (что «не сломалось» — урок 12). «Три «да»» — «коммит». Это и есть «руководство» (вместо «ручного» кода).

«Критерий» готовности (для «Зерно»): (1) 6–7 секций «на месте» (hero, меню, галерея, «о нас», контакты, футер); (2) форма «валидирует» (email, имя); (3) «адаптив» (мобильная версия «не ломается»); (4) npm test «зелёный»; (5) консоль «чистая» (нет ошибок); (6) git-история «чистая» (коммиты по задачам, «не» «wip»). «Шесть «да»» — «сайт готов».

«После» курса (что «дальше»). «Зерно» — «основа» (и «портфолио»). «Дальше»: (1) «бэкенд» (форма «уходит» в API — курсы по Node/Mongo/Postgres); (2) «деплой» (статика — «в любом» хостинге; «с API» — Vercel/Render); (3) «контент» (реальные фото, тексты, «SEO»); (4) «аналитика» (что «кликают»). Курс по Cursor «дал» «навык» (руководить агентами); «продолжение» — «в других» курсах (бэкенд, «специализация»).

TIP: «фиксируй» «процесс» (скриншоты preview на «каждой» секции, git-log): «Зерно» — «портфолио» (и «доказательство» навыка). «Как» ты «сделал» (с агентами, «без» ручного кода) — «самый» «сильный» «аргумент» (на «собесовании»/в «портфолио»).

NOTE: «сайт без ручного кода» — «не «магия»», а «навык» (задачи, диффы, git, тесты, preview). «Магия» — «в навыке» (в «тебе»), а не «в инструменте». Инструмент «поменяешь» (TRAE/Windsurf/Copilot — урок 16) — «навык» «останется».

## Пример

```bash
# «Зерно»: «сборка» (9 задач, «смешанные» режимы, «без» ручного кода).
# Каркас → git init, .cursorrules (из «курса»), package.json (Vitest).
git init && git add -A && git commit -m "chore: каркас «Зерно»"

# Задача 2 (hero, вайб-цикл): «Сделай hero: название, слоган, кнопка,
#  тёплые тона» → preview → 2–3 итерации → коммит.
git commit -am "feat: hero (вайб-цикл)"

# Задача 7 (адаптив, «облачный» агент, урок 9):
# «Сделай адаптив под мобильные: брейкпоинты 480/768/1024, меню — бургер»
# → облачный агент → PR → ревью → merge.
git merge --no-ff origin/agent/mobile-adapt

# Задача 8 (тесты): «Vitest: validateEmail + checkMenuStructure;
#  критерий — npm test зелёный» → npm test → коммит.
npm test   # 4 passed

# Итог: 6–7 секций, форма, адаптив, тесты, чистый git-log. «Без» ручного кода.
```

Смотри на «архитектуру» дня: «мелкие» правки — Tab/Ctrl+K, «красивое» — вайб, «большое» — облачный агент, «умное» — агент + отладка. «Смешанный» подход — «оптимальный» (и «дешёвый», урок 17).

## Частые ошибки

WARN: «сделай сайт целиком» (одна задача): «полпроекта» в «одном» промпте = «средний» сайт (по «чужим» примерам). «Разбей» (9 задач, «маленькие» циклы) — и «каждая» «в точку».

WARN: «без ручного кода» = «без контроля»: дифф + preview + тесты — «три уровня» (урок 12). «Без» контроля — «работает, пока не смотришь».

WARN: «один» режим на «всё» (только «умные» агенты): «дорого» (урок 17) и «медленно». «Смешанный» (Tab/вайб/агенты по «задачам») — «оптимальный».

WARN: «не зафиксировать» «процесс»: «Зерно» — «портфолио». git-log + скриншоты preview = «доказательство» (и «материал» для «дальше»).

## Практическое задание

Собери «Зерно» (9 задач из «теории»): каркас → hero → меню → галерея → «о нас» → контакты+форма → адаптив → тесты → «полировка». «Критерий»: 6 пунктов «готовности» (секции, форма, адаптив, тесты, консоль, git-log). В .cursorrules — «финальная» версия (все разделы «заполнены», «без» TODO): «Зерно» «готово», «файл» — «готов» (и «переносится» в «следующий» проект). «Поздравляем» — курс «пройден».
