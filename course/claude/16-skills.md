# Skills: переиспользуемые инструкции

## Цель

После урока студент сможет: объяснить, что такое Skills в Claude Code, написать свой Skill (инструкцию для повторяющейся задачи), подключить Skill к проекту, и понимать, какие задачи стоит превращать в Skills, а какие — нет.

## Теория

Skill — это переиспользуемая инструкция: «как делать задачу X». Skill — это файл (markdown), который описывает шаги, критерии успеха, примеры. Когда ты вызываешь Skill, агент «читает» инструкцию и действует по ней. Это не магия — это структура: ты один раз описываешь, как делать задачу, и потом вызываешь Skill, а не повторяешь инструкцию каждый раз. Плюс Skills — «портативность»: Skill можно перенести в другой проект (если задача там тоже повторяется) или поделиться с командой.

Примеры Skills: «Skill: написание тестов для API-функции» (шаги: прочитать функцию, написать тест на success-кейс, на error-кейс, запустить), «Skill: добавление новой страницы в Next.js» (шаги: создать файл в src/app, добавить в nav, написать тест), «Skill: деплой» (шаги: проверить, что тесты зелёные, собрать, задеплоить, проверить в прод). Skill — это «рецепт», а не «магия»: агент всё равно решает, как применить рецепт к твоей конкретной задаче, но шагов он не придумывает.

Написание Skill: markdown-файл с названием, описанием, шагами, примерами. Skill лежит в каталоге проекта (или глобально) и вызывается командой. Агент читает Skill и действует по инструкции. Структура Skill важнее его объёма: чёткие шаги с критерием для каждого — лучше, чем длинное описание «что примерно делать».

Когда Skill оправдан: задача повторяется часто, шаги стабильны, критерий успеха чёткий. Когда не оправдан: задача уникальная или шаги меняются каждый раз. Skill — для повторяющихся, структурированных задач.

Есть и «живые» Skills: Skill, который сам обновляется. Если ты заметил, что шаг в Skill устарел (API сменился, команда переименована) — обнови Skill в тот же день, и в CLAUDE.md отметь дату последнего обновления. Через месяц «живой» Skill — это твоя документация процесса, которая всегда актуальна.

NOTE: Skill — это не «автоматизация», а «инструкция». Агент всё равно действует (читает файлы, правит, запускает команды), но по чёткому плану. Skill не «делает» задачу — он «напоминает» агенту, как делать. Поэтому результат Skill зависит от качества инструкций: если в Skill нет критерия успеха для шага — агент «завершит» шаг, а не проверит его.

TIP: начни с одного Skill — самого повторяющегося. Для большинства проектов это «написание тестов» или «добавление новой сущности». Держи список Skills в CLAUDE.md, чтобы помнить, какие инструкции доступны.

Хороший Skill — это тот, который ты «проверил на себе»: сначала ты описал шаги для себя, потом превратил в Skill, потом попросил агента сделать задачу по Skill и убедился, что результат совпадает с тем, что ты бы сделал сам. Если не совпадает — правь Skill, а не удивляйся агенту. Skill — это твоя инструкция, и её качество определяет результат.

## Пример

```bash
# Skill: tests-for-api (в каталоге .claude/skills/tests-for-api.md)
# # Написание тестов для API-функции
# Шаги:
# 1. Прочитать функцию в src/lib/api.ts
# 2. Написать тест на success-кейс
# 3. Написать тест на error-кейс
# 4. Запустить: npm test -- --testPathPattern=api

# Вызываем Skill
claude
> используй Skill tests-for-api для функции createUser
```

Агент читает Skill и действует по шагам. Не нужно каждый раз повторять инструкцию.

## Частые ошибки

WARN: Skill на уникальную задачу: если задача не повторяется — Skill не окупится. Skill — для повторяющихся задач.

WARN: Skill без примеров: шаги без примеров — это общие слова. Добавь пример: «вот как выглядит тест для функции X». Пример > описание.

WARN: Skill, который устарел: если шаги изменились (перешёл с Jest на Vitest) — обнови Skill. Устаревший Skill опаснее, чем его отсутствие.

WARN: не держать список Skills в CLAUDE.md: забудешь, какие инструкции доступны. CLAUDE.md — твоя памятка.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) зафиксируй свои Skills: какие инструкции, для каких задач, где лежат файлы. Заполни разделы по шаблону и устрани все TODO. И есть приём «Skill из боли»: если ты заметил, что第三次 объясняешь агенту одно и то же — запиши это как Skill. Три объяснения — это уже паттерн, и Skill окупится с четвёртого раза. И если Skill начал «рассыхаться» (шаги перестали сходиться с реальностью) — это сигнал обновить или разбить на два.
