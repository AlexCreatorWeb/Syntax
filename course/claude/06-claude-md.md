# CLAUDE.md: память проекта и правила

## Цель

После урока студент сможет: объяснить, что такое CLAUDE.md и зачем он нужен, написать CLAUDE.md для своего проекта, понять, как агент использует этот файл, и избежать типовых ошибок (слишком много текста, устаревшие правила).

## Теория

CLAUDE.md — это файл-память для агента. Он лежит в корне проекта, и Claude Code читает его в начале каждой сессии. Всё, что написано в CLAUDE.md, становится частью контекста модели: агент «помнит» правила проекта, не нужно объяснять их каждый раз.

Зачем это нужно? Без CLAUDE.md ты каждый раз повторяешь: «у нас тесты на Vitest, запускать через npm test», «не трогай сгенерированные файлы», «все API-функции в src/api». С CLAUDE.md эти правила — в файле, и агент читает их сам. Это экономит время и снижает количество ошибок: модель не «забывает», что у тебя не Jest, а Vitest.

Что писать в CLAUDE.md? Четыре категории. Первая — стек: языки, фреймворки, версии, как запускать dev-сервер и тесты. Вторая — структура: где что лежит (src/api — API-функции, src/components — UI). Третья — правила: как называть файлы, где писать тесты, какие паттерны использовать. Четвёртая — «не трогать»: сгенерированные файлы, конфиги, которые менять нельзя.

Важное свойство: CLAUDE.md читается целиком в начало контекста. Это значит, что он расходует токены на каждую сессию. Слишком большой файл — это лишние токены и лишний шум. Оптимальный размер — до 100 строк: достаточно, чтобы агент понял проект, но не настолько, чтобы занимать весь контекст.

NOTE: CLAUDE.md — не документация для людей. Документация отвечает на вопрос «как устроен проект» — для новых сотрудников. CLAUDE.md отвечает на вопрос «как агенту работать в этом проекте» — для модели. Это разные документы с разной аудиторией. CLAUDE.md можно (и нужно) держать коротким и практичным.

TIP: держи CLAUDE.md живым. Если ты изменил стек (перешёл с Jest на Vitest) — обнови CLAUDE.md в тот же день. Устаревший CLAUDE.md опаснее, чем его отсутствие: агент будет действовать по старым правилам и «упорно» делать всё не так.

Формат CLAUDE.md — это обычный markdown без лишних украшений: заголовки разделов, короткие строки, без таблиц и длинных абзацев. Модель читает его как текст, и ей проще «использовать» чёткий список правил, чем разжёвывать длинные описания. Хороший CLAUDE.md выглядит как конспект: стек — три строки, структура — список каталогов, правила — список пунктов. Если тебе самому сложно найти в файле ответ за пять секунд — агенту будет ещё сложнее.

Есть и нюанс иерархии: CLAUDE.md в корне читается всегда, а CLAUDE.md в подкаталогах — когда агент работает с файлами этого каталога. Это полезно для больших проектов, где разные части устроены по-разному (frontend и backend в одном репозитории). Но для обычного проекта одного корневого файла хватает — не усложняй иерархию без нужды.

## Пример

```bash
# CLAUDE.md лежит в корне проекта
cat CLAUDE.md

# Пример содержимого:
# # Трекер привычек
# Стек: Next.js 15, TypeScript, PostgreSQL (Prisma), Vitest
# Запуск: npm run dev (порт 3000), тесты: npm test
#
# Структура:
# src/app — страницы (App Router)
# src/lib — утилиты и Prisma-клиент
# src/components — UI-компоненты
#
# Правила:
# - Тесты рядом с кодом: __tests__-папки
# - Все API-функции — в src/lib/api.ts
# - Не трогать: prisma/schema.prisma без обсуждения
```

Агент читает этот файл в начале сессии и сразу знает, как работать.

## Частые ошибки

WARN: CLAUDE.md на 500 строк: это документация, а не память. Агент читает его целиком на каждой сессии — лишние токены и шум. Держи до 100 строк.

WARN: устаревшие правила: если в CLAUDE.md «тесты на Jest», а у тебя Vitest — агент будет запускать npm run jest и падать. Обновляй файл при изменении стека.

WARN: правила без конкретики: «пиши хороший код» — это не правило. «Тесты в __tests__-папках рядом с кодом» — это правило. Конкретика > общие слова.

WARN: CLAUDE.md в каждом каталоге: достаточно одного файла в корне. Если проект большой и разные части устроены по-разному — можно добавить CLAUDE.md в подкаталоги, но это продвинутый приём.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) заполни разделы по шаблону: стек, структура, правила, «не трогать». Устрани все TODO. Цель — до 100 строк, которые агент будет читать в начале каждой сессии. И запомни правило: CLAUDE.md читает не только агент, но и ты — когда возвращаешься к проекту через неделю. Честно: если файл удобен тебе, он будет удобен и модели. И если файл начал «раздуваться» — это сигнал: часть правил стоит вынести в отдельные Skills (см. урок 16), а в CLAUDE.md оставить только «ядро».
