# Хуки: автоматизация действий агента

## Цель

После урока студент сможет: объяснить, что такое хуки в Claude Code, написать хук на «после каждого коммита», настроить хук на форматирование кода, и понимать, какие действия стоит автоматизировать, а какие — нет.

## Теория

Хуки — это автоматизация: «когда агент сделал X, автоматически сделай Y». Хук — это функция (или bash-команда), которая вызывается в определённый момент работы агента. Примеры хуков: «после каждого коммита — запустить тесты», «после каждой правки файла — отформатировать через prettier», «перед запуском команды — проверить, что не git push». Формально хуки работают и «в обратную сторону»: не агент вызывает хук, а хук реагирует на события агента — но эффект тот же: рутина автоматизирована.

Зачем хуки? Чтобы не повторять одно и то же. Если после каждого коммита ты запускаешь тесты — сделай хук: агент закоммитит, и хук сам запустит тесты. Если после каждой правки ты форматируешь код — хук на форматирование. Хуки снимают рутину и снижают шанс «забыть». Есть и более тонкая польза: хук делает процесс предсказуемым для самого агента — он «знает», что после коммита последуют тесты, и учитывает это в планировании.

Настройка хука: в конфиге Claude Code указываешь событие (commit, file-change, pre-command) и команду (npm test, npx prettier --write). Хук вызывается автоматически в момент события. Если хук падает (тесты красные) — агент видит ошибку и может исправить. Важно: хук — это bash-команда, и у неё есть timeout: если команда висит больше лимита, хук прерывается, и агент видит сбой, а не результат.

Когда хуки оправданы: действие повторяется часто и имеет чёткий критерий успеха (тесты прошли, код отформатирован). Когда не оправданы: действие редкое или субъективное (ревью кода, выбор архитектуры) — для таких действий хук не даст больше, чем ты сам. Поняв эту границу, ты перестанешь «хукать» то, что лучше сделать руками.

NOTE: хуки — это автоматизация, а не контроль. Хук на «проверку кода» не заменит ревью: он проверит то, что проверяет (тесты, форматирование), но не «качество дизайна». Не жди от хуков больше, чем они могут дать.

TIP: начни с одного хука — самого полезного. Для большинства проектов это «после коммита — тесты». Добавляй хуки по мере надобности. Держи список хуков в CLAUDE.md, чтобы помнить, что автоматически происходит.

Есть и «обратные» хуки: pre-события (перед коммитом, перед запуском команды). Хук на pre-commit может, например, проверить, что коммит-сообщение соответствует стилю, или что не затронуты «запретные» файлы. Pre-хуки — это контроль: они могут не дать агенту сделать то, что ты не хочешь. Post-хуки — это автоматизация рутины. Оба вида полезны, но pre-хуки стоит держать минимальными: каждый pre-хук — это потенциальная блокировка работы агента.

## Пример

```bash
# Хук: после каждого коммита — запустить тесты
# (в конфиге Claude Code)
# {
#   "hooks": {
#     "postCommit": ["npm test"]
#   }
# }

# Агент делает коммит → хук запускает npm test
# Если тесты падают — агент видит ошибку и чинит

# Хук: после каждой правки файла — форматирование
# {
#   "hooks": {
#     "postFileChange": ["npx prettier --write {file}"]
#   }
# }
```

В примере видно: хуки автоматизируют рутину (тесты после коммита, форматирование после правки). Агент работает, хуки делают своё.

## Частые ошибки

WARN: хук на всё подряд: хук на каждое действие — это замедление. Автоматизируй только то, что повторяется часто и имеет чёткий критерий.

WARN: хук без критерия успеха: «проверь код» — что значит «проверь»? Тесты? Форматирование? Типы? Чёткий критерий > общие слова.

WARN: не держать список хуков в CLAUDE.md: через месяц забудешь, что автоматически происходит. CLAUDE.md — твоя памятка.

WARN: хук, который падает молча: если хук падает, но агент не видит ошибку — хук бесполезен. Убедись, что агент видит результат хука.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) зафиксируй свои хуки: какие события, какие команды, какой критерий успеха. Заполни разделы по шаблону и устрани все TODO. И держи хуки «видимыми»: если хук делает что-то, чего ты не ожидаешь, — это не магия, а баг конфигурации. Проверяй конфиг хуков так же регулярно, как CLAUDE.md: забытый хук на pre-command может тихо блокировать работу агента, и ты будешь искать проблему в не там. И если хук «замедляет» работу — проверь, не слишком ли он тяжёлый: хук на полный тест-ран на каждый коммит — это нормально, а на каждый save файла — уже перебор.
