# Команды и режимы: plan mode, разрешения, auto-accept

## Цель

После урока студент сможет: объяснить, что такое plan mode и когда его включать, настроить разрешения агента под свой проект, использовать auto-accept для рутинных задач и понимать, когда авто-режим рискован.

## Теория

По умолчанию Claude Code работает в режиме «по умолчанию»: перед опасными действиями (запись в файл, запуск команды) он спрашивает разрешение. Это медленно для рутинных задач, но безопасно. Режимы и разрешения — это баланс между скоростью и контролем.

Plan mode — режим «сначала план, потом действия». Ты включаешь его (команда /plan или клавиша), и агент перед тем как что-то менять, предлагает план: какие файлы поменяет, какие команды запустит, какой ожидаемый результат. Ты смотришь на план, утверждаешь или правите, и только потом агент действует. Plan mode идеален для больших задач: «перепроектировать аутентификацию» — сначала план, потом реализация. Для мелких правок («переименовать переменную») план — избыток.

Разрешения — это список операций, на которые агенту разрешено действовать без подтверждения. По умолчанию: чтение файлов — без подтверждения, запись и команды — с подтверждением. Можно настроить: разрешить агенту запускать npm test без подтверждения (безопасно, это тесты), но запретить git push (опасно, это уже в общий репозиторий). Разрешения настраиваются в конфиге проекта или глобально.

Auto-accept — режим, где агент действует без подтверждения. Полезен для рутинных задач: «отформатируй весь код», «переименуй все console.log в logger.info». Рискован для больших изменений: если агент пойдёт не туда, ты заметишь это только когда он закончит. Правило: auto-accept — для задач, где ты уверен, что агент знает, что делать, и где результат легко откатить (git commit до начала).

NOTE: разрешения и режимы — это не «раз и навсегда». Для каждого проекта и каждого типа задач свой баланс. На новом проекте — строгие разрешения, агент спрашивает на каждом шаге. Когда ты понял, как он работает, — можно ослабить: разрешить тесты, форматирование, чтение. git push и deploy — всегда с подтверждением.

TIP: держи git-дисциплину при использовании auto-accept: перед авто-режимом сделай commit (или stash), чтобы любой результат легко откатить. Одна команда git reset --hard HEAD~1 возвращает проект к состоянию до авто-режима. Без этой привычки auto-accept превращается в лотерею.

Есть и третий вариант, который стоит упомянуть: «selective» — когда ты разрешаешь агенту действовать без подтверждения в одном сценарии, но для каждого нового типа задач возвращаешься к вопросам. Например, «отформатируй все файлы» — без вопросов, «добавь новую зависимость» — с подтверждением. Это гибче, чем «всё авто» или «всё с вопросом», и чаще всего даёт лучший баланс скорости и контроля.

## Пример

```bash
claude

# Включаем plan mode для большой задачи
/plan
> перепроектируй аутентификацию: добавь refresh tokens

# Агент предлагает план (не действуя):
# 1. Прочитать src/lib/auth.ts
# 2. Добавить таблицу refresh_tokens в Prisma schema
# 3. Написать функции issueRefreshToken, rotateRefreshToken
# 4. Обновить middleware
# 5. Написать тесты

# Утверждаем план — агент действует

# Для рутины — auto-accept
/permissions
# разрешить: npm test, prettier, ls, cat
# запретить: git push, npm publish

# Авто-режим для форматирования
> отформатируй весь код через prettier
```

В примере видно: для большой задачи — план, для рутины — auto-accept с заранее настроенными разрешениями.

## Частые ошибки

WARN: plan mode для каждой задачи: для «переименовать переменную» план — избыток. План нужен для задач, где есть несколько возможных подходов и ты хочешь выбрать до начала работы.

WARN: auto-accept без git-защиты: если агент пойдёт не туда, откатывать будет не от чего. Всегда commit перед auto-режимом.

WARN: разрешить git push без подтверждения: это уже в общий репозиторий, откатывать сложнее. git push — всегда с подтверждением, даже в auto-режиме.

WARN: настройки разрешений «на потом»: если настроить разрешения в начале проекта — сэкономишь десятки подтверждений в процессе. «Раз и навсегда» работает.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) зафиксируй свои настройки: какие разрешения ты даёшь агенту, в каких режимах работаешь, когда включаешь plan mode. Заполни разделы по шаблону и устрани все TODO. И ещё: режимы — это не настройка навсегда, а инструмент на текущий день. Утром с новой задачей — plan mode, днём на рутине — auto-accept, вечером перед commit'ом — строгие подтверждения. Свобода переключаться — часть свободы работы.
