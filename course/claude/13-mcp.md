# MCP: подключение внешних инструментов

## Цель

После урока студент сможет: объяснить, что такое MCP (Model Context Protocol), подключить MCP-сервер к Claude Code, понимать, какие инструменты дают MCP-серверы, и выбрать, какие серверы нужны для твоего проекта.

## Теория

MCP (Model Context Protocol) — это открытый протокол, который позволяет подключать к модели внешние инструменты. Без MCP агент знает только «встроенные» инструменты: читать файлы, править, запускать bash. С MCP агент может общаться с базами данных, API, браузером, поиском, любым сервисом — через стандартный протокол.

MCP-сервер — это отдельная программа, которая реализует протокол MCP и предлагает набор инструментов. Например: MCP-сервер Postgres даёт агенту инструменты «выполнить SQL-запрос», «получить схему таблиц», «показать индексы». MCP-сервер Playwright даёт инструменты «открыть страницу», «кликнуть», «сделать скриншот». Агент видит эти инструменты как свои собственные и вызывает их, когда нужно.

Подключение MCP-сервера: в конфиге Claude Code указываешь, какой сервер запустить (команда или URL) и какие переменные окружения передать. При запуске сессии Claude Code стартует MCP-сервер и «видит» его инструменты. Ты можешь подключать несколько серверов одновременно — агент будет видеть объединённый набор инструментов. Инструменты от разных серверов могут иметь похожие имена — агент сам решает, какой вызвать.

Когда MCP нужен: когда агенту нужно общаться с внешним миром (БД, API, браузер), и делать это нужно часто. Когда не нужен: если задача решается bash-командами (curl для API, psql для БД) — MCP не обязателен, хотя делает работу аккуратнее. MCP — это «API для агента», а bash — это «командная строка»: для повторяющихся и сложных операций API удобнее.

NOTE: MCP-серверы — это не «магия», а инструменты с правами. MCP-сервер Postgres с read-only подключением безопасен; с full access — может изменить данные. Выбирай серверы с минимально нужными правами. И держи в CLAUDE.md список подключённых MCP-серверов, чтобы помнить, какие инструменты агент видит.

TIP: начинай с одного MCP-сервера — того, который закрывает самую частую задачу. Если работаешь с БД — Postgres MCP. Если с браузером — Playwright MCP. Добавляй новые серверы по мере надобности, а не «на всякий случай»: каждый сервер — это лишние токены на описании инструментов.

Типовые MCP-серверы, с которых стоит начать: Postgres (работа с БД без psql-команд), Playwright (браузерная автоматизация), filesystem (доступ к файлам вне проекта, например, конфиги в другом каталоге). Каждый из них решает конкретную задачу: если задача решается bash — MCP не нужен, если задача повторяется и требует аккуратного API — MCP окупается.

## Пример

```bash
# Подключаем MCP-сервер Postgres в конфиг Claude Code
# (mcp.json в каталоге проекта)
# {
#   "mcpServers": {
#     "postgres": {
#       "command": "npx",
#       "args": ["-y", "@modelcontextprotocol/server-postgres",
#                "postgresql://localhost:5432/mydb"]
#     }
#   }
# }

# Запускаем сессию
claude

# Агент видит инструменты Postgres и может:
> покажи, какие таблицы в БД
> выполни: SELECT * FROM habits LIMIT 5
```

В примере видно: MCP-сервер подключён, агент видит инструменты БД и вызывает их по запросу.

## Частые ошибки

WARN: «на всякий случай» подключить 10 MCP-серверов: каждый сервер — это токены на описании инструментов. Подключай только то, что реально используешь.

WARN: MCP-сервер с полными правами: если достаточно read-only — не давай full access. Минимальные права = меньше риска.

WARN: не держать список серверов в CLAUDE.md: через месяц забудешь, какие серверы подключены и какие инструменты агент видит. CLAUDE.md — твоя памятка.

WARN: MCP для того, что решается bash: если curl или psql делают задачу — MCP не обязателен. MCP — для частых и сложных взаимодействий, а не для одного запроса.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) зафиксируй свои MCP-серверы: какие подключены, какие инструменты дают, какие права. Заполни разделы по шаблону и устрани все TODO. И есть нюанс с версиями: MCP-серверы — отдельные пакеты, и они обновляются. Если сервер вдруг «перестал отвечать» — сначала проверь версию и changelog, а не ищи баг в проекте: половина «проблем с MCP» — это несовместимость версий между клиентом и сервером. И держи MCP-серверы в актуальном состоянии: один сервер, который ты не трогаешь месяцами, — это потенциальный источник сюрпризов. Обновляй или убирай.
