# Тестирование с Claude Code (включая браузерную автоматизацию)

## Цель

После урока студент сможет: объяснить, как Claude Code запускает unit-тесты, настроить Playwright для браузерной автоматизации, попросить агента написать тесты на UI и понимать, какие тесты агент пишет хорошо, а какие — плохо.

## Теория

Тесты — это главный критерий успеха при работе с агентом. «Агент закончил» — не критерий, «тесты зелёные» — критерий. Claude Code умеет запускать любые тесты: unit (Vitest, Jest), интеграционные, e2e (Playwright, Cypress). Для него это просто bash-команда — он запускает, читает вывод, интерпретирует.

Но есть разница между «агент запускает тесты» и «агент пишет тесты». Запускать — легко: команда npm test, прочесть вывод. Писать — сложнее: агент должен понять, что тестировать, как изолировать, какой критерий успеха. Для unit-тестов на функции — агент пишет хорошо: функция на входе, ожидаемый результат на выходе, изоляция. Для UI-тестов — сложнее: агент должен понять DOM, как симулировать действия пользователя, как проверить состояние.

Playwright — это библиотека для браузерной автоматизации. Она открывает реальный браузер (headless), позволяет кликать, вводить текст, проверять, что элемент на странице. Для Claude Code это мощный инструмент: ты можешь попросить «напиши e2e-тест: пользователь вводит email, жмёт кнопку, видит сообщение об успехе» — и агент напишет Playwright-скрипт, который это проверит. В отличие от «тесты прошли», e2e отвечает на вопрос «работает ли в браузере»: это другой уровень доверия.

NOTE: e2e-тесты медленнее unit-тестов (открывают браузер, ждут загрузок). Не стоит запускать e2e на каждом цикле — это дорого. Стратегия: unit-тесты на каждом шаге, e2e — на «границах» (когда фича готова, перед merge). Агенту можно сказать явно: «запускай только unit, e2e — в конце».

Есть и «интерактивный» режим: агент сам запускает Playwright, делает скриншот, смотрит на него и решает, всё ли в порядке. Это не замена человеку, а быстрый «визуальный чек»: сломалась ли вёрстка, появилась ли ошибка в консоли, нажалась ли кнопка. Для UI-задач это экономит десятки минут ручного «открой и посмотри».

TIP: держи в CLAUDE.md раздел «Тесты»: какие фреймворки, как запускать unit и e2e, где лежат тесты. Тогда агент знает, что запускать, и не тратит итерации на разведку. Одна строка «тесты: npm test (unit), npm run e2e (Playwright, в конце)» экономит минуты на каждой сессии.

Отдельно про браузерную автоматизацию: Playwright-тесты — это «глаза» агента. Когда агент пишет UI, он может запустить Playwright, открыть страницу, кликнуть кнопку и увидеть, что выдало. Это сильнее, чем «тесты прошли»: проверка реального поведения в браузере. Для UI-задач проси агента именно e2e-проверку: «запусти Playwright, открой /habits, добавь привычку, убедись, что она в списке».

## Пример

```bash
claude

# Unit-тесты — на каждом шаге
> напиши unit-тесты для parseUser в src/utils/parse.js
# Агент пишет тесты, запускает npm test

# E2E — на границе фичи
> напиши Playwright-тест: пользователь вводит email в форме логина,
> жмёт submit, видит сообщение «Вход выполнен»
# Агент пишет tests/login.spec.ts, запускает npx playwright test

# Видим результат:
# 1 passed (3.2s)
```

В примере видно: unit на каждом шаге, e2e на границе. Агент сам решает, какой тест писать — ты только задаёшь сценарий.

## Частые ошибки

WARN: e2e на каждом цикле: медленно, дорого. Unit — на каждом шаге, e2e — на границах фичи.

WARN: не давать сценарий: «напиши тесты» — агент напишет то, что посчитает нужным. Лучше: «напиши тест: пользователь вводит X, жмёт Y, видит Z». Сценарий > общие слова.

WARN: забывать про изоляцию: e2e-тест, который зависит от состояния БД, будет падать. Изолируй: тестовая БД, mock-данные, cleanup после каждого теста.

WARN: не читать, какие тесты агент пишет: иногда агент пишет «тесты», которые тестируют mock, а не код. Читай тесты — они должны проверять реальное поведение.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) зафиксируй свои тесты: unit-фреймворк, e2e-фреймворк, команды запуска, где лежат тесты. Заполни разделы по шаблону и устрани все TODO. И последнее: тесты, которые агент написал сам, — это тоже код. Читай их, как читаешь любой код: иногда тест проверяет mock, а не поведение, и зелёный результат ничего не значит.
