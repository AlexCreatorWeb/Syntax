# Финальный проект: приложение с нуля (Next.js + PostgreSQL)

## Цель

После урока студент сможет: спланировать приложение (Next.js + PostgreSQL) с нуля, разбить на задачи и выполнить с Claude Code, применить все инструменты курса (CLAUDE.md, тесты, git, /compact) и задеплоить результат.

## Теория

Финальный проект — это не «ещё одна задача», а применение всего курса на реальном приложении. Ты строишь приложение «Трекер привычек»: пользователь добавляет привычки, отмечает выполнение, видит статистику. Стек: Next.js (App Router) + PostgreSQL (Prisma) + Vitest (тесты). Приложение небольшое, но проходит через все слои: UI, API, БД, тесты, деплой — и на каждом слое применяются инструменты курса.

План: (1) инициализация проекта (Next.js + Prisma), (2) schema (модель Habit, модель CheckIn), (3) API-функции (createHabit, logCheckIn, getStats), (4) UI (страницы: список привычек, форма добавления, статистика), (5) тесты (unit для API, e2e для UI), (6) деплой.

Каждый этап — отдельная задача для агента. Ты даёшь задачу, агент выполняет, ты проверяешь (тесты, визуал), делаешь commit. Между этапами — /compact, чтобы контекст не раздувался. Если этап «завис» (два-три цикла без результата) — не упрямясь: разбей этап на меньшие, или отступи и вернись к нему позже с другой формулировкой. Вайбкодинг — это итеративный процесс, а не «модель делает всё с первого раза».

Критерий готовности проекта: (1) все этапы сделаны, (2) тесты зелёные (unit + e2e), (3) приложение задеплоено и работает в браузере, (4) CLAUDE.md актуален. Если всё четыре — проект готов. Если нет — возвращайся к этапу, который не закрыт.

CLAUDE.md — твой компас: в нём стек, структура, правила, текущая задача. Агент читает его в начале каждой сессии и сразу понимает, над чем работать. И держи под рукой «карту этапов»: список всех этапов с отметками, что сделано, что в работе, что впереди. Это не формальность — это то, что позволяет тебе (и агенту после /compact) быстро понять, где ты остановился, если сессию прервать.

NOTE: финальный проект — это не «сделать как можно быстрее», а «применить всё, что узнал». Держи git-дисциплину, пиши тесты, используй /compact, читай, что агент делает. Это не про результат — это про процесс. Через финальный проект ты поймёшь, какие инструменты курса реально работают в «бою», а какие — остались теорией.

TIP: держи в CLAUDE.md раздел «Текущая задача» и обновляй его после каждого этапа. После /compact агент перечитает CLAUDE.md и сразу поймёт, где ты остановился.

И финальный совет: не гонись за «идеальным» приложением. Цель финального проекта — применить инструменты курса, а не сделать продукт. Если на каком-то этапе агент «упрямится» (два-три цикла без результата) — это нормально: отступи, упрости задачу, разбей на меньшие. Вайбкодинг — это не «модель делает всё сама», а «ты и модель вместе итеративно двигаетесь к цели».

## Пример

```bash
# Этап 1: инициализация
npx create-next-app@latest habit-tracker --typescript
cd habit-tracker
npx prisma init

# Этап 2: schema
claude
> создай Prisma schema: модель Habit (id, name, createdAt),
> модель CheckIn (id, habitId, date)

# Этап 3: API
> напиши API-функции: createHabit, logCheckIn, getStats

# Этап 4: UI
> создай страницу /habits: список привычек, форма добавления

# Этап 5: тесты
> напиши unit-тесты для API-функций, e2e для /habits

# Этап 6: деплой
> задеплой на Vercel
```

В примере видно: каждый этап — отдельная задача, CLAUDE.md — компас, git-коммиты после каждого этапа.

## Частые ошибки

WARN: «сделай всё за раз»: не «сделай приложение», а этап за этапом. Маленькие задачи = контроль.

WARN: не держать CLAUDE.md в актуальном состоянии: после каждого этапа обновляй «Текущая задача». Иначе после /compact агент потеряет нить.

WARN: пропускать тесты: «рабочее» приложение без тестов — хрупкое. Тесты — критерий успеха каждого этапа.

WARN: не делать commit: если этап «сломался» — откатывать не от чего. Commit после каждого этапа.

## Практическое задание

В файле CLAUDE.md (открыт в редакторе) опиши свой финальный проект: стек, план этапов, текущая задача. Заполни разделы по шаблону и устрани все TODO. Это твой компас на весь проект. И когда проект будет готов — посмотри на CLAUDE.md: он вырос за время работы, и это нормально. Актуальный CLAUDE.md — это не только «память агента», но и твоя документация процесса: что сделано, как сделано, почему именно так.
