# Как работает агент: базовый цикл, первые задачи

## Цель

После урока студент сможет: описать базовый цикл «подумал — действовал — посмотрел результат», назвать основные инструменты агента (чтение файлов, поиск, правка, bash), сформулировать задачу, которую агент выполнит хорошо, и распознать задачу, которая сформулирована плохо.

## Теория

Claude Code работает по простому циклу, который называется agentic loop. Ты задаёшь цель. Модель решает, какой инструмент применить первым: прочитать файл, поискать по проекту, запустить команду. Агент выполняет действие, результат возвращается модели. Модель решает следующий шаг. Цикл повторяется, пока задача не решена или пока ты не остановишь.

Ключевые инструменты агента: чтение файлов (agent читает файл целиком или фрагментом), поиск по проекту (grep, поиск по строкам), правка файлов (точечные замены или полная перезапись), запуск команд (bash: тесты, сборка, git). Каждый инструмент — это один шаг в цикле. Агент не «видит» весь проект сразу: он читает то, что решил прочитать, и на основании этого решает, что делать дальше.

Из этого следует главное следствие: качество работы агента — это качество его «разведки». Если агент прочитал три файла из двадцати — он будет решать задачу с позиции этих трёх файлов. Если ты в задаче явно сказал «сначала прочитай src/api и src/models» — агент так и сделает, и его решение будет основано на более полной картине.

Формулировка задачи — твой главный инструмент управления. Плохая задача: «исправь баг». Агент не знает, какой баг, где он и что считать «исправленным». Хорошая задача: «в функции parseUser при пустом email падает TypeError; найди место, добавь валидацию, добавь тест, запусти тесты». В хорошей задаче есть: что сломано (сигнатура), где искать (подсказка), что считать успехом (критерий).

NOTE: агент — не маг, который «понимает» твой проект. Он решает задачу на основании того, что прочитал. Чем точнее ты укажешь, что читать и какой результат считать успехом, тем предсказуемее будет его работа. Это не недоверие к модели — это инженерия контекста.

Ещё одно важное свойство цикла: он итеративный. Агент не обязан решить задачу за один шаг: он может прочитать файл, запустить команду, увидеть результат, и только потом решить, что делать дальше. Это отличает агента от «автодополнения», которое предлагает один вариант сразу. В длинных задачах цикл может сделать десятки шагов — и на каждом агент видит новый результат, который учитывает в следующем решении. Ты как пользователь управляешь не шагами, а целью: если агент ушёл не туда — останавливаешь и корректируешь, но обычно достаточно просто дать хорошую цель.

TIP: держи под рукой шаблон задачи: «Цель: X. Контекст: файлы Y, Z. Ограничения: не трогать W. Успех: тесты проходят, команда K выдаёт P». Этот шаблон экономит итерации: меньше переделок, меньше потраченных токенов, больше предсказуемости.

## Пример

```bash
claude

# Плохая формулировка:
> исправь баг

# Хорошая формулировка:
> в функции parseUser (src/utils/parse.js) при пустом email
> падает TypeError. Добавь валидацию: если email пустой —
> возвращай null и логируй warning. Напиши тест на этот кейс
> и запусти тесты.

# Цикл агента (видишь в терминале):
# 1. читает src/utils/parse.js
# 2. читает src/utils/__tests__/parse.test.js
# 3. правит parse.js
# 4. правит parse.test.js
# 5. запускает npm test
# 6. сообщает результат

# Если агент ушёл не туда — останавливаем (Esc) и корректируем:
> подожди, валидацию делай в отдельной функции validateEmail
```

В примере видно полный цикл: агент сам решает, что читать, что править и какую команду запустить. Ты только видишь каждый шаг.

## Частые ошибки

WARN: «исправь баг» без деталей: агент тратит итерации на разведку, которую ты мог бы дать ему готовой. Чем меньше деталей в задаче, тем больше итераций и тем выше шанс, что агент уйдёт не туда.

WARN: задача на «всё сразу»: «перепиши аутентификацию, добавь тесты, задеплой» — это три задачи в одной. Агент будет делать их последовательно, но без чётких критериев успеха для каждой. Лучше разбить: «перепиши аутентификацию» → проверь → «добавь тесты» → проверь.

WARN: не указывать критерий успеха: без «тесты проходят» агент может «завершить» задачу, не запустив тесты. Всегда явно говори, что считать успехом.

WARN: не читать, что агент делает: цикл прозрачен, но если ты не смотришь — можешь пропустить, что агент пошёл не туда. Первые 10 секунд каждого запуска стоит посмотреть, какие файлы он читает.
