# Урок 10. Связи: Embed vs Reference — ядро моделирования NoSQL

## Цель

После урока студент сможет: объяснять два способа «связей» в MongoDB — **встраивание** (embed) и **ссылки** (reference), применять правила выбора (1-ко-многим с ограничением → embed; множественное/бесконечное → reference), понимать компромиссы (дублирование vs дополнительные запросы) и 16 МБ-лимит документа.

## Теория

### В MongoDB «нет» таблиц и JOIN'ов «из коробки»

В SQL связность — через ключи + JOIN. В MongoDB данные **группируются**: либо связанные документы **вложены** друг в друга, либо связаны **ссылкой** (`id`-поля) и «собираются» при чтении (или `$lookup`, урок 15).

### Embed (встраивание)

Связанные данные **внутри** одного документа:

```js
// «Заказ» со ВСТРОЕННЫМИ позициями
{ _id: …, total: 1500, items: [{ name: "Кофе", qty: 2 }, …] }
```

- **Плюсы**: один запрос = всё (нет «дополнительных» чтений); атомарность (заказ+позиции вместе); «горячие» данные рядом.
- **Минусы**: **дублирование** (если «товар» у 1000 заказов — 1000 копий; обновили цену — не обновятся «прошлые» — но для истории это **правильно**); 16 МБ-лимит.

**Когда embed**: 1-ко-**ограниченному** многим (позиции заказа, теги, характеристики товара — «известное, небольшое количество»), данные «живут вместе» (читаются вместе).

### Reference (ссылка)

Отдельные документы + **id-ссылка**:

```js
// «Заказ» со ССЫЛКОЙ на товары
{ _id: …, items: [{ productId: ObjectId("…"), qty: 2 }] }
// Товары — отдельная коллекция products
```

- **Плюсы**: нет дублирования; «многое-ко-многим»; бесконечный рост (комментарии, лента).
- **Минусы**: **дополнительные запросы** (заказ → ids товаров → товары); «сборка» в приложении (или `$lookup`).

**Когда reference**: 1-ко-**бесконечному** многим (комментарии к посту, посты пользователя), N-ко-N (теги↔статьи), «связанный» документ сам по себе сущность (пользователь).

### Правило (золотое)

> **Встраивайте, если** отношение 1-ко-многим, «многие» **ограничены** (десятки, не тысячи), данные читаются **вместе** и вкладываются «по стоимости». **Ссылайтесь**, если «многие» **растут без bounds**, отношение N-ко-N или связанные данные **меняются независимо**.

Компромисс: **гибрид** — «горячее» встроить (name автора в комментарии), «холодное» — ссылкой (аватар, профиль).

TIP: 16 МБ — **жёсткий** потолок на документ. «Лента комментариев» (тысячи) — **не** встраивайте (упрётесь). Отдельная коллекция + ссылка.

NOTE: в песочнице «сборка» по ссылкам — вручную (`find({ _id: { $in: ids } })`) или `$lookup` (урок 15). В терминале — то же (driver).

## Пример

`models.js`:

```js
import { MongoClient, ObjectId } from "mongodb";

const client = new MongoClient(process.env.MONGO_URL || "mongodb://localhost:27017");
await client.connect();
const db = client.db("course");

// ===== EMBED: заказ с позициями (1-ко-ограниченному-многим) =====
const orders = db.collection("orders");
await orders.insertOne({
  total: 2300,
  status: "paid",
  items: [
    { name: "Кофе", qty: 2, price: 300 },
    { name: "Печенье", qty: 1, price: 1700 },
  ],
});
// Чтение: ОДИН запрос — весь заказ
const o = await orders.findOne({});
console.log("EMBED: заказ + позиции за 1 запрос, total =", o.total);

// ===== REFERENCE: пост с комментариями (1-ко-бесконечному) =====
const posts = db.collection("posts");
const comments = db.collection("comments");
const post = (await posts.insertOne({ title: "О MongoDB" })).insertedId;
await comments.insertMany([
  { postId: post, text: "Отлично!", author: "Аня" },
  { postId: post, text: "Спасибо", author: "Боря" },
]);
// Чтение: ДВА запроса (пост + комментарии по ссылке)
const p = await posts.findOne({ _id: post });
const c = await comments.find({ postId: post }).toArray();
console.log("REFERENCE: пост +", c.length, "комментариев (2 запроса)");

// «Сборка» по ссылкам ($in — один запрос на все ссылки)
const manyPosts = (await posts.insertMany([{ title: "B" }, { title: "C" }])).insertedIds;
const allIds = Object.values(manyPosts);
const allComments = await comments.find({ postId: { $in: allIds } }).toArray();
console.log("Сборка: комментариев на 2 поста:", allComments.length);
```

## Частые ошибки

WARN: **встраиваете «бесконечное»** (комментарии/лента в пост) — упрётесь в 16 МБ и раздуваете документ. «Растущее» — reference.

WARN: **ссылаетесь там, где embed** (позиции заказа → отдельная коллекция) — «один заказ» = 3+ запроса. Ограниченное «вместе» — встраивайте.

WARN: «обновили» вложенное (embed) и ждёте, что «везде» обновится — нет, это **копии** (дублирование). Для «текущих» данных — reference (или осознанное дублирование).

WARN: N-ко-N через встраивание (теги в статьях **и** статьи в тегах) — дублирование в обе стороны. N-ко-N — отдельные коллекции + ссылки (или теги-массив в одной стороне).
