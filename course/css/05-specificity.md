# Урок 5. Специфичность: «баллы» и :where()

## Цель
После урока студент сможет: рассчитать вес любого селектора по схеме «инлайн — id — классы — теги»; предсказать победителя в конфликте правил; применять :where() для «нулевой» специфичности и выстроить систему стилей, где не приходится пересилывать правила.

## Теория
### Как считается вес селектора
Специфичность — это **вес** селектора, который браузер сравнивает в конфликте (каскад, урок 4). Вес — это число из четырёх разрядов: (инлайн, id, классы, теги). Классическая запись — 0-1-0. Что «весит»:

- **инлайн-стиль** style="..." — 1-0-0 (самый тяжёлый после important);

- **каждый id** в селекторе — +1 ко второму разряду: #menu — 0-1-0;

- **каждый класс, атрибут, псевдокласс** — +1 к третьему: .card — 0-0-1, [type="email"] — 0-0-1, :hover — 0-0-1;

- **каждый тег, псевдоэлемент, универсальный не считается** — +1 к четвёртому: p — 0-0-1 (четвёртый разряд), ::before — тоже четвёртый; * — 0-0-0.

Веса **суммируются по частям селектора**: `#nav .links a:hover` = id (0-1-0) + класс (0-0-1) + тег (0-0-0-1) + псевдокласс (0-0-1) = 0-1-2-1. Это НЕ десятичное число 0.121 — разряды сравниваются отдельно, как цифры в «0121».

### Как пользоваться расчётом на практике
Правило: если веса разные — побеждает heavier, порядок в файле не важен. Если веса равные — порядок (урок 4). Поэтому «почему не перекрасилось» почти всегда = «мой селектор легче». Классические ситуации:

- `button` (0-0-0-1) проигрывает любой `.btn` (0-0-1) — где бы ни стоял;

- `.card .title` (0-0-2) бьёт `.title` (0-0-1) — вложенность «накидывает» вес;

- инлайн-стиль не победить никаким селектором (кроме !important) — его можно только переопределить JS-ом или important-ом.

Современная практика — **держите специфичность плоской**: стилизуйте в основном одиночными классами (0-0-1), не копайте в DOM («.menu .nav a»). Тогда любое правило бьёт любое другое порядком — и архитектура не зависит от случайных совпадений.

### :where() — нулевая специфичность
`:where(селектор)` (2021, поддержка везде) принимает аргументы, но сам **весит 0-0-0**. Зачем:

- единый «сброс»: `:where(h1, h2, h3) { margin: 0; }` — лёгкий сброс, который легко переопределить;

- вариативные состояния: `:where(.btn):hover { ... }` — ховер-стили с нулевым весом;

- генерация CSS (Tailwind, BEM-наборы) строится на :where, чтобы утилиты не «уезжали» по весу.

Брат :where — `:is()`: та же синтаксис-форма, но **весит как самый тяжёлый из аргументов**: `:is(.a, #b)` = 0-1-0. Используйте :is() для компактности, когда вес не критичен, и :where(), когда важно остаться «лёгкими».

TIP: если в проекте появился цикл «написал правило → не сработало → усилил селектор → добавил ещё id», это сигнал: чините систему (слои + плоские классы), а не конкретный конфликт.

NOTE: специфичность — про CSS, а не про HTML: два элемента с одинаковым классом имеют одинаковый вес правил; «первый» и «второй» div стилизуются одинаково. Порядок DOM важен только при равных весах (порядок ПРАВИЛ в файле).

## Пример
Каркас:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Урок 5. Специфичность</title>
</head>
<body>
  <main id="content">
    <p class="lead">Обычный абзац</p>
    <p class="lead warn">Важное примечание</p>
  </main>
</body>
</html>
```
CSS (комменты — веса селекторов):
```css
/* 0-0-0-1: тег — самый лёгкий */
p { color: #868e96; }

/* 0-0-1: класс — перебивает тег, где бы ни стоял */
.lead { color: #1971c2; }

/* 0-0-2: два класса — сильнее одиночного */
.lead.warn { color: #e8590c; }

/* 0-1-0-1: id + тег — сильнее .lead, даже если ниже по файлу */
#content p { color: #495057; }

/* 0-0-0: :where весит НУЛЬ — даже слабее тега */
:where(.lead, .warn) {
  font-weight: bold;
}
```
Разбор: первый абзац (.lead) станет серым от #content p (0-1-0-1 бьёт 0-0-1), а второй — оранжевым? Нет: у .warn тоже сработает #content p — сравните веса. `:where` добавил жирность обоим без влияния на цвет. Поменяйте порядок правил в файле и убедитесь: при РАЗНЫХ весах победитель не меняется.

## Частые ошибки
WARN: id-селектор «на мелочовке» — один id в цепочке даёт вес 0-1-0, и переопределить его классом невозможно (0-0-1 < 0-1-0); стилизуйте компонентами-классами, id оставьте якорям.
WARN: .parent .child .grandchild — «глубокий» селектор: вес растёт с каждым уровнем, и правило становится почти неперекрываемым; плоские классы решают то же без копания в DOM.
WARN: инлайн-стили из фреймворков/редакторов — их не победит никакой селектор, кроме !important; найдите источник и уберите инлайн, а не воюйте.
WARN: :where и :is перепутаны — :is() НЕ обнуляет вес (берёт максимум аргументов); «нулевой ховер» через :is будет тяжелее, чем ожидается.
WARN: «веса — это число 0.121» — разряды НЕ складываются в десятичную дробь: 0-0-10 (десять классов) слабее 0-1-0 (один id), хотя «10 > 1».

2. Напишите правило, которое закрасит ОБА абзаца зелёным, НЕ используя id и !important (подсказка: селектор весом ≥ 0-1-0-1, например #content .lead, — и сравните с #content p).

3. Задайте второму абзацу инлайн-стиль style="color: purple" и попробуйте переопределить его классом, затем правилом с :where — что сработало, а что нет?

4. Перепишите сброс для заголовков через :where(h1, h2, h3) и объясните, почему он легче, чем h1, h2, h3 { ... }.

5. Бонус: соберите в styles.css «вояку» — цепочку .a .b .c .d — и объясните, почему это плохая практика, несмотря на «рабочий» результат.
