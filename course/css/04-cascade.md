# Урок 4. Каскад: порядок, слои @layer, !important

## Цель
После урока студент сможет: предсказать, какое из конфликтующих правил победит (учитывая порядок и слои); организовать большой stylesheet на слоях @layer; объяснить, когда `!important` — последняя мера, а не привычка.

## Теория
### Как браузер выбирает одно значение
«Каскад» в имени CSS — это алгоритм выбора: на элемент может попасть несколько правил, задающих одно свойство (например, два цвета), и браузер обязан выбрать ОДИН. Решают три фактора, в порядке проверки:

1. **важность происхождения** — правила автора (наш файл) бьют правила браузера (user agent) и пользователя;

2. **важность правила** — обычные правила против `!important`: в пределах одного происхождения important выигрывает (но порядок слоёв при этом разворачивается — ниже);

3. **конкуренция** — специфичность селектора (урок 5), а при равной специфичности — **порядок**: позднее в файле выигрывает.

«Ложка мёда» порядка: правило «последнее выигрывает» работает только при прочих равных. Селектор `.menu a` победа над `.a`, даже если стоит раньше, — из-за специфичности.

### Слои @layer — порядок как архитектура
В больших проектах «последнее выигрывает» становится минным полем: правило из utility.css бьёт компонентную карточку, потому что файл подключили позже. **Слои** (@layer, 2021, полная поддержка со 2022) решают это: правила группируются в слои, и побеждает не «кто позже в файле», а «кто в ПОЗДНЕЕМ СЛОЕ» — независимо от позиции внутри файла:

- слой, объявленный позже, сильнее: @layer base, components, utilities;

- **неслойные** правила (без @layer) сильнее ЛЮБЫХ слоёв — это подстава: один «забытый» кусок вне слоя переезжает выше всей системы;

- слои можно не объявлять заранее — первое упоминание @layer name { } создаёт слой.

Типовая структура реального проекта: base (сбросы, типографика) → components (карточки, кнопки) → overrides (исключения). Внутри слоя порядок обычный: специфичность, затем позиция.

### !important — последний аргумент
`!important` ставит правило «выше обычных» внутри происхождения. Когда оправдан: перебиваем стили сторонней библиотеки/виджета, без доступа к её файлу; вынужденные исключения. Когда вреден: «война important» — в проекте десятки !important, и каждое новое правило начинается с него; порядок слоёв разворачивается (при двух important побеждает РАНЬНЕЕ объявленный слой). Правило: сначала проверьте специфичность и слои, и только потом — important.

TIP: отладка «почему не перекрасилось»: DevTools → Styles показывает цепочку правил; найдите победителя и сравните его селектор со своим по специфичности. 90% случаев — дело не в порядке, а в весе селектора.

NOTE: каскад — не «CSS не работает». Если правило «не сработало», оно либо проиграло (есть победитель в DevTools), либо селектор не совпал (элемент не выбран). Диагностика начинается с этих двух вопросов.

## Пример
Каркас:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Урок 4. Каскад</title>
</head>
<body>
  <button class="btn btn--primary">Кнопка</button>
  <p class="note">Примечание</p>
</body>
</html>
```
CSS:
```css
@layer base, components, overrides;

@layer base {
  .btn {
    padding: 0.5rem 1rem;
    background: #dee2e6;
    color: #212529;
  }
  .note {
    color: #495057;
  }
}

@layer components {
  .btn--primary {
    background: #1971c2;
    color: #fff;
  }
}

@layer overrides {
  .note {
    color: #e8590c;
  }
}

.btn {
  border: 2px solid #343a40;
}
```
Разбор: `.note` задана дважды (base — серым, overrides — оранжевым): побеждает overrides, потому что слой позже, даже если правила поменять местами. `.btn--primary` (components) перекрашивает фон `.btn` (base). А неслойное правило `.btn { border }` действует ВМЕСТЕ со всеми слоями (оно не конкурирует по свойству) — и оно же сильнее любых слоёв, если задаст color.

## Частые ошибки
WARN: «CSS не работает, потому что правило выше» — на самом деле ниже стоит селектор с большей специфичностью; сначала сверяйте веса, потом порядок.
WARN: !important как привычка — война important: у каждой команды свой important, и чинить систему можно только вычищая всё; правильный ход — слои и специфичность.
WARN: слои не объявили строкой @layer a, b, c — порядок создаётся первыми УПОМИНАНИЯМИ: кто первый появился в файле, тот и «ниже»; перемешайте файлы — слои перемешаются.
WARN: правило вне слоя «на всякий случай» — неслойное бьёт все слои: одна забытая строчка ломает архитектуру; весь stylesheet должен жить в слоях.
WARN: important + слои — при двух !important побеждает РАННЕЕ объявленный слой (порядок разворачивается); это путает и «чинителей», ожидающих обычного порядка.

## Практическое задание

1. Создайте каркас из Примера и соберите в styles.css три слоя base/components/overrides со скелета задания.

2. Поменяйте правила .note в base и overrides местами (внутри своих слоёв) и убедитесь, что победитель не изменился — почему?

3. Уберите @layer с правила overrides-варианта .note (оставьте «голое» правило) — что изменилось и почему?

4. Добавьте в base цвет border для .btn с !important и проверьте в DevTools, какое правило побеждает.

5. Бонус: объясните на этом примере, чем «победил порядок» отличается от «победила специфичность» — возьмите пар селекторов .btn и button.
