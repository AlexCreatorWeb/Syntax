# Урок 18. Container Queries: адаптивность компонента

## Цель
После урока студент сможет: объяснить, чем container query отличается от media query (контейнер vs вьюпорт); «открыть» контейнер (container-type) и написать @container-правила; использовать cqw/cqh-единицы; выбрать «инструмент» под задачу (MQ для страницы, CQ для компонента).

## Теория
### Проблема: компонент «не знает», где он
Media query отвечает на вопрос «какой **экран**». Но компонент (карточка, виджет, баннер) может жить в **разных контейнерах**: узкий сайдбар, широкая колонка, модалка. «Адаптивность» компонента должна зависеть от **ширины контейнера**, а не от экрана:

- та же карточка в сайдбаре (300px) — «вертикальная», в основном контенте (800px) — «горизонтальная»;

- media query «не видит» сайдбар: «широкий экран + узкий сайдбар» — и карточка «не знает», что ей «тесно».

**Container Query** (2023, полная поддержка во всех актуальных браузерах) отвечает на вопрос «какой **контейнер**».

### Как это работает: три шага

1. **Открыть контейнер**: на предке — container-type: inline-size (или size). Это «говорит» браузеру: «этот элемент — контейнер, отслеживай его размер».
   - **inline-size** — отслеживается только ширина (частый случай, «безопасный»);
   - **size** — ширина И высота (нужна явная высота контейнера, иначе «обратная связь»: высота зависит от контента, контент — от высоты).

2. **Написать @container-правило** (по ширине контейнера):
```css
@container (min-width: 480px) {
  .card { flex-direction: row; } /* "в широком контейнере — горизонтально" */
}
```

3. **cqw/cqh-единицы** (container query units): 1cqw = 1% ширины КОНТЕЙНЕРА (не вьюпорта!): font-size: 4cqw — «текст масштабируется от контейнера».

Вложенные контейнеры: @container **name** (min-width: N) — именованный контейнер (container-name: sidebar), если вложенность «смешивает» источники.

### CQ vs MQ: когда что
Правило выбора:

- **страница/раскладка целиком** (колонки, «мобильный/desktop») — **Media Query** (зависит от вьюпорта);

- **компонент** (карточка, виджет, «реusable» блок) — **Container Query** (зависит от «места», где компонент живёт).

Они **комбинируются**: MQ «перестраивает» страницу (колонки), CQ «подстраивает» компоненты внутри колонок. Компонент, «сделанный» с CQ, «переезжает» в другой макет — и «подстраивается» без правок CSS.

TIP: **container-type: inline-size** «безопаснее» size: не требует явной высоты, не создаёт «обратную связь». Для 90% компонентных задач — inline-size. size — только когда нужны cqh (высотные единицы) и высота контейнера «известна» (100vh, fixed).

NOTE: container-type: size «съедает» height: auto — контейнер «не знает» свою высоту без явного значения (иначе «циклическая» зависимость). Если задали size и контейнер «сжался» — проверьте, что у него есть явная высота (100%, 400px, 100dvh).

## Пример
Каркас:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Урок 18. Container Queries</title>
</head>
<body>
  <div class="layout">
    <aside class="sidebar">
      <div class="widget">
        <div class="w-img">IMG</div>
        <h3>Одинаковый компонент</h3>
        <p>Текст карточки. В узком контейнере — колонка, в широком — строка.</p>
      </div>
    </aside>
    <main class="content">
      <div class="widget">
        <div class="w-img">IMG</div>
        <h3>Тот же компонент</h3>
        <p>В широком контейнере — картинка слева, текст справа (flex-direction: row).</p>
      </div>
    </main>
  </div>
</body>
</html>
```
CSS:
```css
.layout {
  display: grid;
  grid-template-columns: 280px 1fr;
  gap: 1rem;
  padding: 1rem;
}

.sidebar, .content {
  container-type: inline-size; /* "открыть" контейнер */
}

.widget {
  display: flex;
  flex-direction: column; /* база: колонка (узкий) */
  gap: 0.75rem;
  padding: 1rem;
  border: 1px solid #dee2e6;
  border-radius: 8px;
}

.w-img {
  width: 100%;
  height: 100px;
  background: #e7f5ff;
  display: grid;
  place-items: center;
}

/* "в широком контейнере (>= 480px) — горизонтально" */
@container (min-width: 480px) {
  .widget {
    flex-direction: row;
    align-items: center;
  }
  .w-img {
    width: 120px;
    flex: 0 0 120px;
  }
}
```
Разбор: .sidebar и .content — **контейнеры** (container-type: inline-size). .widget — ОДИН и тот же компонент: в сайдбаре (280px — «уже» 480px) — колонка, в content (широкий) — строка (картинка слева). Media query «не отличил» бы: «широкий экран» — и оба контейнера «широкие» по вьюпорту, а CQ «видит» реальную ширину.

## Частые ошибки
WARN: @container «не работает» — у предка нет container-type: inline-size/size; «контейнер» должен быть «открыт» (иначе CQ «не имеет» источника).
WARN: container-type: size без явной высоты — контейнер «сжался» в 0 (height: auto «не считается»); для «только ширины» — inline-size (без этой проблемы).
WARN: cqw «масштабирует» от ВЬЮПОРТА — нет, от КОНТЕЙНЕРА; если контейнер «не открыт», cqw считается от «маленького» вьюпорта (fallback) — проверьте container-type.
WARN: CQ «для страницы» — избыточно: «колонки страницы» — MQ (вьюпорт); CQ — для «компонентов», которые «переезжают» по макету.
WARN: вложенные контейнеры «без имён» — @container (min-width) «видит» ближайший предка-контейнер; для «конкретного» (не ближайшего) — container-name + @container name (min-width).

## Практическое задание

1. Соберите каркас из Примера и реализуйте CQ-правила со скелета задания.

2. Измените grid-template-columns у .layout на 1fr 1fr — оба контейнера «широкие», и ОБА .widget «горизонтальные». Верните 280px 1fr.

3. Уберите container-type у .content — «широкий» .widget «станет» колонкой (CQ «не видит» контейнер). Верните.

4. Задайте h3 font-size: 5cqw внутри @container-правила — и объясните, почему в сайдбаре и content размеры ЗАГОЛОВКА разные (cqw от контейнера).

5. Бонус: соберите «именованный» контейнер: container-name: promo у .sidebar, и @container promo (min-width: 200px) { .w-img { height: 140px; } } — и объясните, зачем «имя», если контейнер один.
