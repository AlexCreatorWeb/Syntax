# Урок 1. PostgreSQL: что это и с чего начать (psql)

## Цель

После урока студент сможет: объяснить, что такое реляционная СУБД и почему PostgreSQL, установить/подключиться к базе, работать в psql (psql-meta-команды, автодополнение), создать первую базу и таблицу.

## Теория

Реляционная модель: данные лежат в таблицах (строки и столбцы), таблицы связаны ключами. СУБД хранит данные, управляет целостностью, параллельным доступом и индексами — тебе не нужно писать «файлы + поиск по массиву».

PostgreSQL — открытая реляционная СУБД (прародитель — Berkeley DB, 1970-е; PG — 1995–1996). Отличается строгостью ANSI SQL: полные ACID-транзакции, внешние ключи реально работают, JSONB, оконные функции, расширения (PostGIS, pg_trgm). Один процесс на каждое соединение — конкурентность честная, без «единого демона».

Архитектура: сервер (postmaster + бэкенды) и клиент. Данные — на сервере, клиент отправляет SQL. Клиенты: psql (терминал, ставится вместе с сервером — им и начнём), pgAdmin (GUI), DBeaver, Supabase Studio. В этом курсе — psql. Один клиент = одна сессия = одно соединение с сервером (процесс бэкенда). Сессия «помнит» переменные (SET), открытые транзакции, историю — поэтому «закрой psql» = «закрой сессию».

Подключение: `psql -h localhost -U postgres` (или `psql postgres`). Внутри psql есть меты-команды с `\`: `\l` — список баз, `\c база` — переключение, `\dt` — таблицы в схеме, `\d таблица` — структура (колонки, индексы, ограничения), `\q` — выход. Ctrl+Space — автодополнение (после `\set completion_on`).

Нумерация объектов: схема (обычно public) — таблица — строка. Имя полной таблицы: schema.table.

Митигационный момент: SQL-запрос «живёт» в сессии. В psql каждая команда исполняется в отдельной транзакции (авто-коммит): если запрос успешен — изменения зафиксированы мгновенно (без явного BEGIN/COMMIT). Это удобно для экспериментов и опасно для «полумер» — с транзакциями разберёмся в уроке 13, а пока помни: «сделал запрос — уже записалось в БД».

## Пример

В терминале (не внутри psql):

```sql
-- создать базу
createdb shop
-- подключиться к ней
psql shop
```

Внутри psql:

```sql
CREATE TABLE products (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    price_cents INT NOT NULL DEFAULT 0
);

INSERT INTO products (name, price_cents) VALUES ('Кофе', 4500), ('Чай', 1900);
SELECT * FROM products;
\d products          -- структура таблицы
\dt                 -- все таблицы схемы
```

## Частые ошибки

WARN: Забыл `-h` и psql нашёл сокет Unix — подключение «успешное», но это локальный админ-пользователь без пароля, а не сервер из Docker/облака. Проверяй `\conninfo` (host, порт, пользователь, база) перед «важными» запросами.

WARN: Писал `SELECT * FROM products` и ждал вывод на экране, но psql показал «(0 rows)» — это не ошибка: база пуста или данные в другой схеме. Смотри `\dt` и `SELECT count(*) FROM products`.

WARN: Забыл точку с запятой после запроса — psql не выполнил команду (просто ждёт продолжения, prompt `->`). Нажми Enter с `;` или Ctrl+C.

TIP: Учи три команды наизусть — `\dt`, `\d имя`, `\conninfo` — 80% «куда делось» решается ими.

Почему это важно сейчас: весь курс идёт в psql — короткие команды, видимый результат, никакой магии GUI. Разберёшься в psql — любой GUI-клиент (pgAdmin, DBeaver) станет прозрачным: под капотом он шлёт те же SQL-запросы.

Полезные клавиши psql: стрелки вверх/вниз — история, Tab — автодополнение (после `\set completion_on`), Ctrl+D — подсказка синтаксиса, `\timing` — время выполнения запроса (будет очень пригодится в уроке 16).
